## Backend API

Lens Assistant is backed by the Node MCP server under `server/mcp/`, not by a dedicated FastAPI router. `server/server.js` mounts `mcpRouter` directly with `app.use(mcpRouter)`, and `server/mcp/router.ts` exposes the stateless Streamable HTTP endpoint at `/api/mcp`.

### Send one stateless MCP request

Handle one stateless Streamable HTTP MCP request by creating a fresh `McpServer`, connecting it, and serving the request body.

The `initialize` response sets `result.serverInfo.name` to `lens-mcp`.
The Node factory is `createLensMcpServer` in `server/mcp/server.ts`; the
catalog uses `LensTool` and `lensTools`. The previous `createPrismMcpServer`,
`PrismTool`, and `prismTools` exports remain compatibility aliases for existing
integrations. Tool names, permissions, and request fields remain unchanged.

<Tabs>
  <Tab title="REST API">

**`POST /api/mcp`**

Request:

- Content type: `application/json`
- Body: one MCP JSON-RPC request object. In stateless mode, Lens creates a fresh server per request, so no session id is required.
- Common request shapes include `initialize`, `tools/list`, and `tools/call`.

Example `tools/call` request:

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "method": "tools/call",
  "params": {
    "name": "list_simulation_backends",
    "arguments": {}
  }
}
```

Response:

Successful responses use MCP JSON-RPC result envelopes. For tool calls, Lens's MCP server returns `content` blocks whose `text` contains the JSON-stringified Lens REST result.

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\n  \"items\": []\n}"
      }
    ]
  }
}
```

If an unhandled server error occurs before the SDK sends a response, Lens returns:

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32603,
    "message": "Internal server error"
  },
  "id": null
}
```

  </Tab>
  <Tab title="Python API">

This endpoint is a Node.js MCP handler, not a Python function — there is no direct Python call for the `/api/mcp` transport itself. Call the underlying Python-backed domain directly instead; for example, a deployment-related MCP tool can reuse the same deployment helper shown on the [Deployments](/api-reference/modules/deployments) page:

```python
from llm_d_bench.deploy.standard_kubernetes_service import (
    StandardKubernetesServiceRequest,
    build_standard_kubernetes_service_configuration,
)

request = StandardKubernetesServiceRequest(
    model="meta-llama/Llama-3.1-8B-Instruct",
    deployment_name="assistant-backed-deploy",
    cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
    replicas=1,
    tensor_parallel_size=1,
)
configuration = build_standard_kubernetes_service_configuration(request)
print(configuration.checksum)
```

### GET is not supported in stateless mode

Return `405 Method not allowed.` because stateless mode does not support the Streamable HTTP GET stream.

<Tabs>
  <Tab title="REST API">

**`GET /api/mcp`**

Request:

This endpoint has no request body. In Lens's stateless MCP mode, the Streamable HTTP GET stream is intentionally disabled.

Response:

Returns a JSON-RPC error payload with HTTP status `405`.

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

  </Tab>
  <Tab title="Python API">

This endpoint is a Node.js MCP transport guard, not a Python function — there is no direct Python call. Use the underlying Python-backed module for the tool you actually want to invoke, as summarized below in [What the MCP tools call](#what-the-mcp-tools-call).

  </Tab>
</Tabs>

### DELETE is not supported in stateless mode

Return `405 Method not allowed.` because stateless mode does not support session termination.

<Tabs>
  <Tab title="REST API">

**`DELETE /api/mcp`**

Request:

This endpoint has no request body. Lens does not keep MCP sessions between requests, so there is no server-side session to terminate.

Response:

Returns a JSON-RPC error payload with HTTP status `405`.

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

The tool catalog is assembled in two parts: `server/mcp/tools.ts` contains generated REST adapters, and `server/mcp/specialTools.ts` contains hand-written tools for composite or Node-backed routes. The generated half is produced by `node scripts/generate-mcp-tools.mjs` from the `llm_d_bench` FastAPI OpenAPI schema. The handlers are thin wrappers over Lens's own REST API: `server/mcp/internal.ts` forwards requests to loopback `/api/...` paths through `internalRequest(...)`.

## What the MCP tools call

Representative generated MCP tools forward straight into existing Python-backed REST modules:

| MCP tool | Forwarded HTTP endpoint | Underlying module |
| --- | --- | --- |
| `create_standard_vllm_deployment_run` | `POST /api/v1/deployments/standard-vllm-runs` | [Deployments](/api-reference/modules/deployments) via `llm_d_bench/deploy/router.py` |
| `list_deployment_executions` | `GET /api/v1/deployments/executions` | [Deployments](/api-reference/modules/deployments) via `llm_d_bench/deploy/router.py` |
| `create_evaluate_run` | `POST /api/v1/evaluate/runs` | [Evaluation](/api-reference/modules/evaluation) via `llm_d_bench/evaluate/router.py` |
| `get_cluster_stack_status` | `GET /api/v1/monitoring/cluster-stack/status` | [Observability](/api-reference/modules/observability) via `llm_d_bench/monitoring/cluster_stack/router.py` |
| `list_simulation_tasks` | `GET /api/simulation/tasks` | [Simulation](/api-reference/modules/simulation) via `llm_d_bench/simulation/router.py` |

If you need Python rather than MCP transport, call the underlying Python domains directly instead of `/api/mcp`. For example, the MCP tool `create_standard_vllm_deployment_run` ultimately reaches the same deployment helper used by `POST /api/v1/deployments/standard-vllm-runs`:

```python
from llm_d_bench.deploy.standard_kubernetes_service import (
    StandardKubernetesServiceRequest,
    build_standard_kubernetes_service_configuration,
)

request = StandardKubernetesServiceRequest(
    model="meta-llama/Llama-3.1-8B-Instruct",
    deployment_name="assistant-backed-deploy",
    cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
    replicas=1,
    tensor_parallel_size=1,
)
configuration = build_standard_kubernetes_service_configuration(request)

print(configuration.checksum)
```

See the full request/response schemas in the FastAPI OpenAPI schema (regenerate with `npm run docs:api`).
