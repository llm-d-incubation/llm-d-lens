## 后端 API

智能体创建和细化流使用 `llm_d_bench.agentic.streaming.planning_stream_response`。
这些路由保留了主体解析、预期错误分类以及它们现有的通用错误信息。
流会先发出 `progress`，然后是 `complete` 或 `error`；断开连接时的清理
操作会取消并等待尚未完成的规划。网关操作/日志流是单独处理的。

部署相关功能位于 `llm_d_bench/deploy/router.py` 中的 FastAPI 路由下，
前缀为 `/api/v1/deployments`。

优化路由和精确路由的能力元数据复用了 `llm_d_bench.deploy.capabilities`
中的 `shared_prefix_routing_workload()`。每个场景和推荐的工作负载都会
获得各自独立的嵌套值；提供方专属的基线和目标保持不变。精确提供方的
校准和模型发现共享惰性的 modelserver 调用遍历逻辑，同时各自保留了
自己的"取最后一个值"和"取第一个模型"选择规则。

智能体规划会针对每个经过校验的 baseline-vllm、optimized-baseline 和
pd-disaggregation 候选方案，根据其工作负载和 GPU 拓扑结构，分别估算
缺失的精确 AIC 预测值。候选方案的估算值会以 `aic_estimate` 的形式
提供给 AI 评分；如果估算值不可用，则保持为未知状态，而不是一种
性能或 SLO 保证。智能体估算不会沿用原始搜索的 TTFT/TPOT 目标；
它们只是在没有 SLO 过滤的情况下，对固定的拓扑结构和工作负载进行校验。
当失败的生成器没有留下任何工具调用轨迹时，生成器回退逻辑也会使用
已解析的工作负载，对内置的前三个候选方案进行估算。不受支持或不可用的
拓扑结构保持为未知状态。宽松 AIC 搜索会接受任何不超过可用 GPU
预算的完整配置。它的预测结果并不能确立对原始 SLO 的符合性。
即使生成器只建议了一个更小的拓扑结构，智能体仍会将宽松的锚点方案
保留为一个经过校验的候选方案，然后估算其精确的拓扑结构和工作负载。
已知估算值未能达到原始延迟目标的候选方案会被标记为 `not_satisfied`；
在同样未达标的候选方案中，相对目标偏差更小的方案排名会优先于
GPU 节省量更大的方案。未知的估算值不会被视为失败。
当外部规划器对多个候选方案进行评分时，其选择理由会根据提供的
规划事实，解释为什么每一个评分较低的返回候选方案排在最高选择之后。
只有返回的前三个候选方案会被评分；对于该集合之外的候选方案，
不会推断出任何理由。

### 估算 AIC 拓扑结构

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/v1/aic/estimate`**

    发送 `model_name`、`scenario`（`inference_scheduling` 或 `pd_disaggregation`）、
    `gpu_count`、`mean_input_tokens`、`mean_output_tokens`、AIC 系统/后端/数据库，
    以及拓扑结构字段（`tp` 和 `replicas`，或者 prefill/decode 的 TP 和副本数）。
    可选的 `ttft_target_ms` 和 `tpot_target_ms` 会保留受约束的实验路径；
    两者都省略时，则在没有 SLO 过滤的情况下估算固定的拓扑结构。

    ```json
    {
      "model_name": "Qwen/Qwen3-0.6B",
      "scenario": "inference_scheduling",
      "gpu_count": 1,
      "mean_input_tokens": 1024,
      "mean_output_tokens": 256,
      "aic_system_name": "b60",
      "aic_backend_name": "vllm",
      "aic_database_mode": "SILICON",
      "tp": 1,
      "replicas": 1
    }
    ```

    响应中包含 `mode`、拓扑结构字段，以及在可测量时的 `ttft_ms`、
    `tpot_ms` 和 `throughput_tokens_per_sec`。估算值并不能证明符合 SLO。
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_bench.aic.models import AICEstimateRequest
    from llm_d_bench.aic.service import estimate

    result = await estimate(AICEstimateRequest(
        model_name="Qwen/Qwen3-0.6B", scenario="inference_scheduling",
        gpu_count=1, mean_input_tokens=1024, mean_output_tokens=256,
        aic_system_name="b60", aic_backend_name="vllm", tp=1, replicas=1,
    ))
    ```
  </TabItem>
</Tabs>

import asyncio

from llm_d_bench.deploy.application import deployment_run_manager
from llm_d_bench.deploy.contracts import DeploymentRunCreateRequest
from llm_d_bench.deploy.standard_kubernetes_service import (
    StandardKubernetesServiceRequest,
    build_standard_kubernetes_service_configuration,
)


async def main() -> None:
    request = StandardKubernetesServiceRequest(
        model="Qwen/Qwen3-8B",
        deployment_name="qwen3-standard",
        description="Standard baseline for smoke tests",
        cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
        replicas=1,
        tensor_parallel_size=1,
    )
    configuration = build_standard_kubernetes_service_configuration(request)
    run = await deployment_run_manager.start_run(
        DeploymentRunCreateRequest(
            configurations=[configuration],
            provenance={
                "deployment_source": {"kind": "standard-kubernetes-service"},
                "cluster_session_id": request.cluster_session_id,
                "deployment_name": request.deployment_name,
                "description": request.description.strip(),
            },
        )
    )
    print(run.id, run.status)


asyncio.run(main())

## 配置准备 API

这些配置领域的路由会为部署和评估准备制品。请求和响应模型位于
`llm_d_bench.configuration.models`。示例中使用了用于说明的集群/会话
ID 和指南提交记录；请将它们替换为一个活动的集群会话和真实渲染过的
指南溯源信息。保存操作会发布一个制品；单独的渲染操作不会部署它。

HTTP 边界使用 `application/problem+json` 格式的错误。共享的
`DomainError` 实例会保留其原始的状态码和错误码（例如冲突仍然是
409）；它们不会被转换成一个操作专属的 500 错误。Python 服务调用
会抛出其原始异常；`llm_d_bench.configuration.router` 中的路由适配器
应用下面的 HTTP 映射关系。

### 撤销部署访问权限

从调用方有权管理的部署资源上移除一个用户或组的共享权限。
如果某个绑定属于另一个资源或集群、是一个全局/集群角色绑定，
或者是一个未知的绑定，则会返回 `404` 且不会移除它。创建者/维护者
现有的共享权限仍然适用。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`DELETE /api/v1/deployments/executions/{execution_id}/access/{binding_id}`**

**`DELETE /api/v1/deployments/runs/{run_id}/access/{binding_id}`**

无请求体。成功：HTTP `204`，空响应体。对于缺失或不匹配的绑定，
problem 响应包含：

```json
{"type":"about:blank","title":"Domain request failed","status":404,"detail":"binding not found","code":"not_found"}
```
  </TabItem>
  <TabItem value="python-api" label="Python API">

对于受信任的服务端代码，先对该资源进行鉴权，并从存储的部署信息中
获取其身份和集群。然后带着这个范围调用共享服务：

```python
from llm_d_bench.auth.service import default_service

def revoke_execution_share(binding_id: str, execution_id: str, cluster_id: str) -> None:
    # The caller has already authorized this stored execution.
    default_service().revoke_resource_share(
        binding_id,
        resource_type="deployment_execution",
        resource_id=execution_id,
        cluster_id=cluster_id,
    )
```

对于一次运行，传入 `resource_type="deployment_run"`、其运行 ID，
以及来自其存储溯源信息中的集群 ID。该服务会校验绑定的归属关系；
路由级别的权限检查仍然是强制性的。
  </TabItem>
