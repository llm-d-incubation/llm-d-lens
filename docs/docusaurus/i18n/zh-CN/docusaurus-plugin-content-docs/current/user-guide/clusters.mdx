title: 集群

使用集群工作流来注册基于 kubeconfig 的集群、引导新集群、查看集群健康状态，并访问每个集群上运行的部署。

## 从 kubeconfig 注册集群

1. 打开**集群**并点击**新增**。
2. 在**添加 Kubernetes 集群**中，停留在**基本信息**上，输入**集群名称**。
3. 可选填写**描述**。
4. 在**Kubeconfig 文件**下，保持选中**我已有 kubeconfig**，然后点击**浏览**并选择 kubeconfig 文件。
5. 点击**下一步**。Lens 会使用该 kubeconfig 连接到集群，并检查其 Kubernetes 服务器版本是否满足本次 Lens 发布所固定的最低版本要求（技术栈配置文件中的 `min_k8s_version`）；如果集群不可达或版本过旧，页面会停留在**基本信息**并说明原因。否则页面会进入**网络代理**步骤。选择**自动检测该集群的代理（推荐）**或**为该集群使用自定义代理**。
6. 如果你选择**为该集群使用自定义代理**，请填写 **HTTP_PROXY**、**HTTPS_PROXY** 和 **NO_PROXY**。
7. 点击**下一步**继续到**模型网关**，并选择**提供方**——该向导下拉框目前只能选择 **Istio**（默认选项）；**Envoy AI Gateway**、**agentgateway** 和 **GKE Gateway** 虽然列出，但由于该向导尚不支持，处于禁用状态。所选提供方会为整个集群安装一次，模型服务会基于它发布路由。在同一个**模型网关**步骤中，设置**网关暴露端口（NodePort）**、**网关主机/IP**（可选；供客户端调用以访问网关的外部可达主机/IP——Lens 会将其与暴露端口组合；留空则 Lens 会基于暴露端口和集群节点推导出一个值）、**Lens 地址**（主机/IP；默认自动填入本 Lens 后端的地址——Lens 会附加自己的端口，集群使用它来校验调用方；留空则 Lens 会自动填入）以及**节点 inotify 上限**（`fs.inotify.max_user_instances`，默认 8192；会应用到每个节点，避免繁忙节点耗尽 inotify 资源）。然后继续到**加速器**，在这里选择集群上承载的每一种加速器（异构集群可选择多种）以及驱动的访问模式；Lens 会在集群上逐一检查，并在缺失时从供应商的上游清单安装驱动/设备插件，同时显示每一项的安装进度。接下来**llm-d 技术栈**会列出本次 Lens 发布所安装的组件版本（固定值，不可编辑）——只包含你所选加速器对应的模型服务器镜像；点击**下一步**会下载匹配的 llm-d 和 llm-d-benchmark 源码，并预先拉取你所选加速器对应的 llm-d-router、Inference Payload Processor、网关提供方和模型服务器镜像（一个特权 DaemonSet 会在每个节点上执行 `crictl pull`），并在进入**模型缓存**之前显示每个镜像的拉取进度。
8. 在向导的最后一步，点击**审核**，然后点击**完成**。
9. 向导完成后，点击**结束**。

## 模型网关前置条件

共享网关在每个集群上只安装一次，但集群本身必须先满足一些前置条件。以下内容适用于
**Istio**——这是当前创建/编辑向导中唯一可选的提供方；下面列出的其他提供方
（Lens 在 API 层面的默认值是 **Envoy AI Gateway**）目前只能通过直接调用 REST API 设置
`gatewayProvider` 来使用，尚无法在 UI 中选择：

- **Gateway API + Gateway API Inference Extension CRD**（即 `InferencePool` 资源，
  `inference.networking.k8s.io/v1`）。
- **所选提供方会由 Lens 自动安装**（通过 `helm`/`istioctl`），在该集群的网关
  首次被安装或协调时进行。如果这个后台安装失败，或者你需要手动安装，对于
  **Envoy AI Gateway**，请安装带有 inference-pool 插件的 Envoy Gateway，
  否则模型路由会一直停留在 `ResolvedRefs=False`
  （`InvalidKind`），请求会返回 500：

  ```bash
  helm upgrade -i eg oci://docker.io/envoyproxy/gateway-helm \
    --version v1.8.1 -n envoy-gateway-system --create-namespace \
    -f https://raw.githubusercontent.com/envoyproxy/ai-gateway/v0.7.0/manifests/envoy-gateway-values.yaml \
    -f https://raw.githubusercontent.com/envoyproxy/ai-gateway/v0.7.0/examples/inference-pool/envoy-gateway-values-addon.yaml
  ```

- **必须能够分配一个 LoadBalancer 地址。**在网关 Service 获得 `EXTERNAL-IP` 之前，
  网关会显示 `Programmed=False`（`AddressNotAssigned`）。云端集群通常自带此能力；
  本地 kind 集群则需要 `cloud-provider-kind` 或 MetalLB。如果你无法添加
  负载均衡器，请设置 `LENS_GATEWAY_SERVICE_TYPE=NodePort`，这样 Lens 会渲染一个
  使用 NodePort Service 的 `EnvoyProxy`。

## 通过 Kubespray 引导新集群

1. 打开**添加 Kubernetes 集群**。
2. 在**基本信息**中，在**Kubeconfig 文件**下，选择**通过 Kubespray 引导新集群**。
3. 在引导面板中，为每个节点填写**主机地址**、**端口**、**角色**、**用户名**，以及**SSH 私钥**或**SSH 密码**二选一。
4. 对于每一台要加入的额外机器，点击**新增节点**。
5. 在**目标节点的网络代理**下，选择**自动（复用每个目标节点自身已配置的任何代理）**或**为这些节点使用自定义配置**。
6. 如果你选择**为这些节点使用自定义配置**，请填写 **HTTP_PROXY**、**HTTPS_PROXY** 和 **NO_PROXY**。
7. 点击**运行预检**，等待**预检结果**显示所有主机均已通过。
8. 点击**开始引导**。
9. 生成的 kubeconfig 返回到向导后，继续点击**下一步**、**审核**和**完成**，将集群保存到 Lens 中。

## 编辑集群

1. 选择你要修改的集群。
2. 在页面标题栏点击**编辑集群**，或打开该行的**操作**菜单并选择**编辑集群**。
3. 在**编辑集群**中，更新**名称**、**描述**、**网络代理**、**模型网关提供方**、**网关暴露端口**、**网关主机/IP**、**Lens 地址**或**节点 inotify 上限**。（llm-d 组件版本由 Lens 发布版本固定，在创建向导中以只读方式显示。）
4. 如果你选择**自定义**，请填写 **HTTP_PROXY**、**HTTPS_PROXY** 和 **NO_PROXY**。
5. 点击**保存更改**。

## 删除集群注册

1. 打开该集群的**操作**菜单。
2. 选择**删除集群**。
3. 在**删除集群**中，确认你要移除的是正确的集群注册记录。
4. 点击**删除**。

## 查看集群健康状况与部署访问入口

1. 从**集群**列表中选择一个集群。
2. 查看汇总卡片：**工作节点**、**CPU**、**内存**、**可部署 GPU**、**显存**、**磁盘**和**监控**。
3. 在**部署**中，使用**复制命名空间**来复制某个部署的命名空间。
4. 使用**复制端点**来复制部署端点。
5. 如果该行显示本地转发操作，点击**为该部署打开本地端口转发**。
6. 当你需要**打开 Grafana**、**打开 Prometheus**或**性能分析**时，打开该部署的**监控**菜单。

## 将工作节点置于维护模式

1. 在集群详情页的**工作节点**列表中，选择一个或多个工作节点所在行。
2. 点击**进入维护模式**以隔离（cordon）所选节点，或点击**退出维护模式**以取消隔离（uncordon）。
3. 在确认对话框中，查看列出的节点名称，然后点击**隔离节点**或**取消隔离节点**。

隔离操作只会将所选节点标记为不可调度，从而阻止新 Pod 落在这些节点上；已经在这些节点上运行的 Pod 会继续运行（不会执行驱逐/排空操作）。取消隔离会使这些节点重新变为可调度状态。

## 查看某个部署的 Pod 与日志

1. 打开你要查看的部署，点击**查看 Pod 与日志**。
2. 在标题为**Pod 与日志 —** 后跟部署名称的抽屉中，查看**Pods** 部分。
3. 使用**所有节点（`<数量>`）**、**搜索节点...**或**搜索 Pod...**来缩小 Pod 列表范围。
4. 点击你要查看的 Pod，日志面板会显示**Pod 日志：**后跟 Pod 名称。
5. 使用**100 行**、**200 行**、**500 行**或**1000 行**来选择要加载多少历史记录。
6. 根据需要开启或关闭**上一个**或**自动刷新 (5 秒)**。
7. 使用**筛选日志行...**来缩小输出范围，或点击**复制**来复制当前的日志文本。

## 删除某个部署并可选地删除其命名空间

1. 打开该部署的删除操作，弹出**删除部署**对话框。
2. 查看**执行 ID**、**集群**和**命名空间**。
3. 如果希望 Lens 移除该命名空间及其中的资源，请保持**同时删除 Kubernetes 命名空间**选中；如果只想移除部署记录，请取消勾选。
4. 在标注为**输入**后跟所需短语以及**以确认**的确认输入框中，输入对话框中显示的确切短语。
5. 点击**删除部署**。

## 集群范围划分

集群访问权限在 Lens 中是按作用域感知的。管理员可以查看和管理每一个集群，而维护者只能查看分配给他们的集群；权限模型请参阅 [认证与 RBAC](/architecture)。

## 软件准备的一致性

创建集群和编辑集群使用同一套源码下载工作流。进度会同时覆盖 llm-d 和 llm-d-benchmark；终止性失败会包含每个失败仓库的原因。缺失的返回路径会保留其已保存的值。创建和编辑各自保留了它们原有的、开始下载的触发条件以及各自的导航逻辑。
