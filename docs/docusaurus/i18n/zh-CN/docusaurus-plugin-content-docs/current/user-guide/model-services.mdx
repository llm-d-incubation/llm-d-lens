使用模型服务相关界面，可以通过各集群自己的共享 Gateway URL 来对外暴露部署、
签发个人 API 密钥，并管理哪些模型服务器为每个公开模型名称提供服务。

## 浏览已发布的模型并复制请求示例

1. 打开**我的服务**。
2. 在**网关连接**中，每个集群都会显示各自的 Gateway 基础 URL——点击你想
   调用的集群旁边的**复制**（如果配置了全局的
   `LENS_MODEL_GATEWAY_PUBLIC_URL` 覆盖项，它会替换掉每个集群的 URL）。
3. 找到你想调用的模型，点击 **cURL**。
4. 在标题为 **cURL examples —** 加上模型名称的抽屉中，点击你想复用的示例
   旁边的**复制**。这些示例使用的是该模型所属集群的基础 URL，并且针对那些
   **不会**自动注入 `X-Gateway-Base-Model-Name` 的提供方（Envoy AI
   Gateway、Agentgateway；Istio/GKE 则通过 Inference Payload Processor
   注入）会在示例中包含该请求头。复制成功后按钮会变为**已复制**。
5. 发送请求前，请将示例中的 `lens-mk-...` 替换为你自己的某个密钥。
6. 只有当流式请求中包含 `"stream_options": {"include_usage": true}` 时，
   才会被计入用量统计（网关会从响应的 `usage` 中读取 token 计数）；生成的
   聊天示例已经设置了这一项。

## 创建并保存 API 密钥

1. 打开 **API keys**（API 密钥）。
2. 点击 **New key**（新建密钥）。
3. 在 **Create API key**（创建 API 密钥）中，为**密钥名称**输入一个值。
4. 点击**创建**。
5. 在 **Copy your key now**（请立即复制你的密钥）中，点击**复制**并立刻
   保存好完整的令牌。
6. 保存好令牌后，点击 **I saved it**（我已保存）。

## 重置或吊销 API 密钥

1. 打开 **API keys**。
2. 要轮换默认密钥，点击**重置**。Lens 会立即打开 **Copy your key now**
   以展示替换后的令牌。
3. 在 **Copy your key now** 中，点击**复制**，保存新的令牌，然后点击
   **I saved it**。
4. 要彻底移除某个密钥，使用该密钥所在行的操作按钮，打开
   **Revoke API key**（吊销 API 密钥）。
5. 在 **Revoke API key** 中，点击**吊销**。

## 创建模型服务

1. 打开**模型服务**。
2. 点击**添加模型服务**。
3. 在**新建服务**中，选择该服务所属的**集群（必填）**。一个模型服务的作用
   域仅限于这一个集群：其提供方必须是该集群中的部署，同一个公开名称也可以
   在另一个集群中存在而不会产生冲突。
4. 填写**模型名称（面向用户）**——这是调用方使用的名称；Lens 也会用它作为
   路由/模型引用，其余内容会自动推导。
5. 可选地填写**显示名称（可选）**和**描述**。
6. 点击**创建**。

## 为模型服务添加模型服务器

1. 在**模型服务**页面，点击**添加模型服务器**。
2. 在 **Add provider**（添加提供方）抽屉中，先选择**集群**，再选择该集群中
   的**模型服务**，然后选择其中一个**部署**选项（只有该服务所属集群中的
   部署才能成为提供方）。
3. 查看**推导出的目标（基于该部署）**（命名空间、Service、Pool、端口、
   kind）。每个提供方对应一个由该部署所拥有的 InferencePool，自动命名为
   `namespace/pool`；无需手动填写任何内容。
4. 点击**添加提供方**。一个模型服务只路由到**一个** InferencePool（每个
   pool 对应一个 EPP）；第一个处于活动状态的提供方会成为 HTTPRoute 中发布
   的 pool。

## 移除模型服务或某个提供方

1. 打开**模型服务**。
2. 在某个模型服务的 **HTTPRoute** 节点上，打开其菜单。
3. 选择**移除提供方（仅本集群）**，只移除该集群的提供方；该服务仍可通过
   其他提供方继续可用（只有本集群的路由会被协调移除）。如果它是最后一个
   提供方，这会移除整个模型服务。
4. 选择**移除模型服务（所有集群）**，移除该服务及其在所有集群中的全部
   提供方。
5. 在弹窗中确认。受影响的路由会被协调移除，使用它们的调用方将无法继续
   工作。

## 管理数据面组件

**Service flow**（服务流程）图会把每个组件显示为独立的节点——**Gateway**、
**IPP**、**HTTPRoute**、**InferencePool**、**EPP** 和**模型服务器**。每个
节点的状态点都有颜色编码（绿色表示健康，琥珀色表示降级或缺失，红色表示不
健康，灰色表示已停止/不存在）；将鼠标悬停在状态点上可查看该组件的确切
状态文字。在某一行模型服务中，这四个节点是独立探测的：当 **HTTPRoute**
存在且已被 Accepted 时为绿色，当 **InferencePool** 存在且已被 Accepted
时为绿色，当 **EPP** 的 Service 拥有端点时为绿色，当 **InferencePool** 的
selector 拥有一个就绪端点时**模型服务器**为绿色——因此仅删除模型服务器的
Deployment，只会使那一个节点变红。检查大约每 10 秒在后端运行一次，页面
每隔几秒刷新一次，因此会有短暂的延迟。各项操作会将其日志行实时流式输出到
右侧的全高日志面板中。集群必须满足
[模型网关前置条件](/user-guide/clusters#model-gateway-prerequisites)
（Gateway API Inference Extension 的 CRD、支持 InferencePool 的提供方，
以及一个 LoadBalancer 地址）。

1. 打开**模型服务**并点击**协调**，以协调所有拥有成员的集群的共享 Gateway
   和模型路由。
2. 在某个集群的 **Gateway** 节点上，打开其菜单并选择**安装**（或**卸载**）
   ——提供方已在该集群上选定——此外还有单独的**协调**、**启动**/**停止**
   和**查看日志**操作。
3. 在 **IPP** 节点上，打开其菜单以**安装 IPP**、**卸载 IPP**、**启动**或
   **停止**。payload-processor 的 chart 和版本固定在 Lens 内置的技术栈
   配置文件（`llm_d_bench/versions`）中，不能按次安装单独配置。
4. 在某个 **EPP** 节点上，打开其菜单并选择**启动**或**停止**，以伸缩该
   EPP Deployment。
5. 在 **IPP** 节点上，打开其菜单并选择**配置**，以编辑 Inference Payload
   Processor 的 `PayloadProcessorConfig`。它是从集群实时读取的，保存会
   升级 IPP；**使用 chart 默认值**会清除自定义配置。
5. **HTTPRoute** 和 **InferencePool** 是 CRD，因此它们只显示状态，没有
   启动/停止控件。
6. 每一次安装/卸载/协调/启动/停止/**查看日志**都会在右侧打开日志面板，该
   面板会保持页面高度，并通过其 **X** 按钮关闭。

## 权限

模型服务相关操作受权限控制。网关级别的设置和服务级别的策略变更，需要
[认证与 RBAC](/architecture) 中描述的模型服务管理员权限；没有该权限的
用户根本看不到对应的按钮和菜单操作（例如 Gateway/IPP 的更多操作菜单、
**添加模型服务**和**添加模型服务器**），而不是显示为禁用或只读控件。
