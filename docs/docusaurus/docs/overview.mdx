Lens is an open-source control plane for deploying and operating large language
models on [llm-d](https://llm-d.ai/), the Kubernetes-native distributed
inference stack, across your Kubernetes clusters. It plans and executes
inference deployments, runs guided evaluations and traffic simulations, and
keeps clusters, storage and external providers under one roof — so a team can
go from a registered model to a benchmarked, production-serving deployment
without stitching together separate tools.

## Capabilities

| Area | Description |
| --- | --- |
| Model market | Browse and register models. |
| Deployments | Plan, approve and execute inference deployments. |
| Evaluation | Design guided experiments, run benchmarks, analyze and export results. |
| Simulation | Replay registered request traces against an inference endpoint. |
| Model services | Publish deployments as model-service providers behind the gateway data plane. |
| Clusters | Discover, bootstrap and manage Kubernetes clusters. |
| Storage | Manage model cache and shared storage volumes. |
| External providers | Configure OpenAI- or Anthropic-compatible AI providers used by Lens's optional AI features. |
| Observability | Maintain the cluster monitoring stack (Prometheus/Grafana). |
| Lens Assistant | A tool-calling assistant backed by the MCP tool catalog. |

## Architecture

<img src={useBaseUrl('/img/overview-1-7d83bcc33b.png')} alt="Lens system architecture" width="100%" />

A single Lens server manages any number of Kubernetes clusters, on-premises or
in the cloud, from one pane of glass: the console talks to an application layer
over same-origin API routes, and that layer forwards requests to a control plane
that owns the domain services, persists state to the database, and drives
clusters, storage and the model-service data plane directly. Access control and
audit logging are enforced in the control plane, so every page — deployments,
evaluation, simulation and model services alike — respects the same per-cluster
permissions.
