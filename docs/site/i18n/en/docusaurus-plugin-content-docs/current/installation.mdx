## Install online

On Ubuntu 22.04 LTS or newer (x86_64), download and run the online installer.
No repository checkout is needed. Run it as the intended service user, not with
`sudo bash`; it requests sudo only for missing system packages.
The download entry requires Bash, `curl` or `wget`, CA certificates and `python3`
(`sudo apt-get install curl ca-certificates python3` if missing).

Set `VERSION` to `main` for the development version, or replace it with an actual
release tag such as `vX.Y.Z`. Only tags containing the online installer are supported.

With **curl**:

```bash
VERSION=main && curl -fsSL "https://raw.githubusercontent.com/llm-d-incubation/llm-d-lens/${VERSION}/scripts/LensInstaller-Ubuntu-x86_64-online.sh" | bash
```

Or with **wget**:

```bash
VERSION=main && wget -qO- "https://raw.githubusercontent.com/llm-d-incubation/llm-d-lens/${VERSION}/scripts/LensInstaller-Ubuntu-x86_64-online.sh" | bash
```

The installer reads interactive input from `/dev/tty`. After validating the source
archive, it saves `LensInstaller-Ubuntu-x86_64-online.<unique-id>.sh` in the current
directory and prints the path; existing files are not overwritten. Use a writable
working directory. The complete script body must arrive before it can execute.
In automated Bash shells, enable `set -o pipefail` so downloader failures also
produce a nonzero pipeline status.

Interactive mode asks for the install directory (default `$HOME/llm-d-lens`) and
one app/API port (default `3000`); press Enter to accept each default.
The installer downloads a commit-pinned source archive, then provisions Node,
Python 3.11+ and a virtualenv, configures PostgreSQL, builds the app and sets up TLS.
If a compatible Python is missing, it uses pinned uv to install private Python 3.12
under the installation's `.tools/`; system Python is unchanged.
It accepts only a new or empty install directory, not an existing installation.

### Version selection

The script embeds its source version; no version argument is needed or accepted.
`main` installs the development branch as it exists when the script runs. Release
scripts install their tagged source. Both resolve to a commit SHA before downloading;
the installed `.lens-version.json` records the version, SHA and installation time.
Source pinning does not lock every transitive npm/Python dependency.

### Network and failures

Allow HTTPS access to `raw.githubusercontent.com`, `api.github.com`, `codeload.github.com`,
Node.js and package registries, and Ubuntu package mirrors. Private Python provisioning
also downloads from GitHub release assets. Existing `HTTP_PROXY`, `HTTPS_PROXY` and
`NO_PROXY` settings are inherited; certificate verification remains enabled.
If sudo filters proxy variables, configure apt's proxy separately.

Logs are private files under `$LENS_LOG_DIR` (default `~/.local/state/lens/logs/`).
They can contain installer-generated database credentials; do not publish them.
Temporary downloads use `$LENS_SCRATCH_DIR` and are removed on exit. Downloads and
archive checks finish before the install directory is changed; later failures may
leave a partial installation, which is retained for diagnosis. There is no automatic
upgrade, rollback or deletion of that directory. GitHub API rate-limit/network failures
are reported without falling back to another version.

For scripted or CI installs without a terminal, replace the final `| bash` with
`| bash -s -- --silent`.

Other installer options can follow `--silent`. A saved script can still be run
directly with `bash <saved-script-path> [options]`.

Common options:

| Option | Purpose |
| --- | --- |
| `--install-dir DIR` | Install location (default `$HOME/llm-d-lens`). |
| `--app-port PORT` | Web app/API port (default `3000`). |
| `--backend-port PORT` | Legacy alias for `--app-port`; both select the same listener. |
| `--no-https` | Serve plain HTTP instead of auto-HTTPS (self-signed cert). |
| `--no-start` | Install without starting services. |
| `--db-mode embedded\|external` | Use the built-in database or an external one. |
| `-h, --help` | Show every option. |

When auto-HTTPS is enabled, the local source launcher also enables unverified TLS for the model Gateway's internal `lens-authz` hop (`LENS_MODEL_GATEWAY_AUTHZ_TLS_INSECURE=1`), because the cluster does not trust the self-signed certificate. This is a development convenience and disables certificate verification for that hop, so a network attacker could impersonate authz and forge identity. Use it only on a trusted network. See [Environment variables](/environment-variables) for the security warning and how to disable it.

## Manage the installation

The installer writes `lensctl.sh` into the install directory:

```bash
"$HOME/llm-d-lens/lensctl.sh" start
"$HOME/llm-d-lens/lensctl.sh" status
"$HOME/llm-d-lens/lensctl.sh" stop
```

To remove an installation, run `"$HOME/llm-d-lens/lensctl.sh" uninstall`;
data is kept by default. Use `--purge` to remove data as well, or `--keep-data`
to skip the data prompt. Embedded database retention is controlled separately by
`--keep-db` / `--purge-db`. The online installer itself does not accept uninstall flags.

To upgrade an existing installation instead of a fresh install, see
[Upgrade](/upgrade).

## Install and run from source

From the repository root, use the local source launcher instead of the
Ubuntu installer's packaged deployment:

```bash
hack/lens-local.sh start
hack/lens-local.sh status
```

The launcher prepares Node.js, npm dependencies and the Python environment,
then runs the source frontend on port `5173` and the unified Python API on `3000`.
This serves source code through Vite; it does not replace the production build
command below. `npm run dev` and `npm run dev:web` start both development processes.
After `npm run build`, `npm start` serves the built frontend, API and MCP from
the Python process on one port. Node is needed for frontend builds, not production serving.

`hack/lens-local.sh start` and `restart` regenerate and validate the reuse map before
changing services. Invalid registrations block startup without stopping existing
services; pending user decisions warn without being resolved automatically.
To constrain deployments to a node, pass `--target-node NODE` and optionally
`--kubeconfig FILE`, or set `TARGET_NODE` and `KUBECONFIG`. No target-specific
configuration file is needed. See the [CLI Reference](/cli-reference) for
preflight requirements and every `hack/lens-local.sh` subcommand.

## Build and test

```bash
npm run build
npm run type-check
make test-js
make test-python
```

## Documentation site

This site is built with [Docusaurus](https://docusaurus.io/). Preview it locally
with hot reload:

```bash
npm run docs:dev
```

Validate configuration and page paths:

```bash
npm run docs:check
```

The Python MCP catalog is derived from the current API schema and packaged special
tool definitions. Local and installed launchers validate it before starting services;
unexpected skipped operations block startup. It does not require a generated Node artifact.
