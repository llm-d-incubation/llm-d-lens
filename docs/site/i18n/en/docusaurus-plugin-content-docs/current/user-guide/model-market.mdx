Open **Model Market** to choose a model and deploy it to a cluster.
For your first deployment, use **Standard** mode.

Use **Search models** above the categories to filter by model name, publisher,
repository, model type, category, or precision. Search ignores case and combines
with the selected category; multiple words must all match. The model count updates
as you type. Use **Clear filters** to reset both search and category.

## Create a standard deployment

1. Open **Model Market**, use **Model categories** to narrow the list, and click a model card.
2. In **One-click deployment**, enter **Deployment name** and choose a ready **Cluster**.
3. Choose **Model cache storage** containing this model. Wait for **This model is ready in the selected cache.**
4. Keep **Mode** on **Standard** and start with the suggested **Replicas** and **Tensor parallelism**.
5. Review **Standard vLLM plan**, then click **Create deployment**.
6. If available cards are insufficient, review the warning and click **Confirm & deploy** when the physical total is sufficient; otherwise, reduce replicas / TP.
7. Lens opens **Deployments**. Wait for the new deployment to show **Ready**.

No cluster or cache available? [Add a cluster](/user-guide/clusters),
[create cache storage](/user-guide/storage), and [download the model](/user-guide/model-cache).
If the model is missing from the selected cache, download it there before returning.

Before creating the deployment, expand **Pod placement** below **vLLM parameters**
to choose **Replica placement**. **Prefer one node** favors co-location without
requiring it. **Require one node** reveals an optional **Node** selector populated
from the selected cluster; selecting a node constrains replicas to its hostname.
**Distribute evenly across nodes** and **Require separate nodes** can leave Pods
Pending if there are too few eligible nodes or insufficient capacity.

## Choose a different deployment mode

| Mode | Choose it when |
| --- | --- |
| **Standard** | You want to start a model with a basic vLLM deployment |
| **Advanced** | You want to choose an llm-d Guide, configure resources or review generated YAML |
| **Agentic** (Experimental) | You want Lens to recommend a configuration for a workload and performance target |

## Configure an advanced deployment

1. Open a model, enter **Deployment name**, and choose **Cluster** and **Model cache storage**.
2. Set **Mode** to **Advanced** and click **Configure deployment**.
3. In **Basic settings**, review **Runtime image**, **Replicas**, and **TP** (accelerators per replica).
4. Under **Guide template**, choose **Guide** and **Accelerator**. Use [Choose an evaluation Guide](/evaluation/guides) to compare the options.
5. For a P/D or tiered-cache Guide, choose a variant from the displayed list. Keep the supplied defaults for the first run.
6. Click **Generate YAML**. If available cards are insufficient but the physical total is sufficient, review the Pending warning and click **Continue & generate**.
7. Review **Generated deployable configuration**. Correct any highlighted errors, then click **Next**.
8. On **Deployments**, wait for **Ready**; use **View Pods & Logs** to inspect startup.

Change the runtime image only when you have an image compatible with the selected
hardware. After changing the cluster or Guide source, check the variant selection
again. A resource or network error during generation must be resolved before deployment.

## Get an AI-assisted recommendation

1. Open a model and fill in the deployment name, cluster and cache storage.
2. Set **Mode** to **Agentic**.
3. Choose **Use case** and **GPU capacity for planning**, then review the workload and performance-target fields.
4. Leave **AI provider** on **Default (no external AI provider)**, or select a configured provider to help rank the options.
5. Optional: expand **Preference** and enter an English preference, such as `use fewer GPU resources` or `prefer prefix cache`.
6. Click **Generate recommendation**.
7. Under **Validated alternatives**, expand **Why this option** to compare resource use and estimated performance.
8. Click **Deploy recommendation** on the option you choose. Track startup on **Deployments**.

Before generating a recommendation, expand **Pod placement** below **Workload
estimate** to choose a placement preset. **Require one node** also allows a
hostname selection. The chosen preset and node are applied when you approve a
candidate. Prefill and Decode model-server Pods in a P/D deployment share one
placement group; routing Pods do not. LeaderWorkerSet candidates do not support
the balanced or separate-node presets.

To change the recommendation, enter your revised preference below the alternatives
and click **Recalculate selection**. This also works without an external AI provider.

**AI score** ranks the alternatives; it is not a measured performance result or
a probability of success. Treat **SLO not met** as a reason to revise the target
or resources. [Run an evaluation](/user-guide/evaluation) to measure the deployed model.

## Adjust optional settings

| Goal | Where to change it |
| --- | --- |
| Change context length or batching | **vLLM parameters** in Standard; **Advanced settings** in the advanced editor |
| Enable tool calling | **Enable automatic tool choice**, then choose **Tool call parser** |
| Use a deployment-specific proxy | **Deployment environment** |
| Change replicas or accelerator count | **Replicas** and **Tensor parallelism** / **TP** |

If startup reports insufficient KV-cache capacity, lower the maximum context
length or allocate more resources in a new configuration.

If **Your role cannot create deployments.** appears, ask an administrator for
deployment access to the target cluster. **Open Deployments** still lets you view
deployments you can access.

When creating a standard deployment, sufficient available cards let you proceed
directly. Otherwise, a red warning shows required, available, and total physical
cards. You can confirm when the physical total is sufficient, but the deployment
may remain **Pending** until cards become available. Reduce replicas / TP if the
physical total is insufficient.
