Welcome is the operator landing page. It opens directly with a Lens Assistant
prompt starter, current cluster issues and a small set of quick actions. It does
not duplicate cluster capacity, model-service tables, deployment history or
token usage; those remain on their owning pages.

## Who sees Welcome

Welcome is the first sidebar item for admins, maintainers and custom roles with
`cluster:cluster:read`. Consumer-only roles keep their existing landing page.
The page always filters issues and actions to the clusters and permissions your
account can use. If no cluster is accessible and your role can create clusters,
Welcome offers to open the create-cluster wizard.

## Workspace layout

The sidebar meets the top bar without an outer gap. Each page's title and short
description appear on the left of the top bar. Page controls, including
**Create**, **Refresh**, filters and back buttons, stay in the content area
below it, with balanced side margins. The top bar stays visible while content
scrolls and always shows
**Documentation**, **Join Slack**, **Star on GitHub** and the theme switch,
regardless of the page. The page title is not repeated above the content.
On smaller screens, the links appear as labeled icon buttons.
Use the top-right sun or moon button to switch themes; scrollbars, including
the Model Services canvas, follow the selected theme. The sidebar collapse
control and account menu remain in the sidebar. When expanded, **Lens Assistant**
and the icon-only account menu share the bottom row; hover over the account icon
to see its label and username. When collapsed, their icons are stacked.
Administration sections can be expanded or collapsed even while viewing a
page in another section. Navigating to an administration page opens its section.

Right-side drawers close when you click the dimmed backdrop, unless the form is
submitting or the drawer explicitly requires an in-panel action.

Benchmark details group the task header, runtime status and section tabs on one
surface with dividers. Observability similarly groups its service controls and
the Namespace/GUIs row. **Platform → Model Usage** places **Time range**,
**Group by**, **User**, **Model**, **Cluster** and **Clear filters** together in
one row when space permits; controls wrap on narrow screens.

Page actions share compact buttons and icon-only refresh controls:

| Page | Control location |
| --- | --- |
| Deployments | Create and refresh at the right of the Total-through-Cleaned cards |
| Evaluation and Trace Replayer | New Task and refresh at the right of the task-status cards; click a card to filter |
| Storage | New storage volume and refresh after the Failed card |
| Model cache | Download model and refresh after the Deleting card; synchronization and back controls stay alongside |
| Clusters | Cluster selection, readiness, edit, navigation, search and Add share one desktop toolbar; the description is available from its help icon |
| Observability | Service tabs, context, target cluster and refresh share one desktop toolbar |

Controls wrap on narrow screens instead of clipping.

## Ask Lens Assistant

Welcome uses a compact fleet-status card so that issues and the assistant remain
easy to scan. The assistant's **Message** field has a visible border and can be
resized vertically.

1. Type a message in the **Message** field under **Ask Lens Assistant**.
2. Choose an AI provider in the lower-left of the composer.
3. Click **Send**, or press `Enter`. Use `Shift+Enter` for a new line.

Sending opens Lens Assistant, selects the provider you chose, and submits the
message automatically once the provider is ready. Tool calls keep the assistant's
normal confirmation rules. The prompt is carried in temporary browser session
storage, not in the URL.

Only providers Lens Assistant can use are listed. If none are available, Send
is disabled and the composer links to **External providers**. If your role
cannot add providers, ask an administrator. If the provider list cannot be
loaded, retry; do not assume no provider exists.

If your role cannot use Lens Assistant, the page shows a short permission note
instead of an unusable composer. Issues and permitted quick actions remain
available.

## Review cluster issues

**Needs attention** lists current findings in the selected cluster scope:

- No accessible clusters, a cluster without model-cache storage, or a recorded HF_TOKEN Secret that no longer exists. The missing-storage issue links to **New storage volume** with the cluster and the **Model cache** purpose already selected.
- A model-cache volume has no cached model, or a cluster's model-cache volumes contain no ready model.
- Cluster components or nodes that are not ready. Missing Grafana dashboards are informational when core monitoring is healthy.
- Model services without a ready serving path, or unavailable Gateway/IPP.
- Sustained serving pressure or backend errors on a backing deployment.
- Recent deployment failures, or ready deployments that no model service publishes.
- Failed storage provisioning or model-cache download/sync.
- Active users with no direct or group-inherited role, or groups with no role binding (info). Each user finding names the user and links to that user's role editor.
- No compatible External AI provider (info).

Each row shows severity, resource identity, evidence, the first time the issue was seen and a diagnostic
link labeled **To check**, **To fix**, or **To resolve**. A finding without sufficient telemetry
is shown as unknown or stale, not as healthy.

Use the cluster selector in the section header to narrow the list. **View all
issues** opens the full, filterable issue page. The page refreshes current issues
every 15 seconds and keeps the existing rows during a quiet refresh.

## Quick actions

The right-hand rail contains actions your role can perform:

| Action | What it opens |
| --- | --- |
| Token usage analytics | Usage reports for recorded token consumption. |
| Add a model deployment | Model market, to prepare a model for serving. |
| Publish a model service | Model services with the add form requested. |
| Launch benchmark | Evaluation with the new-task wizard open. |
| Replay traces | Simulation with the new-task form open. |
| Manage storages | Storage, to inspect or create cluster volumes. |
| Cache a new model | Model cache with the download form requested. |
| Create a new cluster | Clusters with the create wizard requested. |

Actions are navigation only. Forms, validation, confirmations and writes remain
on the destination pages and are still permission-gated. Actions you cannot
perform are not shown.

## Empty and partial states

| What you see | Meaning |
| --- | --- |
| All systems operational | Health checks and telemetry across monitored clusters are reporting normally. No action is required. |
| Cluster access needed | Your account has no accessible cluster. Ask for a cluster-scoped role. |
| Some checks unavailable | One or more telemetry or Kubernetes sources did not answer. |
| No compatible provider | Add an OpenAI-compatible provider under External providers. |
| Assistant not available | Your role lacks `playground:chat:use`. |
