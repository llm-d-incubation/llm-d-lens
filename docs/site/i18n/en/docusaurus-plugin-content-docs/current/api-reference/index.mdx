Lens exposes two ways to automate the same operations:

- **REST API** for remote clients, scripts and the browser.
- **In-process Python SDK** for trusted automation on the Lens host.

Both use the same request and response models, permissions and audit rules.

## Quick start

### REST API

Use a Bearer access token or an authenticated browser session:

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  http://127.0.0.1:3000/api/v1/deployments/executions
```

Unsafe cookie-authenticated requests also need the `prism_csrf` cookie in the
`x-prism-csrf` header. See [Authentication](/user-guide/administration).

### In-process Python SDK

```python
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    executions = lens.deployments.list_executions()
    for execution in executions:
        print(execution.execution_id, execution.status)
```

The SDK is for code running on the Lens host. Use REST when the caller is remote
or the local user is not trusted.

## Choose an API

| Caller | Use |
| --- | --- |
| Remote service, CI runner or another machine | REST API with a Bearer token |
| Browser UI | REST API with a session cookie |
| Trusted script or CI job on the Lens host | In-process Python SDK |
| Lens Assistant | MCP tools |

## Conventions

- Responses are JSON unless the operation downloads a file or streams events.
- Errors use `application/problem+json` with a stable `code`, `message` and
  optional `details`.
- Requests are authenticated. Unsafe cookie-authenticated requests require CSRF.
- Resource-level permissions and cluster scope are enforced by the service layer,
  not only by the route.
- Field names in HTTP payloads are camelCase. Python models expose snake_case
  attributes and accept both names where aliases are defined.

## Deprecated paths

Old `/api/...` paths such as `/api/cluster`, `/api/simulation` and `/api/mcp`
remain temporary aliases to `/api/v1/...` while clients migrate. `/healthz`
remains available for process probes.

## Full schema

The generated OpenAPI schema is the source of truth for every request and
response field:

- Swagger UI: `/api/v1/simulation/docs`
- OpenAPI JSON: `/api/v1/simulation/openapi.json`

Use the module pages for common tasks and the OpenAPI schema for exhaustive field
definitions.
