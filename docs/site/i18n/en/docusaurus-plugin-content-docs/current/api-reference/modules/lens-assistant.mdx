## Backend API

Lens Assistant uses `llm_d_lens.mcp.router` in the unified Python service. Its FastAPI router exposes the stateless Streamable HTTP endpoint at `/api/mcp` using the official MCP Python SDK.

Candidate tools advertise and forward either `workload.concurrency` or
`workload.request_rate` (positive, mutually exclusive load targets). The compatibility
API defaults omitted input/output token lengths to 4000/1000, matching Agentic
planning. Expected validation messages and no-feasible-candidate retry behavior
are preserved. Other AIC service failures return the generic
`{ "error": "AIC candidate search failed" }` response with status `400`;
internal exception details are logged only on the server.

### Send one stateless MCP request

Handle one stateless Streamable HTTP MCP request with a fresh SDK server and transport manager.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/mcp`**

Request:

- Content type: `application/json`
- Body: one MCP JSON-RPC request object. In stateless mode, Lens creates a fresh server per request, so no session id is required.
- Common request shapes include `initialize`, `tools/list`, and `tools/call`.

Example `tools/call` request:

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "method": "tools/call",
  "params": {
    "name": "list_simulation_backends",
    "arguments": {}
  }
}
```

Response:

Successful responses use MCP JSON-RPC result envelopes. For tool calls, Lens' MCP server returns `content` blocks whose `text` contains the JSON-stringified Lens REST result.

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\n  \"items\": []\n}"
      }
    ]
  }
}
```

If an unhandled server error occurs before the SDK sends a response, Lens returns:

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32603,
    "message": "Internal server error"
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

Use the official MCP Python client for transport calls. For metadata, `llm_d_lens.mcp.catalog.catalog(app)` returns the same tool definitions used by the endpoint. In-process domain integrations can reuse the helper shown on the [Deployments](/api-reference/modules/deployments) page:

```python
from llm_d_lens.deploy.standard_kubernetes_service import (
    StandardKubernetesServiceRequest,
    build_standard_kubernetes_service_configuration,
)

request = StandardKubernetesServiceRequest(
    model="meta-llama/Llama-3.1-8B-Instruct",
    deployment_name="assistant-backed-deploy",
    cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
    replicas=1,
    tensor_parallel_size=1,
)
configuration = build_standard_kubernetes_service_configuration(request)
print(configuration.checksum)
```

  </TabItem>
</Tabs>

### GET is not supported in stateless mode

Return `405 Method not allowed.` because stateless mode does not support the Streamable HTTP GET stream.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`GET /api/mcp`**

Request:

This endpoint has no request body. In Lens' stateless MCP mode, the Streamable HTTP GET stream is intentionally disabled.

Response:

Returns a JSON-RPC error payload with HTTP status `405`.

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

The Python router rejects GET streams in stateless mode. Use the MCP client's POST transport or the underlying Python domain, as summarized in [What the MCP tools call](#what-the-mcp-tools-call).

  </TabItem>
</Tabs>

### DELETE is not supported in stateless mode

Return `405 Method not allowed.` because stateless mode does not support session termination.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`DELETE /api/mcp`**

Request:

This endpoint has no request body. Lens does not keep MCP sessions between requests, so there is no server-side session to terminate.

Response:

Returns a JSON-RPC error payload with HTTP status `405`.

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

The Python router rejects session termination because it keeps no transport session. Configure the Python MCP client with `terminate_on_close=False`.

  </TabItem>
</Tabs>

`llm_d_lens.mcp.catalog` derives tools from the FastAPI OpenAPI schema and combines them with 25 special definitions in `llm_d_lens/mcp/definitions.json`. `node scripts/generate-mcp-tools.mjs --check` validates this catalog without generating Node files. `llm_d_lens.mcp.tools` invokes the canonical REST routes through an in-process ASGI client, preserving authentication, CSRF and resource-scope checks.

## What the MCP tools call

### Query public benchmark evidence

The generated `query_public_benchmark_rag` tool is read-only despite using POST.
The endpoint and operation ID retain their public-query names for compatibility,
including when the caller opts into the authorized internal branch.
It passes the REST body unchanged and returns the same `QueryResponse` JSON in
an MCP text block. It is not a deployment-planner tool or a corpus ingestion API.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/benchmark-rag/query`**

Requires a real authenticated caller with `benchmark-rag:query:read` at GLOBAL
scope. Only GLOBAL admins receive it by default. Other roles require explicit
GLOBAL grants; cluster grants, anonymous and disabled-auth `system` identities
do not qualify. Browser cookie calls must also satisfy the standard CSRF policy.
MCP callers additionally need `mcp:tool:invoke` or `playground:chat:use`.
The Python MCP adapter forwards the actual caller through an in-process ASGI
request using internal HMAC signatures, never a service principal or an identity
provided in arguments. It validates strict input and response schemas without
converting Decimal strings; failed or malformed responses become MCP tool errors
without returning upstream evidence. No separate Node server is required.

```json
{
  "question": "What published throughput measurements match this workload?",
  "intent": "numeric",
  "filters": {
    "origins": ["prism:public-snapshot"],
    "metric": "throughput",
    "statistic": "mean",
    "unit": "tokens/s",
    "workload": {"batch_size": 8},
    "value_min": "100.000000001",
    "normalized": false
  },
  "limit": 10,
  "include_internal": false
}
```

`question` is required (1–2048 characters). `intent` is `auto` (default),
`numeric`, `comparison`, `definition` or `figure`; `limit` defaults to 10
(1–50 total returned evidence envelopes across both branches, after verified merges).
`include_internal` is a boolean defaulting to `false`. Without opt-in, no internal
data, counts or identity checks are accessed. With `true`, the existing GLOBAL
RAG grant is still required, and internal records additionally require the existing
`evaluate:run:read` policy in their owning evaluation context. Missing, deleted or
unverifiable owners are excluded even for admins; opt-in is not an authorization bypass.
Extra request/filter fields are rejected; there is no arbitrary SQL.
Filters include `origins`, `source_revision`, `source_path`, `record_id`,
`experiment_id`, `model`, `hardware`, `runtime`, `metric`, `statistic`, `unit`,
structured JSON `workload` and `series`, `value_min`, `value_max` and `normalized`.
Numeric ranges require an explicit `unit`; minimum must not exceed maximum.
Use Decimal strings to preserve precision. Normalized retrieval is explicit;
responses retain original units and expose normalized values, units and rules
separately rather than silently mixing incompatible measurements.
Question planning uses bounded deterministic keyword rules, not general NLP or
LLM inference. Numeric questions extract explicit statistics such as `p99`,
`99th percentile`, `mean`/`average`/`avg` and `median` (`p50`), and model
identifiers such as `Llama-3.1-70B` or `org/model`. Bare names can use
`for Falcon on H100`; multiword names need a label such as `model "Custom Model"`.
Quoted names are treated as one identifier, including embedded version numbers
or repository-like tokens. An empty/missing model label abstains before retrieval.
Recognized model/statistic conditions must agree with explicit filters;
conflicts are validation errors, not overrides. Multiple statistics/models or
an ambiguous model subject produce `statistic_scope_required` or
`model_scope_required` abstentions before retrieval. Use separate exact queries
for these comparisons. An absent requested model/statistic yields
`no_exact_match`, never a different model or a mean substituted for p99.
Other conditions still need explicit structured filters; these bounded rules
are not a guarantee that arbitrary free-form constraints are understood.
With `intent: "auto"` and no explicit measurement scope, `What is TTFT?`,
`Define request latency` and metric-definition comparisons search passages.
An explicit `filters.metric` is a measurement scope: a short question with only
that filter stays numeric and requests experiment conditions rather than searching prose.
Measurement questions recognize both `TTFT`/`time to first token` and
`TPOT`/`time per output token`. An explicit `intent` is never overridden.
Automatic keyword rules are English-only. Questions in other languages are
supported through explicit `intent` and structured `filters`, not automatic
language understanding.

The response has `contract: "benchmark-rag.query.v1"`, resolved `intent`,
`question`, `filters`, `status` (`answered`, `partial`, `abstained`), `answer`,
`evidence`, `matched_items`, `returned_observations`, `truncated`, `abstentions` and `warnings`.
It always reports `generation_mode: "deterministic"`.
`internal_branch_enabled` defaults to `false` and reflects request opt-in, not
whether any internal record was authorized or returned. `matched_items` counts
candidate public index items plus authorized internal benchmark records; it is
neither an independent-experiment count nor an exact distinct-run count.
`returned_observations` counts returned metric/evidence envelopes **after verified
merges**. `truncated` explicitly reports omitted results under the total `limit`.
Evidence contains Decimal string values,
units/statistics, experiment context, optional normalized values and figure
coverage/missing-series information. Figure evidence may also include
`related_experiments` (default: empty), containing only explicitly linked
published scenarios with their experiment context; identities are not guessed.
Public citations identify the origin,
revision, path, SHA-256, archived artifact URI, source pointer, heading path
and published manifest.

Evidence `origin` is `public`, `agentic` or `public_and_agentic`; internal
measurements use `evidence_type: "agentic_measurement"`. An `AgenticCitation`
contains `origin_id: "agentic:evaluate"`, `evidence_type: "agentic_measurement"`,
`benchmark_id`, `evaluate_run_id`, `cluster_id`, `resource_uri`, `record_sha256`,
`metric_field`, `record_timestamp`, `access_scope: "owning_evaluation"` and
`numeric_precision: "stored_float"`. Internal normalized metrics are persisted
as Float values: their response Decimal strings represent the stored float,
**not** the exact original source token. Public raw-byte precision is unchanged.

Evidence text, source-pointer strings and experimental-context JSON preserve
original whitespace, including JSON keys and table cells. Character offsets
and numeric subvalue spans refer to those untrimmed strings. Request questions
and filter strings continue to be trimmed independently.

A public/internal merge requires a canonical `evaluate:<UUID>` identifier
actually present in the pinned public raw JSON and a matching metric, statistic,
unit and value. Model/workload similarity is not identity proof. A verified merge
returns one envelope with the public `citation`, retained internal
`corroborating_citations`, and
`identity_verification: "canonical_evaluate_run_and_metric"`.
Otherwise `corroborating_citations` defaults to empty and `identity_verification`
is optional/null. Unknown overlaps remain separate; unauthorized records cannot
affect overlap identity or leak through counts or citations. Historical writer
records with eight-character simulation task IDs in `evaluate:<id>` lack a
verifiable canonical evaluation owner and are intentionally omitted; querying
does not rewrite them or change the planner.

An abstention is an explicit domain result; upstream
authorization, transport or corrupt-response failures are MCP `isError: true`
results without evidence, not successful empty responses.

Missing or corrupt pinned evidence, including malformed archive manifests,
returns REST HTTP 503 with code `rag_evidence_unavailable`, not an abstention
or a partial answer. Restoring the unchanged valid manifest and source bytes
allows subsequent queries to recover without reindexing.

Only approved published public sources are eligible: `prism:public-snapshot`,
`https://github.com/VincyZhang/llm-d`, and
`https://github.com/llm-d/llm-d-benchmark.git`. Restore the published corpus and
its immutable source archive together; database records alone are insufficient.
These are the public branch's sources. The opt-in internal branch retrieves only
authorized stored evaluation measurements, not arbitrary private data. Neither
branch uses an Agentic generation path.
Local-instance acceptance does not certify production, multi-Pod or cross-cluster
deployment; validate the selected runtime and shared evidence storage separately.

  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
    "question": "What published throughput measurements are available?",
    "intent": "numeric",
    "filters": {"metric": "throughput", "unit": "tokens/s", "value_min": "100.1"},
    "limit": 10,
})
body = request.model_dump(mode="json")
# Send body to the authenticated REST endpoint; validate its successful JSON:
# result = QueryResponse.model_validate(response_json)
# print(result.model_dump(mode="json"))  # Decimal values remain strings.
```

DTO validation is not authorization: use an authenticated REST session, or the
shared service with the real caller's resolved principal. Do not fabricate a
`system`/admin identity or bypass GLOBAL permission checks.

### Administer reviewed benchmark refreshes

Refreshing evidence is a target-local administration operation, **not** a
REST endpoint or MCP tool. The query tool remains read-only and cannot approve
sources, refresh them or roll back publication.

<Tabs>
  <TabItem value="rest-api" label="REST / MCP">

No write endpoint is exposed. A trusted operator/job runs:

```bash
export PYTHONPATH=apps/backend/src
python -m llm_d_lens.benchmark_rag.admin refresh \
  --schema public --data-dir /srv/lens-data \
  --plan /secure/rag/approved-plan.json --source /srv/sources/llm-d-benchmark \
  --trigger commit --event-revision "$REVIEWED_COMMIT"
```

Use `--trigger periodic` without `--event-revision` for cron/managed Jobs.
Both triggers consume the same approved fixed-commit plan, never branch HEAD.
Prism snapshot refreshes use `--trigger manual` only.
Configure `LLM_D_BENCH_DATABASE_URL` securely; do not put credentials in
arguments or reviewed plans. No scheduler or real cluster Job is installed
automatically.

  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
import os
from pathlib import Path

from llm_d_lens.benchmark_rag.publication import RagPublicationService
from llm_d_lens.benchmark_rag.refresh import RagRefreshService, RefreshPlan
from llm_d_lens.db.dao.rag_transfer import transfer_database

# LENS_DATA_DIR must name the same persistent archive used by query instances.
plan = RefreshPlan.model_validate_json(Path("/secure/rag/approved-plan.json").read_bytes())
with transfer_database(os.environ["LLM_D_BENCH_DATABASE_URL"], schema="public") as dao:
    dao.prepare()
    report = RagRefreshService(RagPublicationService(dao=dao)).run(
        plan, Path("/srv/sources/llm-d-benchmark"), trigger="periodic"
    )
    print(report.model_dump_json())
```

`RefreshPlan.model_json_schema()` describes the strict plan contract. Review
the exact source approval, full inventory/path hashes, per-kind counts,
base manifest/generation, allowed triggers and all figure coverage. New guide
numeric revisions also require `metadata_review_reference` confirming that
the existing adapter's model, hardware and workload assumptions remain valid;
new schemas/layouts still require an adapter update. Empty inventories need
explicit `allow_empty: true`. Plans never expand the source/path allowlist,
re-enable a source or infer ownership from simulation IDs.

  </TabItem>
</Tabs>

Success emits a `published` or `unchanged` JSON report containing plan/inventory
hashes, review reference, revision, file and per-kind counts, timestamps and
publication IDs/generation. Failure exits 1 with a failed JSON report on stderr,
not a successful empty import. Persist job stdout/stderr for attempt history.
`admin status --origin ...` reads the active source head/history; explicit
`admin rollback --origin ... --manifest-id ... --expected-generation ...`
restores a previously published manifest. Both require the same schema/data-dir
arguments. Old citations remain backed by retained bytes; new answers use only
current published members. Stale plans, concurrent changes, incomplete
inventories or pagination, and parser/hash/count failures cannot replace the
active release. A direct approved replay is a no-op; an old periodic job cannot
undo a rollback or access-policy change.

### Evaluate the fixed evidence baseline

This is a read-only acceptance API, not a REST/MCP tool or an LLM judge.
`llm_d_lens.benchmark_rag.evaluation` exposes versioned `EvaluationSuite`,
`EvaluationCase`, `EvaluationReport` and:

```python
report = run_evaluation(
    suite,
    execute=execute_authorized_case,
    verify_evidence=verify_retained_source_evidence,
)
```

Execution must use the actual caller's permissions. The mandatory independent
verifier checks every primary/corroborating citation against retained bytes or
authorized owning records; it returns a tuple of issue codes, empty only for
valid evidence. The runner checks exact Decimal observations, deterministic
measured answer lines, context/refusals, origin/type restrictions, limits,
counts and leakage expectations. Unexpected errors propagate; expected denial
requires the actual domain error. Every case must pass, with no skipped source
acceptance. This does not evaluate arbitrary free-form model output.

Replay the fixed public and internal suites from the repository root:

```bash
LENS_RAG_BASELINE_REPORT_DIR=/secure/acceptance/rag-v1 \
PYTHONPATH=apps/backend/src .venv/bin/python -m pytest \
  apps/backend/tests/unit/db/test_rag_public_baseline.py \
  apps/backend/tests/unit/db/test_rag_internal_baseline.py \
  apps/backend/tests/unit/benchmark_rag/test_evaluation.py -q
```

The public suite needs the separately provisioned pinned three-source inputs.
Internal cases create isolated live-owner/Evaluate fixtures; they do not fix
or broaden legacy simulation ingestion. Optional reports contain pinned source
versions/inventory hashes, suite hashes,
timestamps, case outcomes and issue codes, not raw private responses.
`verified_citations` includes corroborating provenance;
`numeric_observations` counts numeric envelopes.

Passing the baseline does **not** enable additional sources. Every new
repository/dataset, GCS/GIQ source or paper collection still needs separate
visibility/license/permission approval, exact origin/path/revision inventory,
adapter and original-byte regressions, manifest publication, rollback and
withdrawal tests. Papers remain explanatory unless measurements are
independently verified. URLs discovered in evidence never approve themselves;
the v1 allowlist is unchanged.
