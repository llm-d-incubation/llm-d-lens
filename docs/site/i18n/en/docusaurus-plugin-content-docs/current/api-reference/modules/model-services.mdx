## What this module is

Model services turns a ready deployment into an OpenAI-compatible model name that applications can call through a shared gateway. Use it to create and rotate API keys, discover callable models and gateway URLs, send chat requests, review token usage, and — with the right permissions — publish deployments and grant inference access.

## Quick start

Create an API key, find the gateway for your cluster, then call a published model with any OpenAI-compatible client.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
# 1. Create an API key. Copy `token` now: it is returned only once.
curl -X POST "$LENS_URL/api/v1/model-service/tokens" \
  -H "Content-Type: application/json" \
  -d '{"name":"my-app"}'

# 2. Get the gateway base URL for your cluster.
curl "$LENS_URL/api/v1/model-service/connection"

# 3. Call a model through that gateway.
curl "$GATEWAY_URL/v1/chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":"Hello"}]}'
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.sdk import LensLocal
from llm_d_lens.model_service.contracts import TokenCreateRequest

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        issued = await lens.model_services.create_token(TokenCreateRequest(name="my-app"))
        print(issued.token)

        connection = await lens.model_services.model_service_connection()
        for cluster in connection.clusters:
            print(cluster.cluster_name, cluster.base_url)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### Rotate or revoke an API key

Rotating revokes the active key or keys and issues a replacement. Revoking one key returns `204` and stops new requests that use it.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST "$LENS_URL/api/v1/model-service/tokens/regenerate" \
  -H "Content-Type: application/json" \
  -d '{"name":"default"}'

curl -X DELETE "$LENS_URL/api/v1/model-service/tokens/<token-id>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.sdk import LensLocal
from llm_d_lens.model_service.contracts import TokenCreateRequest

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        issued = await lens.model_services.regenerate_token(TokenCreateRequest(name="default"))
        print(issued.token)
        await lens.model_services.revoke_token("<token-id>")

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### Find callable models and the gateway URL

Model services are cluster-scoped, so list entries include `clusterName` to distinguish the same public name in different clusters. Only active models with an online, positive-weight provider appear.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl "$LENS_URL/api/v1/model-service/models"
curl "$LENS_URL/api/v1/model-service/connection"
```

```json

  "items": [
    {
      "id": "msg-4a8b41f3dd6c",
      "name": "<model>",
      "clusterId": "cluster-a",
      "clusterName": "Cluster A",
      "status": "active"
    }
  ]
}
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

### Call a published model

Use the gateway base URL with any OpenAI-compatible client. The public model name belongs in `model`, not the provider's internal model name.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl "$GATEWAY_URL/v1/chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"model":"<model>","messages":[{"role":"user","content":"Hello"}]}'
```

To list the models a key may call, use `GET /v1/models` with the same key.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.sdk import LensLocal
from openai import OpenAI

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        connection = await lens.model_services.model_service_connection()
        models = await lens.model_services.list_models()

        client = OpenAI(base_url=connection.clusters[0].base_url, api_key="<token>")
        reply = client.chat.completions.create(
            model=models.items[0].name,
            messages=[{"role": "user", "content": "Hello"}],
        )
        print(reply.choices[0].message.content)

    asyncio.run(main())
```

</Tabs>

### Publish a ready deployment as a model

A ready deployment can become a new public model name in its cluster. If the public name already exists in that cluster, add the deployment as a provider instead of publishing a duplicate.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
# Find ready deployments and their executionId values.
curl "$LENS_URL/api/v1/model-service/admin/deployments"

curl -X POST "$LENS_URL/api/v1/model-service/admin/groups/publish" \
  -H "Content-Type: application/json" \
  -d '{"name":"<model>","clusterId":"<cluster-id>","executionId":"<execution-id>"}'
```

Response (`201`) is the created model service. To add another deployment to an existing model, use `POST /api/v1/model-service/admin/members` with `groupId` and `executionId`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.sdk import LensLocal
from llm_d_lens.model_service.contracts import GroupPublishRequest

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        group = await lens.model_services.admin_publish_group(
            GroupPublishRequest(
                name="<model>",
                clusterId="<cluster-id>",
                executionId="<execution-id>",
            )
        )
        print(group.id, group.name, group.status)

    asyncio.run(main())
```

  </TabItem>

### Review your usage

Usage is recorded per request. Use the daily time series for trends and the record list for individual requests.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl "$LENS_URL/api/v1/model-service/usage/records?limit=50&offset=0"
curl "$LENS_URL/api/v1/model-service/usage/timeseries?days=30"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        records = await lens.model_services.usage_records(limit=50, offset=0)
        for record in records.items:
            print(record.group_name, record.input_tokens, record.output_tokens)

        totals = await lens.model_services.usage_timeseries(days=30)
        for item in totals.items:
            print(item.date, item.requests, item.output_tokens)

    asyncio.run(main())
```

## Endpoints

Consumer and API-key endpoints:

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |
| GET | `/api/v1/model-service/tokens` | `model-service:token:manage` | List your active API keys. |
| POST | `/api/v1/model-service/tokens` | `model-service:token:manage` | Create a key; plaintext returned once. |
| POST | `/api/v1/model-service/tokens/regenerate` | `model-service:token:manage` | Revoke active keys and issue a replacement. |
| DELETE | `/api/v1/model-service/tokens/{token_id}` | `model-service:token:manage` | Revoke one key. |
| GET | `/api/v1/model-service/models` | `model-service:inference:use` | List models you may call. |
| GET | `/api/v1/model-service/connection` | `model-service:inference:use` | Get gateway base URLs per cluster. |
| GET | `/api/v1/model-service/usage/records` | `model-service:usage:read` | List your recent usage. |
| GET | `/api/v1/model-service/usage/timeseries` | `model-service:usage:read` | Get daily token totals. |
| GET | `/v1/models` | Model token | OpenAI-compatible model list. |
| POST | `/v1/chat/completions` | Model token | OpenAI-compatible chat completion. |

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |

| POST | `/api/v1/model-service/admin/groups` | `model-service:group:manage` | Create a model service, optionally with a deployment. |
| POST | `/api/v1/model-service/admin/groups/publish` | `model-service:member:manage` | Publish a ready deployment as a new model. |
| PATCH | `/api/v1/model-service/admin/groups/{group_id}` | `model-service:group:manage` | Update metadata or status. |
| POST | `/api/v1/model-service/admin/groups/{group_id}/status` | `model-service:group:toggle` | Enable or disable a model. |
| DELETE | `/api/v1/model-service/admin/groups/{group_id}` | `model-service:group:remove` | Delete an empty model. |

| GET | `/api/v1/model-service/admin/usage[/analytics]` | `usage:report:read` | Read usage across users, models and clusters. |

## Errors / limits

- **The model token is returned once.** Only `POST /api/v1/model-service/tokens` and `POST /api/v1/model-service/tokens/regenerate` include `token`. Other responses show `tokenHint`. Store the token immediately.
- **Access requires both cluster permission and a model grant.** Consumers need inference permission in the model's cluster plus a direct or group grant on that model. Deployment ownership does not grant inference.
- **Model names are cluster-scoped.** The same public name can exist in different clusters. Use `clusterName` to choose the right gateway.
- **A model needs at least one active, online, positive-weight provider.** Disabled models, offline providers and zero-weight providers receive no traffic.
- **Publishing needs a ready deployment in the same cluster.** A duplicate public name returns `409`; add the deployment as a member or choose another name.
- **Only empty models can be deleted.** Any attached provider, including an offline or zero-weight one, returns `409 model_group_conflict`.
- **Saved state can outlive a routing failure.** `502` with `model_publication_apply_failed` or `model_traffic_apply_failed` means the change was saved but routing was not applied; retry **Reconcile** after fixing the cause. `model_removal_failed` keeps the record so you can retry removal.
- **Common status codes.** `401 token_invalid` for a missing, expired or revoked model token; `403` for missing permissions or cluster scope; `404` for missing resources; `409` for conflicts; `422` for invalid input.
- **Paging limits.** Usage records accept `limit` up to `500`; the time series accepts `days` from `1` to `365`.
- **Cached-token counters depend on the engine.** The usage ledger supports cached input and cache-write tokens, but some engines report only input and output tokens, so those fields may be `0`.
