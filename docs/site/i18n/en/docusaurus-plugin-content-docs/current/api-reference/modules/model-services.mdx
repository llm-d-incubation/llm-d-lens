## Backend API

Model Service routes are split across `llm_d_lens/model_service/router.py`'s user, admin, public, and internal routers.

### List model access tokens

List the caller's active model access tokens. The response never includes plaintext token values, only the metadata needed to identify and revoke them later.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/v1/model-service/tokens`**

    Request: no request body. The caller must be authenticated with a Lens user session.

    Response: returns an `items` array of `ModelAccessToken` records projected through `ModelAccessToken.api_payload()`, so `tokenHash` is omitted.

    ```json
    {
      "items": [
        {
          "id": "mat-7f2c4a19b6d1",
          "userId": "user-123",
          "name": "laptop",
          "tokenHint": "9mQx",
          "status": "active",
          "lastUsedAt": "2026-09-23T08:15:00Z",
          "lastUsedIp": "10.0.0.25",
          "createdAt": "2026-09-21T12:00:00Z"
        }
      ]
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.model_service.service import default_service

    service = default_service()
    tokens = service.tokens.list_for_user("user-123", include_revoked=False)
    for token in tokens:
        print(token.api_payload())
    ```
  </TabItem>
</Tabs>

### Create a model access token

Create a new model access token for the caller. The plaintext token is returned exactly once together with the persisted token metadata.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/v1/model-service/tokens`**

    Request body (`TokenCreateRequest`):

    - `name` (`string`): display name for the token.

    ```json
    {
      "name": "automation"
    }
    ```

    Response: one `ModelAccessToken` payload plus the one-time `token` string.

    ```json
    {
      "id": "mat-2c47de48a35b",
      "userId": "user-123",
      "name": "automation",
      "tokenHint": "K8xP",
      "status": "active",
      "createdAt": "2026-09-23T09:00:00Z",
      "token": "lens-mk-bTj9X7mW4zP1qN8sR6uC2yF5hL0aV3dK1mQ"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.model_service.service import default_service

    service = default_service()
    token, raw_token = service.tokens.create("user-123", name="automation")

    print(token.api_payload())
    print(raw_token)
    ```
  </TabItem>
</Tabs>

<Tabs>

    ```json
      "tokenHint": "F6rN",
      "status": "active",
    ```

### Revoke a model access token

Revoke one previously issued model access token for the caller. After revocation, the token can no longer be used for gateway access.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`DELETE /api/v1/model-service/tokens/{token_id}`**

    Request: no request body.

    - `token_id` (`string`, path): token id such as `mat-7f2c4a19b6d1`.

    Response: `204 No Content`. This endpoint does not return a JSON body.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.model_service.service import default_service

    service = default_service()
    revoked = service.tokens.revoke("user-123", "mat-7f2c4a19b6d1")
    print(revoked)
    ```
  </TabItem>

### List accessible models

List callable active models with online positive-weight providers. Consumers need
inference permission in the model's cluster plus a direct or group model grant;
non-self-scoped operators retain inference access in their binding's scope.
Deployment shares and ownership do not grant consumer inference. This policy
also applies to `/v1/models` and Gateway authorization. Entries include
`clusterName` to distinguish identical public names in different clusters.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/v1/model-service/models`**

    Request: no request body. The caller must be authenticated with a Lens user session.

    Response: returns an `items` array of `ModelServiceGroup` payloads, each with an added `clusterName`.

    ```json
    {
      "items": [
        {
          "id": "msg-4a8b41f3dd6c",
          "name": "qwen3-8b",
          "modelRef": "Qwen/Qwen3-8B",
          "displayName": "Qwen3 8B",
          "description": "Shared Qwen 3 8B service",
          "selectionPolicy": "random",
          "status": "active",
          "clusterId": "cluster-a",
          "clusterName": "Cluster A",
          "servedName": "Qwen/Qwen3-8B",
          "baseModel": "Qwen/Qwen3-8B",
          "createdByUserId": "user-123",
          "createdAt": "2026-09-20T15:00:00Z",
          "updatedAt": "2026-09-22T11:30:00Z"
        }
      ]
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">

### Get gateway connection info

Return the Gateway connection info a client copies into its OpenAI client. Each cluster runs its own Gateway, so the response lists one connection per cluster the caller can access; `LENS_MODEL_GATEWAY_PUBLIC_URL`, when set, is a single override applied to every cluster.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/v1/model-service/connection`**

    Request: no request body.

    Response: the global override (empty string when unset) plus a per-cluster list.

    ```json
    {
      "baseUrl": "",
      "clusters": [
        {
          "clusterId": "cluster-a",
          "clusterName": "Cluster A",
          "provider": "istio",
          "gatewayName": "lens-inference-gateway",
          "address": "10.0.0.10",
          "publicUrl": null,
          "port": null,
          "baseUrl": "http://10.0.0.10/v1",
          "ready": true
        }
      ]
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import os

    import asyncio

    from llm_d_lens.model_service.gateway_ops import GatewayOpsService, gateway_base_url

    global_url = os.environ.get("LENS_MODEL_GATEWAY_PUBLIC_URL", "").strip()
    public_host = os.environ.get("LENS_PUBLIC_HOST", "").strip()
    status = asyncio.run(GatewayOpsService().status())
    clusters = [
        {
            "clusterId": cluster.cluster_id,
            "clusterName": cluster.cluster_name,
            "provider": cluster.gateway_provider,
            "gatewayName": cluster.gateway_name,
            "address": cluster.gateway_address,
            "publicUrl": cluster.gateway_public_url,
            "port": cluster.gateway_port,
            "baseUrl": gateway_base_url(cluster, public_host, global_url),
            "ready": bool(cluster.gateway_ready),
        }
        for cluster in status.clusters
    ]

    print({"baseUrl": global_url, "clusters": clusters})
    ```

### Get daily usage totals

Aggregate the caller's recent usage records into daily token totals. The handler reuses the same usage ledger and buckets it with `_daily_totals`.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/v1/model-service/usage/timeseries`**

    Request: no request body.

    - `days` (`integer`, query, default `30`, range `1..365`): number of recent days to include.

    Response: daily usage buckets with totals for each token class.

    ```json
    {
      "items": [
        {
          "date": "2026-09-22",
          "requests": 4,
          "inputTokens": 1200,
          "cachedInputTokens": 300,
          "cacheWriteTokens": 0,
          "outputTokens": 640
        },
        {
          "date": "2026-09-23",
          "requests": 2,
          "inputTokens": 530,
          "cachedInputTokens": 64,
          "cacheWriteTokens": 0,
          "outputTokens": 211
        }
      ]
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from datetime import datetime, timedelta

    from llm_d_lens.model_service.router import _daily_totals
    from llm_d_lens.model_service.service import default_service

    service = default_service()
    since = datetime.now() - timedelta(days=30)
    ```

### List model routing groups

List configured model groups in the caller's cluster-scoped read authority.
Each group is a public model name routing to deployment-owned InferencePools.
`GET /api/v1/model-service/admin/groups/{group_id}` enforces the same scoped
`model-service:group:read` permission. Group payloads also include nullable
`ownerUserId` and `ownerGroupId`; ownership alone does not grant consumer inference.

### Model inference grants

All access-management endpoints require `model-service:group:share` in the
model's cluster. Admin and maintainer have this permission; it does not imply
group or Gateway management. Grants cover every provider of the model, not its
management APIs. Model deletion revokes grants; renaming preserves them.
An empty model cannot move clusters while grants remain.

<Tabs>
  <TabItem value="rest-api" label="REST API">

| Method | Path below `/api/v1/model-service/admin/groups/{group_id}` | Result |
| --- | --- | --- |
| GET | `/access` | `{"items":[...]}` with grant IDs, `subjectType`, `subjectId`, `subjectName`, `permission`, `createdAt` |
| GET | `/access/options` | `{"users":[{"id":"user-123","username":"alice"}],"groups":[{"id":"group-123","name":"team"}]}` |
| POST | `/access` | HTTP 201 with grant ID, recipient and inference permission |
| DELETE | `/access/{binding_id}` | HTTP 204, empty body |

POST body:

```json
{"subjectType":"user","subjectId":"user-123"}
```

Response example:

```json
{"id":"binding-123","subjectType":"user","subjectId":"user-123","permission":"model-service:inference:use"}
```

Use `subjectType: "group"` for a group. No role, cluster or owner field is accepted.
The server fixes the grant role and derives the cluster from the stored model.
Recipients must already have inference permission in that cluster. The options
endpoint exposes only eligible recipient IDs and display names, not full
identity records. Disabled/protected users are not selectable.

Insufficient scope returns 403, missing resources or a mismatched revoke binding
return 404, duplicates return 409, and invalid/extra fields return 422.
Revocation re-evaluates subsequent requests using existing API keys without
interrupting already-running streams or changing HTTPRoute weights.
  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
from llm_d_lens.model_service.contracts import ModelGrantRequest
from llm_d_lens.model_service.service import default_service

def grant_model(model_id: str, user_id: str, principal):
    service = default_service()
    return service.grant_access(
        model_id,
        ModelGrantRequest(subject_type="user", subject_id=user_id),
        principal=principal,
    )

def read_model_access(model_id: str, principal):
    service = default_service()
    return (
        service.list_access(model_id, principal=principal),
        service.access_options(model_id, principal=principal),
    )

def revoke_model(model_id: str, binding_id: str, principal):
    default_service().revoke_access(model_id, binding_id, principal=principal)
```

Pass the authenticated caller's resolved principal. These methods enforce
grant-management action and model cluster scope, including for internal callers.
  </TabItem>
</Tabs>

### Create a model routing group

Create a routing group that exposes one user-facing model name in a single cluster. `name` and `clusterId` are required; the public name is unique per cluster (`clusterId`) and every provider must be a deployment in that same cluster. Supplying `executionId` creates the group and its initial member in one transaction, as used by **Add model**. The deployment must be ready and have a model name. Lens derives `modelRef` and `servedName` from that deployment and sets `baseModel` to the public name, ignoring caller overrides for those three fields. Without `executionId`, standalone group creation remains supported.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/v1/model-service/admin/groups`**

    Request body (`GroupCreateRequest`):

    - `name` (`string`): the public model name clients use in Chat Completions API requests.
    - `clusterId` (`string`): the cluster the service belongs to (required); its providers must be in this cluster and the name is unique within it.
    - `displayName` (`string`, optional): UI-friendly label; defaults to `name`.
    - `description` (`string`, optional): free-form description.
    - `executionId` (`string`, optional): ready deployment to publish as the first member. Requires both `model-service:group:manage` and `model-service:member:manage` in the deployment's cluster.
    - `modelRef` / `servedName` / `baseModel` (`string`, optional, advanced): with `executionId`, derived server-side. Without it, `modelRef` defaults to `name`, `baseModel` to `modelRef`, and `servedName` to null.
    - `selectionPolicy` (`string`, legacy): accepted for compatibility; the llm-d data plane ignores it.

    ```json
    {
      "name": "qwen3-8b",
      "clusterId": "cluster-a",
      "executionId": "exec-123",
      "displayName": "Qwen3 8B",
      "description": "Shared Qwen 3 8B service"
    }
    ```

    Response: `201` with the created `ModelServiceGroup`. When `executionId` is supplied, its member is also committed and gateway reconciliation is scheduled in the background. Errors: `403` for missing management permissions or scope, `404` for a missing deployment target, `409` for a duplicate name, cluster mismatch, non-ready deployment or missing deployment model name, and `422` for invalid input. A failed transaction leaves neither record behind.

    ```json
    {
      "id": "msg-4a8b41f3dd6c",
      "name": "qwen3-8b",
      "modelRef": "Qwen/Qwen3-8B",
      "clusterId": "cluster-a",
      "servedName": "Qwen/Qwen3-8B",
      "baseModel": "qwen3-8b",
      "displayName": "Qwen3 8B",
      "description": "Shared Qwen 3 8B service",
      "selectionPolicy": "random",
      "status": "active",
      "createdByUserId": "user-123",
      "createdAt": "2026-09-23T09:10:00Z",
      "updatedAt": "2026-09-23T09:10:00Z"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.model_service.contracts import GroupCreateRequest
    from llm_d_lens.model_service.service import default_service

    service = default_service()
    group = service.create_group(
        GroupCreateRequest(
            name="qwen3-8b",
            clusterId="cluster-a",
            executionId="exec-123",
            displayName="Qwen3 8B",
            description="Shared Qwen 3 8B service",
        ),
        created_by="user-123",
    )
    print(group.api_payload())
    print([member.api_payload() for member in service.list_members(group.id)])
    ```

    `exec-123` must identify an existing ready deployment in `cluster-a`.
    Trusted Python callers may omit `principal`; request adapters must pass the
    authenticated principal to enforce both permissions and cluster scope.
    `create_group` commits records only; the HTTP route additionally schedules
    gateway reconciliation.
  </TabItem>
</Tabs>

### Publish a deployment as a member

Publish one ready deployment execution into a routing group. The route derives the actual namespace, service, port, and endpoint kind from the execution id. The execution's cluster must be the group's cluster, otherwise the call is rejected with `409` (`model_member_conflict`).
Every new provider defaults to weight 1; existing provider weights are preserved.
Use the traffic-distribution endpoint to change the allocation.
The HTTP route schedules reconciliation; the direct Python call only persists.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/v1/model-service/admin/members`**

    Request body (`MemberCreateRequest`):

    - `groupId` (`string`): target routing group id.
    - `executionId` (`string`): ready deployment execution id.
    - `poolName` (`string`, optional, advanced): the deployment-owned InferencePool name; defaults to the deployment's pool stored as `namespace/pool` (unique across namespaces).

    ```json
    {
      "groupId": "msg-4a8b41f3dd6c",
      "executionId": "exec-qwen3-8b",
      "poolName": "ns/qwen"
    }
    ```

    Response: the created `ModelServiceMember`.

    ```json
    {
      "id": "msm-32d55cb7f9a1",
      "groupId": "msg-4a8b41f3dd6c",
      "executionId": "exec-qwen3-8b",
      "clusterId": "cluster-a",
      "targetNamespace": "ns",
      "targetService": "qwen-epp",
      "targetPort": 8000,
      "endpointKind": "llm-d-epp",
      "weight": 1,
      "poolName": "qwen",
      "eppRef": "qwen-epp",
      "status": "active",
      "ownerUserId": "user-123",
      "publishedByUserId": "user-123",
      "createdAt": "2026-09-23T09:12:00Z",
      "updatedAt": "2026-09-23T09:12:00Z"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.model_service.contracts import MemberCreateRequest
    from llm_d_lens.model_service.service import default_service
    ```

### Save and apply traffic distribution

Atomically replace all weights and optionally add deployment providers, then
reconcile the cluster's shared Gateway and weighted HTTPRoute. The
`model-service:member:manage` permission is required in the group's cluster.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`PUT /api/v1/model-service/admin/groups/{group_id}/traffic`**

    Request body (`TrafficUpdateRequest`):

    - `members`: complete list of 1 to 16 entries with `executionId` and integer `weight` in **0..1000000**. Existing providers cannot be omitted; use member deletion separately.
    - `expectedWeights`: previously read execution-ID-to-weight map, including every existing provider and excluding new providers.

    ```json
    {
      "members": [
        {"executionId": "stable", "weight": 90},
        {"executionId": "canary", "weight": 10}
      ],
      "expectedWeights": {"stable": 1}
    }
    ```

    New deployments and zero-weight providers being activated must be ready,
    in the same cluster, backed by distinct InferencePools/EPPs, and use the
    group's provider model name. At least one non-disabled provider must have
    positive weight. Zero-weight members remain stored but are not rendered
    in backendRefs; disabled members also receive no traffic.

    Response: `200` with `items` (full updated member payloads, including `weight`)
    and `operation` (a `GatewayOperation` with `status`, `message`, and
    `detailJson`). **A failed operation does not roll back the saved weights.**
    `succeeded` means the configuration was submitted, not that request counts
    have verified the split.

    Validation returns `422` for malformed/range-invalid values, `409`
    (`model_traffic_conflict`) for stale snapshots or invalid allocations,
    `404` for missing targets, and `403` for insufficient permissions.
    A transport/domain exception after saving returns `502`
    (`model_traffic_apply_failed`) explicitly stating that configuration was saved.
    Reload the allocation and retry Reconcile after resolving the failure.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    `ModelService.update_traffic()` validates and persists; call
    `GatewayOpsService.reconcile_cluster_gateway()` separately to submit it.
    Obtain the principal from the authenticated request, not user-supplied identity.

    ```python
    from llm_d_lens.auth.access import current_principal
    from llm_d_lens.model_service.contracts import TrafficUpdateRequest
    from llm_d_lens.model_service.gateway_ops import GatewayOpsService
    from llm_d_lens.model_service.service import default_service

    async def configure_traffic(request, group_id, canary_execution_id):
        service = default_service()
        principal = current_principal(request)
        existing = service.list_members(group_id)
        weights = {member.execution_id: member.weight for member in existing}
        members = [{"executionId": member.execution_id, "weight": member.weight}
                   for member in existing]
        members[0]["weight"] = 90
        members.append({"executionId": canary_execution_id, "weight": 10})
        saved = service.update_traffic(
            group_id,
            TrafficUpdateRequest(members=members, expectedWeights=weights),
            principal=principal,
        )
        operation = await GatewayOpsService().reconcile_cluster_gateway(
            saved[0].cluster_id, actor=principal.user_id,
        )
        return {"items": [member.api_payload() for member in saved],
                "operation": operation.api_payload()}
    ```
  </TabItem>
</Tabs>

The renderer `render_model_route(..., pools=[PoolBinding(...)])` emits exact
relative weights, one IPP model map, and cross-namespace ReferenceGrants.
Its existing `pool=PoolBinding(...)` single-backend calling convention remains
supported. Do not pass both forms. `PoolBinding.weight` defaults to 1.

### Delete a model routing group

Remove an empty routing group with cluster-scoped group-management permission.
Any attached provider, even offline or weight 0, returns `409 model_group_conflict`.
The handler serializes with Gateway reconciliation, removes the model's
Lens-managed HTTPRoute and IPP mapping, and confirms deletion before deleting
the record. Missing models return `404`; cleanup failure returns
`502 model_removal_failed` and retains the record for retry. Other models,
shared Gateway resources, deployments and Pods are not removed.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`DELETE /api/v1/model-service/admin/groups/{group_id}`**

    Request: no request body. Response: `204 No Content`.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster.registry import gateway_lock
    from llm_d_lens.model_service.gateway_ops import GatewayOpsService
    from llm_d_lens.model_service.service import default_service

    async def remove_model(group_id, principal):
        service = default_service()
        group = service.require_empty_group(group_id, principal=principal)
        async with gateway_lock(group.cluster_id):
    ```

### Start or stop all providers

Requires member-management permission in the model's cluster. Changes all provider
statuses atomically, then reconciles routing once per affected cluster. Weights,
parent model status and Pods are unchanged. Starting requires every deployment
to be ready in the registered cluster. An empty model, unready deployment or
concurrent provider change returns `409 model_member_conflict` without partial
status updates; missing models return `404`. A `502 model_publication_apply_failed`
means statuses were saved but route application failed: retry **Reconcile**.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`PUT /api/v1/model-service/admin/groups/{group_id}/providers/status`**

    ```json

    ```

    Success: `200` with `{"items": [...]}` containing the updated member payloads.

  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.model_service.contracts import ProvidersStatusRequest
    from llm_d_lens.model_service.gateway_ops import GatewayOpsService
    from llm_d_lens.model_service.service import default_service

    async def stop_providers(group_id, principal):
        members = default_service().set_providers_status(
            group_id, ProvidersStatusRequest(status="disabled"), principal=principal
        )
        for cluster_id in {member.cluster_id for member in members}:
            operation = await GatewayOpsService().reconcile_cluster(
                cluster_id, actor=principal.user_id
            )
            if operation.status != "succeeded":
                raise RuntimeError(operation.message)
        return members
    ```

### Stream a data-plane operation

Run a data-plane operation and stream its log lines as Server-Sent Events. Used by the admin UI for install/uninstall/reconcile so the log drawer updates live.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/v1/model-service/admin/gateway/stream`**

    Request body (`GatewayStreamRequest`):

    - `clusterId` (`string`)
    - `op` (`string`): `install-gateway` | `uninstall-gateway` | `reconcile` | `scale` | `install-ipp` | `uninstall-ipp`
    - `provider`, `namespace`, `name`, `replicas`, `kind`, `gatewayName`, `ippChart`, `ippVersion` (optional, depending on `op`)

    ```json
    { "clusterId": "cluster-a", "op": "reconcile" }
    ```

    Response: `text/event-stream`; each event carries one log line, then the terminal `GatewayOperation` payload.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    The stream is an HTTP transport; the equivalent Python calls run the operation directly.

    ```python
    import asyncio

    from llm_d_lens.model_service.gateway_ops import GatewayOpsService

    async def main() -> None:
        ops = GatewayOpsService()
        await ops.reconcile_cluster_gateway("cluster-a")          # op=reconcile
        await ops.install_cluster_gateway("cluster-a")            # op=install-gateway
        await ops.uninstall_inference_gateway("cluster-a")        # op=uninstall-gateway
        await ops.install_ipp("cluster-a")                        # op=install-ipp
        await ops.uninstall_ipp("cluster-a")                      # op=uninstall-ipp

    asyncio.run(main())
    ```
  </TabItem>
</Tabs>

## Internal endpoints (Edge ext_authz)

These `/api/v1/internal/model-gateway/*` routes are called only by Edge Envoy's `ext_authz` filter and the llm-d EPP, never by Lens clients directly; they carry no Lens user session.

### Authorize a gateway request

Validate the caller's model token, resolve the requested public model name to an active routing group the token may use, select one backend member, and return routing headers for Edge Envoy to attach upstream. `GET /v1/models` (no model) is token-checked only; every other HTTP method is accepted because Envoy forwards the client's original method.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/v1/internal/model-gateway/authorize`** (also `GET`/`PUT`/`PATCH`/`DELETE`, and `/authorize/{rest:path}` for Envoy's per-cluster path shape, e.g. `.../authorize/cluster/<id>/...`)

    Request: a JSON body `{"token": "...", "model": "..."}`, or the raw OpenAI request body plus `Authorization`/`x-api-key` and `x-lens-model`/`x-gateway-base-model-name` headers.

    Response: `200` with the `AuthorizeResult` payload and `x-lens-*` / `x-ai-eg-model` / `x-llm-d-inference-fairness-id` routing headers Edge forwards upstream; `401` (`token_invalid`) or `404` (`model_not_found`) on failure.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.model_service.contracts import AuthorizeRequest
    from llm_d_lens.model_service.service import default_service

    service = default_service()
    result = service.authorize_request(
        AuthorizeRequest(token="lens-mk-bTj9X7mW4zP1qN8sR6uC2yF5hL0aV3dK1mQ", model="qwen3-8b"),
        cluster_id="cluster-a",
    )
    print(result.model_dump(mode="json", by_alias=True))
    ```
  </TabItem>
</Tabs>
