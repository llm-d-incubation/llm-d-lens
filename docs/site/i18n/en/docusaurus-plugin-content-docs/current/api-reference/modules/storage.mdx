## Overview

Storage registers the local disk, NFS export, or dynamic PVC that Lens mounts into
model cache downloads and deployments. Create a volume here before downloading
cached models or deploying a model that needs shared storage. Volumes can be
tagged with the `model-cache` purpose, which makes them selectable in Model Cache
and requires `local-disk` or `nfs` storage rather than `dynamic-pvc`.

## Quick start

List the storage volumes you can use, optionally scoped to one cluster.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes?cluster_id=<cluster-id>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        result = await lens.storage.list_storage_volumes(cluster_id="<cluster-id>")
        for volume in result.items:
            print(volume.id, volume.name, volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

`status` moves from `pending` to `ready` (or `failed`) while provisioning runs in
the background.

## Common tasks

### Create a local-disk model cache volume

Use `local-disk` when the same host path is prepared on every node. The volume
must be writable to hold model downloads. Creation returns `202` and returns the
record in `pending` state while Kubernetes objects are provisioned.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "name": "<volume-name>",
    "kind": "local-disk",
    "capacity": "500Gi",
    "readOnly": false,
    "purposes": ["model-cache"],
    "localDisk": {"hostPath": "/srv/model-cache"}
  }' \
  "$LENS_URL/api/v1/storage/volumes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal
from llm_d_lens.storage.contracts import (
    LocalDiskSpec,
    StorageVolumeCreateRequest,
    StorageVolumeKind,
    StorageVolumePurpose,
)


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.create_storage_volume(
            StorageVolumeCreateRequest(
                cluster_id="<cluster-id>",
                name="<volume-name>",
                kind=StorageVolumeKind.LOCAL_DISK,
                capacity="500Gi",
                read_only=False,
                purposes=[StorageVolumePurpose.MODEL_CACHE],
                local_disk=LocalDiskSpec(host_path="/srv/model-cache"),
            )
        )
        print(volume.id, volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

The host path must be absolute and must not contain `..` segments. Names are
optional; leave the name blank to let Lens generate one.

### Create an NFS model cache volume

Use NFS when every node should share one network export. Send `nfs.server` and
`nfs.path` instead of `localDisk`.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "name": "<volume-name>",
    "kind": "nfs",
    "capacity": "1Ti",
    "readOnly": false,
    "purposes": ["model-cache"],
    "nfs": {"server": "<nfs-server>", "path": "/exports/models"}
  }' \
  "$LENS_URL/api/v1/storage/volumes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal
from llm_d_lens.storage.contracts import (
    NfsSpec,
    StorageVolumeCreateRequest,
    StorageVolumeKind,
    StorageVolumePurpose,
)


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.create_storage_volume(
            StorageVolumeCreateRequest(
                cluster_id="<cluster-id>",
                name="<volume-name>",
                kind=StorageVolumeKind.NFS,
                capacity="1Ti",
                read_only=False,
                purposes=[StorageVolumePurpose.MODEL_CACHE],
                nfs=NfsSpec(server="<nfs-server>", path="/exports/models"),
            )
        )
        print(volume.id, volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

For `dynamic-pvc`, use `dynamicPvc.storageClass`, `namespace`, and `accessMode`
instead, and do not add the `model-cache` purpose.

### Check provisioning and live claim state

A volume is usable only after `status` is `ready`. Read the record for drift and
usage metadata, then inspect the live PVC and PV objects.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>"

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volume-resource-status?volume_id=<volume-id>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.get_storage_volume("<volume-id>")
        resources = await lens.storage.get_storage_volume_resource_status(
            volume_ids=["<volume-id>"]
        )
        print(volume.status, volume.nodes_added)
        print(resources.items)


asyncio.run(main())
```

  </TabItem>
</Tabs>

Unknown ids in `volume_id` are ignored and repeated ids are deduplicated. A
failed volume cannot be repaired by this API; delete it and create a new one.

### Handle new nodes on a local-disk volume

When a local-disk volume reports new nodes in `nodesAdded`, copy its contents to
those nodes, then acknowledge the change to reset the baseline and clear the
warning.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>/acknowledge-nodes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.acknowledge_storage_volume_nodes("<volume-id>")
        print(volume.nodes_added)


asyncio.run(main())
```

  </TabItem>
</Tabs>

Acknowledge only after the content is present on every new node. Otherwise
deployments scheduled there can fail to find the model files.

### Import model files already on the volume

If you copied model files onto the volume outside Lens, scan the volume. Lens
imports the discovered models as Model Cache entries in the background. The
volume must be `ready`.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>/scan-models"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        result = await lens.storage.scan_storage_volume_models("<volume-id>")
        print(result.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

The call returns `202` and `{"status": "scanning"}`. Check Model Cache for the
imported entries after the scan completes.

### Delete a volume

Deleting marks the volume `deleting` immediately, returns `202`, and finishes
cleanup in the background. Pass `keep_model_files=true` to remove records only
and leave model files on the underlying disk or NFS export.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X DELETE -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>?keep_model_files=true"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.delete_storage_volume(
            "<volume-id>",
            keep_model_files=True,
        )
        print(volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

A volume referenced by a deployment execution is blocked with
`409 storage_volume_in_use`. Model Cache entries do not block deletion; they are
deleted with the volume unless `keep_model_files` is set.

## Endpoints

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |
| GET | `/api/v1/storage/volumes` | `storage:volume:read` | List volumes with optional filters. |
| GET | `/api/v1/storage/volumes/{volume_id}` | `storage:volume:read` | Read one volume and its drift metadata. |
| GET | `/api/v1/storage/volume-resource-status` | `storage:volume:read` | Read live PVC and PV status. |
| POST | `/api/v1/storage/volumes` | `storage:volume:create` | Create and provision a volume. |
| POST | `/api/v1/storage/volumes/{volume_id}/acknowledge-nodes` | `storage:volume:acknowledge` | Clear local-disk node drift. |
| POST | `/api/v1/storage/volumes/{volume_id}/scan-models` | `storage:volume:scan` | Import model files already on the volume. |
| DELETE | `/api/v1/storage/volumes/{volume_id}` | `storage:volume:delete` | Delete a volume and optionally its model files. |
| GET | `/api/v1/storage/storage-classes` | `storage:volume:read` | List StorageClasses for a cluster. |
| GET | `/api/v1/storage/nodes` | `storage:volume:read` | List cluster nodes and schedulability. |

Reads return `200`; create, scan, and delete return `202`.

## Errors and limits

- **`401` / `403`** — missing authentication or no access to the cluster.
  Maintainers manage volumes only on assigned clusters.
- **`404`** — the volume or cluster does not exist, or the cluster API cannot be
  reached for a storage-class or node listing.
- **`409 storage_volume_name_conflict`** — the name is already used on that
  cluster. Names are unique per cluster and compared case-insensitively.
- **`409 storage_volume_in_use`** — a deployment execution still references the
  volume. Remove it from those deployments first.
- **`409 storage_volume_not_ready`** — wait for `status: ready` before scanning.
- **`422`** — invalid request. Capacity must be an integer with `Gi`, `Mi`, or
  `Ti` (for example `500Gi`), the path must be absolute, and the spec must match
  the chosen kind.
- A `model-cache` purpose cannot be combined with `kind: dynamic-pvc`. Use
  `local-disk` or `nfs`, and mount the volume writable.
- Model-cache volumes must be writable. Set `readOnly` to `false`.
- Deleting a volume removes its Lens record and Kubernetes PVC/PV objects. The
  underlying files remain only when `keep_model_files=true`.
- Deletion is asynchronous. Poll the volume or list until it disappears.
