Use Administration to sign in, provision users, grant roles and cluster access, review or revoke sessions, and maintain Lens system settings such as the database connection and stored-secret master key. Use it when you need to give someone access, remove access, or confirm the security state of the Lens installation.

## Quick start

Sign in to obtain an access token and confirm the resulting principal.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -s -X POST http://127.0.0.1:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -c cookies.txt \
  -d '{"username":"<username>","password":"<password>"}'

curl -H "Authorization: Bearer $LENS_ACCESS_TOKEN" \
  http://127.0.0.1:3000/api/v1/auth/session
```

The login response returns `accessToken`, `tokenType`, `expiresIn`, and the current `principal`. Send the token as a Bearer token on later requests. The refresh cookie is stored in `cookies.txt`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        principal = await lens.administration.current_session()
        print(principal.user_id, principal.username, principal.permissions)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

## Common tasks

### 1. Create and list users

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:3000/api/v1/users \
  -d '{"username":"<username>","password":"<password>","displayName":"<display-name>","email":"<email>"}'

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/users?query=<search>&status=active"
```

Create returns `201 Created` with the user record. List returns direct `roles`, `groups`, and `inheritedRoles` for each user.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.auth.models import UserCreateRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        user = await lens.administration.create_user(
            UserCreateRequest(
                username="<username>",
                password="<password>",
                displayName="<display-name>",
                email="<email>",
            )
        )
        print(user.id, user.username)

        users = await lens.administration.list_users(query="<search>", status="active")
        for item in users:
            print(item.id, item.username, item.status)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 2. Update, disable, or reset a user

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X PATCH -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:3000/api/v1/users/<user-id> \
  -d '{"displayName":"<display-name>","email":"<email>","status":"disabled"}'

curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:3000/api/v1/users/<user-id>/password \
  -d '{"newPassword":"<new-password>"}'
```

Password reset returns `204 No Content`. Disabling a user keeps the record but blocks future sign-in.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.auth.models import ResetPasswordRequest, UserUpdateRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        user = await lens.administration.update_user(
            "<user-id>",
            UserUpdateRequest(
                displayName="<display-name>",
                email="<email>",
                status="disabled",
            ),
        )
        print(user.id, user.status)

        await lens.administration.reset_password(
            "<user-id>", ResetPasswordRequest(newPassword="<new-password>")
        )

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 3. Grant or revoke cluster access

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:3000/api/v1/clusters/<cluster-id>/access \
  -d '{"subjectType":"user","subjectId":"<user-id>","roleId":"<role-id>"}'

curl -H "Authorization: Bearer $LENS_TOKEN" \
  http://127.0.0.1:3000/api/v1/clusters/<cluster-id>/access

curl -X DELETE -H "Authorization: Bearer $LENS_TOKEN" \
  http://127.0.0.1:3000/api/v1/clusters/<cluster-id>/access/<binding-id>
```

Grant returns `201 Created` with the binding. Delete returns `204 No Content`. Use `subjectType: "group"` with a group id to grant a group.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.auth.models import AccessRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        binding = await lens.administration.grant_cluster_access(
            "<cluster-id>",
            AccessRequest(subjectType="user", subjectId="<user-id>", roleId="<role-id>"),
        )
        print(binding.id, binding.scope_cluster_id)

        items = await lens.administration.list_cluster_access("<cluster-id>")
        print(len(items))

        await lens.administration.revoke_cluster_access("<cluster-id>", binding.id)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 4. Create a role and set its permissions

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:3000/api/v1/roles \
  -d '{"name":"<role-name>","description":"<description>","permissions":["cluster:cluster:read"]}'

curl -X PUT -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:3000/api/v1/roles/<role-id>/permissions \
  -d '{"permissions":["cluster:cluster:read","deployment:run:read"]}'
```

Create returns `201 Created`. Setting permissions returns `204 No Content` and only works for custom roles.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.auth.models import RoleCreateRequest, RolePermissionsRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        role = await lens.administration.create_role(
            RoleCreateRequest(
                name="<role-name>",
                description="<description>",
                permissions=["cluster:cluster:read"],
            )
        )
        print(role.id, role.name)

        await lens.administration.set_role_permissions(
            role.id,
            RolePermissionsRequest(
                permissions=["cluster:cluster:read", "deployment:run:read"]
            ),
        )

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 5. List and revoke sessions

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/sessions?include_revoked=true"

curl -X DELETE -H "Authorization: Bearer $LENS_TOKEN" \
  http://127.0.0.1:3000/api/v1/sessions/<session-id>
```

Administrators with `session:session:revoke` see all sessions; other callers see only their own. Delete returns `204 No Content`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        sessions = await lens.administration.list_sessions(include_revoked=True)
        for session in sessions:
            print(session.id, session.user_id, session.revoked_at)

        await lens.administration.revoke_session("<session-id>")

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 6. Rotate the stored-secret master key

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  http://127.0.0.1:3000/api/v1/system/secret-key

curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  http://127.0.0.1:3000/api/v1/system/secret-key/rotate \
  -d '{"newKey":"<new-key>"}'
```

The status response returns `source`, `envLocked`, `fingerprint`, `oldKeyCount`, and `providerSecretCount`; it never returns the key. Rotate re-encrypts provider secrets and reports `rotatedSecrets`. Leave `newKey` empty to generate a key.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.auth.models import RotateSecretKeyRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        status = await lens.administration.get_secret_key_status()
        print(status.source, status.env_locked, status.fingerprint)

        rotated = await lens.administration.rotate_secret_key(
            RotateSecretKeyRequest(newKey="<new-key>")
        )
        print(rotated.fingerprint, rotated.rotated_secrets)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

## Endpoints

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |
| POST | `/api/v1/auth/login` | Public | Sign in; returns an access token and sets the refresh cookie. |
| POST | `/api/v1/auth/refresh` | Public + refresh cookie + CSRF | Get a new access token using the refresh cookie and CSRF header. |
| POST | `/api/v1/auth/logout` | Authenticated | Revoke the current session (`204`). |
| GET | `/api/v1/auth/session` | Authenticated | Read the current principal and permissions. |
| POST | `/api/v1/auth/password` | Authenticated | Change your own password (`204`). |
| GET | `/api/v1/auth/sessions` | Authenticated | List your own sessions. |
| GET | `/api/v1/sessions` | Authenticated | List sessions; admins see all sessions. |
| DELETE | `/api/v1/sessions/{session_id}` | Authenticated | Revoke a session (`204`). |
| GET | `/api/v1/users` | `user:user:read` | List users and inherited access. |
| POST | `/api/v1/users` | `user:user:create` | Create a user (`201`). |
| GET | `/api/v1/users/{user_id}` | `user:user:read` | Read one user. |
| PATCH | `/api/v1/users/{user_id}` | `user:user:update` | Update profile fields or status. |
| DELETE | `/api/v1/users/{user_id}` | `user:user:delete` | Delete a user (`204`). |
| POST | `/api/v1/users/{user_id}/password` | `user:user:reset-password` | Reset a password (`204`). |
| GET, POST | `/api/v1/users/{user_id}/role-bindings` | `role:binding:manage` | List or add user role bindings. |
| DELETE | `/api/v1/users/{user_id}/role-bindings/{binding_id}` | `role:binding:manage` | Remove a user role binding (`204`). |
| GET, POST | `/api/v1/groups/{group_id}/role-bindings` | `role:binding:manage` | List or add group role bindings. |
| DELETE | `/api/v1/groups/{group_id}/role-bindings/{binding_id}` | `role:binding:manage` | Remove a group role binding (`204`). |
| GET | `/api/v1/roles` | `role:role:read` | List roles and permissions. |
| POST | `/api/v1/roles` | `role:role:create` | Create a custom role (`201`). |
| GET | `/api/v1/roles/{role_id}` | `role:role:read` | Read one role. |
| PATCH | `/api/v1/roles/{role_id}` | `role:role:update` | Update a custom role. |
| DELETE | `/api/v1/roles/{role_id}` | `role:role:delete` | Delete a custom role (`204`). |
| PUT | `/api/v1/roles/{role_id}/permissions` | `role:role:update` | Replace a custom role's permissions (`204`). |
| GET, POST | `/api/v1/clusters/{cluster_id}/access` | `cluster:cluster:grant-access` | List or grant cluster access. |
| DELETE | `/api/v1/clusters/{cluster_id}/access/{binding_id}` | `cluster:cluster:grant-access` | Revoke cluster access (`204`). |
| GET | `/api/v1/system/database` | `system:database:read` | Read database setup status. |
| POST | `/api/v1/system/database` | `system:database:configure` | Configure the Lens database. |
| GET | `/api/v1/system/secret-key` | `system:secret:read` | Read master-key status. |
| POST | `/api/v1/system/secret-key/rotate` | `system:secret:manage` | Rotate the master key. |
| DELETE | `/api/v1/system/secret-key/old` | `system:secret:manage` | Drop retained fallback keys. |

## Errors / limits

- **401**: invalid credentials, an expired or revoked session, or a locked account. **403**: missing permission, another user's session, or no cluster access.
- **404**: unknown user, role, group, session, or binding. **409**: duplicate username, group, or role; protected built-in accounts; removing the last global admin; or disabling the built-in admin.
- **422**: invalid permission code, malformed request, or a password that is shorter than 12 characters, equals the username, or does not mix at least three character classes.
- Refresh uses the HttpOnly refresh cookie plus the `X-Prism-CSRF` header; Bearer requests do not need CSRF. Logout revokes the current session.
- Resource-scope role bindings only accept `scopeResourceType: "model_service_group"` with the built-in end-user role. The model and cluster must match, and the recipient needs inference permission in that cluster. Use the [scoped model access API](/api-reference/modules/model-services) for routine model grants.
- Master-key rotation is rejected when `LENS_SECRET_KEY` is environment-locked. Clearing old keys makes secrets still encrypted with them unreadable.
- Database setup: external mode requires `databaseUrl` with a scheme matching `engine`; embedded mode is always PostgreSQL. Connection errors return `422`; setup failures return `409`.
