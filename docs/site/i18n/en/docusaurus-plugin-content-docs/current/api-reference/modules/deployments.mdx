Lens Deploy runs an already-rendered deployment configuration on a Kubernetes cluster and tracks each run, case, and execution. Use this module to deploy a saved configuration artifact, start a Standard vLLM service, follow rollout status, connect to a ready endpoint, and clean up resources. Configuration preparation endpoints are included because they produce the artifact that a deployment consumes.

## Quick start

Start a Standard vLLM service. The model must be ready in the registered Model Cache volume.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -sX POST http://127.0.0.1:3000/api/v1/deployments/standard-vllm-runs \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3-8B",
    "deployment_name": "qwen3-standard",
    "cluster_session_id": "<cluster-session-id>",
    "replicas": 1,
    "tensor_parallel_size": 1,
    "storage_volume_id": "<model-cache-volume-id>"
  }'
```

```json
{
  "id": "<run-id>",
  "status": "queued",
  "cases": []
}
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.deploy.standard_kubernetes_service import StandardKubernetesServiceRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        run = await lens.deploy.create_standard_kubernetes_service_run(
            StandardKubernetesServiceRequest(
                model="Qwen/Qwen3-8B",
                deployment_name="qwen3-standard",
                cluster_session_id="<cluster-session-id>",
                replicas=1,
                tensor_parallel_size=1,
                storage_volume_id="<model-cache-volume-id>",
            )
        )
        print(run.id, run.status)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

## Common tasks

### Deploy a saved configuration

Start a run from one or more deployable configurations. A run with several cases uses `failure_policy` to decide whether later cases continue after a failure.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/deployments/runs`**

```json
{
  "configurations": [
    {
      "schema_version": "deployable-configuration.v1",
      "type": "baseline",
      "format": "helm",
      "provider_ref": "optimized-baseline",
      "checksum": "sha256:<checksum>",
      "content": {
        "model": {"name": "Qwen/Qwen3-8B"},
        "decode": {"replicaCount": 1, "tensorParallelSize": 1, "maxModelLen": 4096}
      },
      "provenance": {"deployment_name": "qwen3-guide"}
    }
  ],
  "failure_policy": "continue",
  "provenance": {"cluster_session_id": "<cluster-session-id>"}
}
```

Response fields: `id`, `status`, `cases[].id`, `cases[].status`, `cases[].execution_id`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.deploy.contracts import DeployableConfiguration, DeploymentRunCreateRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        run = await lens.deploy.create_run(
            DeploymentRunCreateRequest(
                configurations=[
                    DeployableConfiguration(
                        type="baseline",
                        format="helm",
                        provider_ref="optimized-baseline",
                        checksum="sha256:<checksum>",
                        content={
                            "model": {"name": "Qwen/Qwen3-8B"},
                            "decode": {
                                "replicaCount": 1,
                                "tensorParallelSize": 1,
                                "maxModelLen": 4096,
                            },
                        },
                        provenance={"deployment_name": "qwen3-guide"},
                    )
                ],
                provenance={"cluster_session_id": "<cluster-session-id>"},
            )
        )
        print(run.id, run.status)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### Find runs and executions

List runs newest first. Use `query` to search by run id, provider ref, deployment name, or namespace. Executions can be filtered by status and cluster.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`GET /api/v1/deployments/runs?query=qwen3`**

**`GET /api/v1/deployments/executions?status=ready&cluster_id=<cluster-id>`**

```json
{
  "items": [
    {
      "execution_id": "<execution-id>",
      "status": "ready",
      "cluster_id": "<cluster-id>",
      "namespace": "llmd-qwen3-standard",
      "endpoint": "http://qwen3-router.llmd-qwen3-standard.svc:8000"
    }
  ]
}
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.deploy.contracts import DeploymentStatus
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        runs = await lens.deploy.list_runs(query="qwen3")
        for run in runs:
            print(run.id, run.status)

        executions = await lens.deploy.list_executions(
            status=DeploymentStatus.READY,
            cluster_id="<cluster-id>",
        )
        for execution in executions.items:
            print(execution.execution_id, execution.endpoint)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### Connect to a ready endpoint and read logs

A `ready` execution has an in-cluster URL. Call the endpoint action to create or reuse a reachable forwarded URL before sending model traffic.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/deployments/executions/<execution-id>/endpoint`**

```json
{
  "success": true,
  "execution_id": "<execution-id>",
  "endpoint": "http://127.0.0.1:38000/v1",
  "namespace": "llmd-qwen3-standard",
  "service": "qwen3-router",
  "remote_port": 8000
}
```

Read pod logs with `GET /api/v1/deployments/executions/<execution-id>/pods/<pod-name>/logs?tail=200`. `tail` accepts 1-2000.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        execution = await lens.deploy.get_execution("<execution-id>")
        print(execution.status, execution.endpoint)

        resolved = await lens.deploy.connect_execution_endpoint("<execution-id>")
        print(resolved.endpoint)

        logs = await lens.deploy.get_execution_pod_logs(
            "<execution-id>", "<pod-name>", tail=200
        )
        print(logs.logs)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### Stop, clean, or delete a deployment

Stop or clean individual cases without deleting the run history. Delete a run only after it reaches a terminal state; deletion also cleans remaining cases.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/deployments/runs/<run-id>/cases/<case-id>/stop`**

**`POST /api/v1/deployments/runs/<run-id>/cases/<case-id>/clean`**

**`DELETE /api/v1/deployments/runs/<run-id>`** returns `204`.

```json
{
  "case": {"id": "<case-id>", "status": "stopped", "execution_id": "<execution-id>"},
  "execution": {"execution_id": "<execution-id>", "status": "rolled_back"},
  "deployment": {"run_id": "<run-id>", "case_id": "<case-id>", "status": "stopped"}
}
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.deploy.models import CleanCaseRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        stopped = await lens.deploy.stop_case("<run-id>", "<case-id>")
        print(stopped.case.status, stopped.execution.status)

        cleaned = await lens.deploy.clean_case(
            "<run-id>",
            "<case-id>",
            CleanCaseRequest(preserve_rendered_overlay=False),
        )
        print(cleaned.case.status)

        await lens.deploy.delete_run("<run-id>")

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### Clean orphan namespaces

An orphan namespace matches the deployment prefix but is not referenced by any Lens execution record. Names outside the prefix, or still referenced, are refused.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`GET /api/v1/deployments/orphans?cluster_id=<cluster-id>`**

**`POST /api/v1/deployments/orphans/clean`**

```json
{
  "clusterId": "<cluster-id>",
  "namespaces": ["llmd-optimized-baseline-1-1-20260918032423139529"]
}
```

Response: `cleaned` and `failed` namespace lists.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.deploy.models import CleanOrphansRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        orphans = await lens.deploy.list_orphan_namespaces("<cluster-id>")
        print(orphans.prefix, [item.name for item in orphans.items])

        result = await lens.deploy.clean_orphan_namespaces_route(
            CleanOrphansRequest(
                cluster_id="<cluster-id>",
                namespaces=[item.name for item in orphans.items],
            )
        )
        print(result.cleaned, result.failed)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### Scale a deployment execution

Change the live Prefill and Decode model-server replicas for a ready or failed execution. This changes Kubernetes replicas only; the saved configuration is unchanged. Deployments and DisaggregatedSets are supported. DisaggregatedSet scaling changes role replicas and never changes `spec.slices`.

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/deployments/executions/{execution_id}/scale`**

```json
{"prefill_replicas": 1, "decode_replicas": 2}
```

Only supplied roles are changed. Aggregated deployments use `decode_replicas`. Returns the updated execution with `scale`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.deploy.contracts import DeploymentScaleRequest
from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        context = await lens.deploy.scale_execution(
            "<execution-id>",
            DeploymentScaleRequest(decode_replicas=2),
        )
        print(context.scale)


asyncio.run(main())
```

  </TabItem>
</Tabs>

## Endpoints

### Deployment lifecycle

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/v1/deployments` | `deployment:run:read` | List runs (alias of `/runs`) |
| `GET` | `/api/v1/deployments/runs` | `deployment:run:read` | List or search runs |
| `POST` | `/api/v1/deployments/runs` | `deployment:run:create` | Start a run from configurations |
| `POST` | `/api/v1/deployments/standard-vllm-runs` | `deployment:run:create` | Start a Standard vLLM service |
| `GET` | `/api/v1/deployments/runs/{run_id}` | `deployment:run:read` | Get a run and its cases |
| `DELETE` | `/api/v1/deployments/runs/{run_id}` | `deployment:execution:delete` | Delete a terminal run and clean resources |
| `POST` | `/api/v1/deployments/runs/{run_id}/cancel` | `deployment:run:cancel` | Cancel an active run |
| `POST` | `/api/v1/deployments/runs/{run_id}/cluster-session` | `deployment:session:rebind` | Rebind an active cluster session |
| `GET` | `/api/v1/deployments/runs/{run_id}/cases/{case_id}` | `deployment:run:read` | Get a case with execution and summary |
| `GET` | `/api/v1/deployments/runs/{run_id}/cases/{case_id}/logs` | `deployment:run:read` | Read case orchestration logs |
| `POST` | `/api/v1/deployments/runs/{run_id}/cases/{case_id}/refresh` | `deployment:case:execute` | Re-read live case status |
| `POST` | `/api/v1/deployments/runs/{run_id}/cases/{case_id}/stop` | `deployment:case:execute` | Stop a case |
| `POST` | `/api/v1/deployments/runs/{run_id}/cases/{case_id}/restart` | `deployment:case:execute` | Restart a stopped or failed case |
| `POST` | `/api/v1/deployments/runs/{run_id}/cases/{case_id}/clean` | `deployment:case:execute` | Clean case runtime resources |
| `GET` | `/api/v1/deployments/executions` | `deployment:run:read` | List executions |
| `GET` | `/api/v1/deployments/executions/{execution_id}` | `deployment:run:read` | Get an execution |
| `PATCH` | `/api/v1/deployments/executions/{execution_id}` | `deployment:execution:update` | Edit display name or description |
| `DELETE` | `/api/v1/deployments/executions/{execution_id}` | `deployment:execution:delete` | Delete an execution record |
| `GET` | `/api/v1/deployments/executions/{execution_id}/pods` | `deployment:run:read` | List live pod status |
| `GET` | `/api/v1/deployments/executions/{execution_id}/pods/{pod_name}/logs` | `deployment:run:read` | Read pod logs |
| `POST` | `/api/v1/deployments/executions/{execution_id}/endpoint` | `deployment:execution:connect` | Create or reuse a forwarded endpoint |
| `GET` | `/api/v1/deployments/cluster/{cluster_id}` | `deployment:run:read` | List case records for a cluster |
| `GET` | `/api/v1/deployments/node-labels?cluster_id=<cluster-id>` | `deployment:run:create` | List node label keys and values |
| `GET` | `/api/v1/deployments/runtime-classes?cluster_id=<cluster-id>` | `deployment:run:read` | Discover RuntimeClasses |
| `GET` | `/api/v1/deployments/orphans?cluster_id=<cluster-id>` | `deployment:run:read` | List orphan namespaces |
| `POST` | `/api/v1/deployments/orphans/clean` | `deployment:execution:delete` | Delete orphan namespaces |

## Errors and limits

| Code | Meaning | What to do |
| --- | --- | --- |
| `401` / `403` | Not authenticated or missing permission | Check the token and the permission column above |
| `404` | Run, case, execution, or artifact not found | Re-list resources and confirm the id |
| `409` | Lifecycle conflict | Wait for a terminal state or inspect the current status |
| `422` | Invalid request or no namespace for pod logs | Fix the request fields |
| `502` | Port-forward or cleanup failed | Retry after checking the cluster |
| `503` | Cluster placement or RuntimeClass discovery failed | Check cluster access and retry |

- Active runs are `queued`, `running`, or `cancelling`. Cancel an active run before deleting it. The background reconciler treats only `cleaned` and `cancelled` runs as terminal, so a failed rollout can still recover.
- A stopped case keeps a `rolled_back` execution record. Cleaned cases remain in the run history.
- An execution must be `ready` and include an endpoint before you connect to it or benchmark it.
- Standard vLLM runs require a ready Model Cache entry and a registered Model Cache volume. `local-cache` and direct `pvc` storage are rejected.
- `placement_node_label` requires `placement_replicas: "same-node"` and must exist on the target cluster. LeaderWorkerSet cannot use `balanced` or `spread`.
- Deleting a run cleans its remaining cases first. Active runs return `409`; cancel them and wait for a terminal state.
- Case `clean` removes runtime resources but keeps the lifecycle record. `preserve_rendered_overlay=true` keeps rendered files.
- Case logs accept `limit` 1-1000 (default 200). Pod logs accept `tail` 1-2000.
