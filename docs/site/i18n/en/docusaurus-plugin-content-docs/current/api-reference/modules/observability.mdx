Use Observability to check or install the cluster Prometheus/Grafana stack, inspect accelerator and GPU driver health, manage monitoring for one deployment, and read profiling metrics. Use it when dashboards are missing, a driver or exporter needs attention, or you need to confirm which deployment executions are already monitored.

## Quick start

List the accelerator families and access modes Lens supports.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  http://127.0.0.1:3000/api/v1/monitoring/accelerators
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python

with LensLocal("<username>") as lens:
    response = lens.accelerator.list_accelerators()

        print(item.type, item.access_modes, item.default_namespace)
```

## Common tasks

### 1. Check the cluster monitoring stack and dashboard links

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/cluster-stack/status?namespace=llm-d-monitoring&cluster_id=<cluster-id>"

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/cluster-stack/links?namespace=llm-d-monitoring&cluster_id=<cluster-id>"
```

Read `status`, `message`, `release`, and `components[]`. The links response returns Prometheus and Grafana entries with `available` and `url`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        status = await lens.cluster_stack.status(
            namespace="llm-d-monitoring", cluster_id="<cluster-id>"
        )
        print(status.status, status.message)

        links = await lens.cluster_stack.links(
            namespace="llm-d-monitoring", cluster_id="<cluster-id>"
        )
        for link in links.links:
            print(link.kind, link.available, link.url)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 2. Preflight and install or reinstall the cluster stack

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  "http://127.0.0.1:3000/api/v1/monitoring/cluster-stack/installations/preflight?cluster_id=<cluster-id>" \
  -d '{"namespace":"llm-d-monitoring","mode":"central","enable_tls":false,"reinstall":false}'

curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <request-id>" \
  "http://127.0.0.1:3000/api/v1/monitoring/cluster-stack/installations?cluster_id=<cluster-id>" \
  -d '{"namespace":"llm-d-monitoring","mode":"central","enable_tls":false,"reinstall":false}'
```

Preflight returns `allowed`, blocking `checks`, and `warnings`. Install returns `202 Accepted` with an `operation_id`; poll the operation until its `status` is `succeeded` or `failed`. Reinstalling deletes stored metrics.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.monitoring.cluster_stack.models import ClusterStackInstallRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        request = ClusterStackInstallRequest(
            namespace="llm-d-monitoring",
            mode="central",
            enable_tls=False,
            reinstall=False,
        )
        preflight = await lens.cluster_stack.installation_preflight(
            request, cluster_id="<cluster-id>"
        )
        print(preflight.allowed, preflight.warnings)

        operation = await lens.cluster_stack.create_installation(
            request, idempotency_key="<request-id>", cluster_id="<cluster-id>"
        )
        print(operation.operation_id, operation.status)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 3. Check accelerator capabilities and status

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/accelerators/nvidia_gpu/status?namespace=dcgm-exporter&access_mode=dra&cluster_id=<cluster-id>"
```

Read `status`, `message`, `release`, `access_modes[]`, and `components[]`. Pass `dcgm-exporter` or your NVIDIA release namespace explicitly; the query default is `intel-xpumd`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

        status = await lens.accelerator.status(
            "nvidia_gpu",
            namespace="dcgm-exporter",
            access_mode="dra",
            cluster_id="<cluster-id>",
        )
        print(status.status, status.message)
        for mode in status.access_modes:
            print(mode.mode, mode.available, mode.detected)

    asyncio.run(main())
```

### 5. Manage deployment monitoring

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/deployments?cluster_id=<cluster-id>"

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/deployments/<execution-id>?cluster_id=<cluster-id>"

curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/deployments/<execution-id>/enable?cluster_id=<cluster-id>"
```

Valid actions are `install`, `enable`, `disable`, and `uninstall`. Read `status`, `enabled`, `servicemonitors`, and `podmonitors` from the response.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        listing = await lens.observability.list_deployment_monitoring("<cluster-id>")
        print(listing.cluster_id, listing.stack_ready, len(listing.items))

        status = await lens.observability.get_deployment_monitoring(
            "<execution-id>", "<cluster-id>"
        )
        print(status.status, status.enabled)

        result = await lens.observability.manage_deployment_monitoring(
            "<execution-id>", "enable", "<cluster-id>"
        )
        print(result.status, result.message)

    asyncio.run(main())
```

### 6. Inspect the GPU driver and profiling flow map

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/gpu-driver/status?access_mode=dra&cluster_id=<cluster-id>&hardware=intel-xpu"

curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  "http://127.0.0.1:3000/api/v1/monitoring/gpu-driver/install?cluster_id=<cluster-id>&hardware=intel-xpu" \
  -d '{"access_mode":"dra"}'

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "http://127.0.0.1:3000/api/v1/monitoring/profiling/flow-map?execution_id=<execution-id>&cluster_id=<cluster-id>"
```

The driver status returns `installed`, `ready`, and `message`. Driver install is asynchronous (`202`). The flow map returns `prometheus_reachable`, `components`, and `edges`.

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.monitoring.gpu_driver.models import GpuDriverInstallRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    async def main() -> None:
        status = await lens.gpu_driver.read_status(
            "dra", cluster_id="<cluster-id>", hardware="intel-xpu"
        )
        print(status.installed, status.ready, status.message)

        installed = await lens.gpu_driver.create_install(
            GpuDriverInstallRequest(access_mode="dra"),
            cluster_id="<cluster-id>",
            hardware="intel-xpu",
        )
        print(installed.applied, installed.message)

        flow = await lens.profiling.flow_map("<execution-id>", "<cluster-id>")
        print(flow.prometheus_reachable, len(flow.components), len(flow.edges))

    asyncio.run(main())
```

## Endpoints

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |
| GET | `/api/v1/monitoring/accelerators` | `monitoring:accelerator:read` | List accelerator capabilities. |
| GET | `/api/v1/monitoring/accelerators/{accelerator}/status` | `monitoring:accelerator:read` | Read accelerator health. |
| POST | `/api/v1/monitoring/accelerators/{accelerator}/installations/preflight` | `monitoring:accelerator:install` | Run install checks. |
| POST | `/api/v1/monitoring/accelerators/{accelerator}/installations` | `monitoring:accelerator:install` | Install components (`202`). |
| GET | `/api/v1/monitoring/accelerators/{accelerator}/operations/{operation_id}` | `monitoring:operation:read` | Read install progress. |
| GET | `/api/v1/monitoring/accelerators/{accelerator}/links` | `monitoring:accelerator:read` | Resolve dashboard links. |
| GET | `/api/v1/monitoring/cluster-stack/status` | `monitoring:cluster-stack:read` | Read cluster stack health. |
| POST | `/api/v1/monitoring/cluster-stack/installations/preflight` | `monitoring:cluster-stack:install` | Run install checks. |
| POST | `/api/v1/monitoring/cluster-stack/installations` | `monitoring:cluster-stack:install` | Install or reinstall (`202`). |
| GET | `/api/v1/monitoring/cluster-stack/operations/{operation_id}` | `monitoring:operation:read` | Read install progress. |
| GET | `/api/v1/monitoring/cluster-stack/links` | `monitoring:cluster-stack:read` | Resolve dashboard links. |
| GET | `/api/v1/monitoring/deployments` | `monitoring:deployment:read` | List deployment monitoring. |
| GET | `/api/v1/monitoring/deployments/{execution_id}` | `monitoring:deployment:read` | Read one deployment. |
| POST | `/api/v1/monitoring/deployments/{execution_id}/{action}` | `monitoring:deployment:action` | Install, enable, disable, or uninstall. |
| GET | `/api/v1/monitoring/gpu-driver/status` | `monitoring:gpu-driver:read` | Read driver readiness. |
| POST | `/api/v1/monitoring/gpu-driver/install` | `monitoring:gpu-driver:install` | Install the driver stack (`202`). |
| GET | `/api/v1/monitoring/profiling/flow-map` | `monitoring:profiling:read` | Read profiling flow metrics. |

## Errors / limits

- **401 / 403**: missing or expired authentication, missing monitoring permission, or no access to the target cluster.
- **404 `CLUSTER_NOT_FOUND`**: the cluster id is unknown. A deployment action outside `install`, `enable`, `disable`, or `uninstall` also returns `404`.
- **422**: invalid namespace, access mode, or installer request; the body accelerator must match the path.
- **502** with `CLUSTER_QUERY_FAILED`, `ACCELERATOR_QUERY_FAILED`, or `FLOW_MAP_FAILED`: the cluster or Prometheus query failed and is retryable.
- Install operations return `202`; poll the operation endpoint until `status` is `succeeded` or `failed`. Preflight never changes the cluster.
- **Reinstall deletes stored metrics.** Use it only when you intend to replace the monitoring stack.
- `POST /api/v1/monitoring/deployments/{execution_id}/install` and `enable` require a ready deployment. `GET /api/v1/monitoring/deployments` requires `cluster_id`; the flow map requires `execution_id`.
- Namespaces are limited to 63 characters and must be valid DNS labels. Accelerator ids come from registered hardware profiles, such as `intel_gpu` and `nvidia_gpu`.
- The accelerator status query defaults to `intel-xpumd` for every family; always pass the NVIDIA release namespace, usually `dcgm-exporter`.
