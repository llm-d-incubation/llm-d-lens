## Overview

Model Cache stores model weights on a registered storage volume so deployments
and benchmarks can load them without downloading at startup. Use this module to
seed a shared cache, inspect download progress and logs, retry failures, sync new
nodes, and remove cached models. The target volume must be `ready` and tagged with
the `model-cache` purpose. Downloads always use the Hugging Face token saved on
the cluster; the API does not accept a per-request token.

## Quick start

List cached models, optionally scoped to one cluster or volume.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries?cluster_id=<cluster-id>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

import asyncio

from llm_d_lens.sdk import LensLocal

## Common tasks

### Download a model from Hugging Face

Request a download into a ready model-cache volume. The call returns `202` with a
`pending` entry while the download Job starts in the background.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "storageVolumeId": "<volume-id>",
    "source": {
      "kind": "huggingface",
      "huggingface": {
        "repoId": "<org>/<model>",
        "revision": "main"
      }
    }
  }' \
  "$LENS_URL/api/v1/model-cache/entries"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.model_cache.contracts import (
    HuggingFaceSource,
    ModelCacheCreateRequest,
    ModelSource,
    ModelSourceKind,
)
from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.create_model_cache_entry(
            ModelCacheCreateRequest(
                cluster_id="<cluster-id>",
                storage_volume_id="<volume-id>",
                source=ModelSource(
                    kind=ModelSourceKind.HUGGINGFACE,
                    huggingface=HuggingFaceSource(
                        repo_id="<org>/<model>",
                        revision="main",
                    ),
                ),
            )
        )
        print(entry.id, entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

For a private or gated model, ask an administrator to save a Hugging Face token
with access to that model in the cluster settings. Public models download without
one. `tokenSource` is accepted for compatibility but ignored.

### Re-download a model already on the volume

A second request for the same model and revision returns
`409 model_cache_entry_exists` with the existing `entryId` and `entryStatus`.
Resend with `force: true` to download it again. Lens never creates a duplicate
entry.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "storageVolumeId": "<volume-id>",
    "source": {
      "kind": "huggingface",
      "huggingface": {"repoId": "<org>/<model>", "revision": "main"}
    },
    "force": true
  }' \
  "$LENS_URL/api/v1/model-cache/entries"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.model_cache.contracts import (
    HuggingFaceSource,
    ModelCacheCreateRequest,
    ModelSource,
    ModelSourceKind,
)
from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.create_model_cache_entry(
            ModelCacheCreateRequest(
                cluster_id="<cluster-id>",
                storage_volume_id="<volume-id>",
                source=ModelSource(
                    kind=ModelSourceKind.HUGGINGFACE,
                    huggingface=HuggingFaceSource(
                        repo_id="<org>/<model>",
                        revision="main",
                    ),
                ),
                force=True,
            )
        )
        print(entry.id, entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

A `ready` or `failed` entry is reset and downloaded again in place. A `pending` or
`downloading` entry is returned unchanged, so the confirmation joins the running
download instead of starting another one.

### Check download progress and read logs

Read the entry for per-node status, then fetch logs for a failed node.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>"

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>/logs?node=<node-name>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.get_model_cache_entry("<entry-id>")
        logs = await lens.model_cache.get_model_cache_entry_logs(
            "<entry-id>",
            node="<node-name>",
        )
        print(entry.status, entry.node_progress)
        print(logs.logs)


asyncio.run(main())
```

  </TabItem>
</Tabs>

`nodeProgress[].status` is `pending`, `downloading`, `ready`, or `failed`.
`failureDetail` contains the user-facing error when a node fails.

### Retry a failed download

Only entries in `failed` state can be retried. The call returns `202` and moves
the entry back to `pending`.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>/retry"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.retry_model_cache_entry("<entry-id>")
        print(entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

Retrying a `ready`, `pending`, `downloading`, or `deleting` entry returns
`409 model_cache_invalid_state`. Fix the underlying cause before retrying.

### Sync cached models to new nodes

New or replaced nodes do not have local-disk cache contents. Sync one entry or
all entries on a cluster; Lens queues downloads only for nodes that are missing
the model.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
# Sync every local-disk entry missing on new nodes.
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/sync-nodes?cluster_id=<cluster-id>"

# Or sync one entry.
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>/sync-nodes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        changed = await lens.model_cache.sync_model_cache_nodes(
            cluster_id="<cluster-id>"
        )
        entry = await lens.model_cache.sync_model_cache_entry_nodes("<entry-id>")
        print(len(changed.items), entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

Both calls return `202`. When new nodes need provisioning, the entry moves back to
`downloading`. NFS volumes do not need node sync because every node shares them.

### Delete a cached model

Delete removes the entry and, unless you keep files, schedules cleanup of the
cached files. The call returns `202`.

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X DELETE -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>?keep_files=true"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        result = await lens.model_cache.delete_model_cache_entry(
            "<entry-id>",
            keep_files=True,
        )
        print(result)


asyncio.run(main())
```

  </TabItem>
</Tabs>

Set `keep_files=false` to remove the files from the shared volume. An entry that
never reached `ready` can return a minimal `{"id": "<entry-id>", "status":
"deleted"}` response because there is nothing to clean up.

## Endpoints

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |
| GET | `/api/v1/model-cache/entries` | `model-cache:entry:read` | List entries, optionally by cluster or volume. |
| GET | `/api/v1/model-cache/entries/{entry_id}` | `model-cache:entry:read` | Read one entry, node progress, and pending nodes. |
| POST | `/api/v1/model-cache/entries` | `model-cache:entry:create` | Request a model download. |
| POST | `/api/v1/model-cache/entries/{entry_id}/retry` | `model-cache:entry:retry` | Retry a failed download. |
| POST | `/api/v1/model-cache/entries/sync-nodes` | `model-cache:entry:sync` | Sync every entry missing on new nodes. |
| POST | `/api/v1/model-cache/entries/{entry_id}/sync-nodes` | `model-cache:entry:sync` | Sync one entry to new nodes. |
| DELETE | `/api/v1/model-cache/entries/{entry_id}` | `model-cache:entry:delete` | Delete an entry and optionally its files. |
| GET | `/api/v1/model-cache/entries/{entry_id}/logs` | `model-cache:entry:read` | Read download or cleanup logs. |
| GET | `/api/v1/model-cache/huggingface/search` | `model-cache:entry:read` | Search Hugging Face repositories. |
| GET | `/api/v1/model-cache/huggingface/models/{repo_id}` | `model-cache:entry:read` | Read metadata and README for one repository. |

Reads return `200`; create, retry, sync, and delete return `202`.

## Errors and limits

- **`401` / `403`** — missing authentication or no access to the cluster.
- **`404`** — the entry does not exist, or the repository is not found on
  Hugging Face.
- **`409 model_cache_entry_exists`** — the volume already holds this model and
  revision. Resend with `force: true` after confirming.
- **`409 storage_volume_not_model_cache`** — the volume is not tagged with the
  `model-cache` purpose.
- **`409 storage_volume_not_ready`** — wait for the storage volume to become
  `ready`.
- **`409 model_cache_invalid_state`** — only `failed` entries can be retried.
- **`501 model_catalog_not_supported`** — model-catalog sources are not
  implemented. Send a Hugging Face `repoId` and `revision` instead.
- **`502 huggingface_hub_unavailable`** — Hugging Face is unreachable. Check
  network access and the cluster or host proxy.
- A download requires a ready `local-disk` or `nfs` volume. `dynamic-pvc` volumes
  cannot carry the `model-cache` purpose.
- Hugging Face environment variables are administrator-managed. Set credentials
  through the cluster's saved token, not deployment custom parameters.
- Sync applies to local-disk entries. NFS volumes are shared and need no per-node
  copy.
- Deletion is asynchronous. The entry moves to `deleting` until cleanup finishes.
