## Backend API

Cluster management routes come from `llm_d_lens/cluster/router.py`, `llm_d_lens/cluster/bootstrap/router.py`, and `llm_d_lens/cluster/sdk_discovery.py`.

### List clusters

List Lens-managed clusters and optionally include draft records that have not been finalized yet. The route also computes a `ready` flag per cluster by probing its Kubernetes API reachability.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/cluster/clusters`**

    Request: no request body.

    - `includeDrafts` (`boolean`, query, default `false`): include draft cluster records.

    Response: `ClustersResponse` with one `ClusterRecord` per visible cluster. `ready` validates cluster connectivity, including namespace-scoped (`edit`) kubeconfigs.

`hfTokenSecret` reports the namespace and name of the cluster's HF_TOKEN Secret, or `null` when the cluster has none. Only the location is returned; the token value stays on the target cluster and is never served by the API.

`ClusterRecord` also includes `vllmImage` (`string | null`, custom OCI image reference or `null` when using the selected hardware profile's `runtime_image` default) and monitoring configuration fields: `monitoringMode` (`"managed"` or `"existing"`), `monitoringNamespace` (default `"llm-d-monitoring"`), `prometheusUrl`, `grafanaUrl`, `prometheusNodePort`, and `grafanaNodePort`.

    ```json
    {
      "items": [
        {
          "id": "cluster-a",
          "name": "Primary cluster",
          "description": "Shared production GPU cluster",
          "createdAt": "2026-09-20T10:15:00Z",
          "ready": true,
          "proxy": {
            "mode": "custom",
            "httpProxy": "http://proxy.example:3128",
            "httpsProxy": "http://proxy.example:3128",
            "noProxy": "127.0.0.1,localhost,.svc"
          },
          "llmDRef": "v0.3.0",
          "llmDBenchmarkRef": "main",
          "llmDRepoPath": "/cache/llm-d/v0.3.0",
          "llmDBenchmarkRepoPath": "/cache/llm-d-benchmark/main",
          "hfTokenSecret": {
            "namespace": "llm-d-bench-storage-44395349",
            "name": "hf-token-c758ced0"
          },
          "draft": false
        }
      ]
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster import service

    async def main() -> None:
        clusters = service.list_clusters(include_drafts=True)
        ready_flags = await asyncio.gather(*(service.cluster_is_ready(cluster) for cluster in clusters))
        for cluster, ready in zip(clusters, ready_flags):
            print(cluster.id, cluster.name, ready)

    asyncio.run(main())
    ```
  </TabItem>
</Tabs>

### Get a cluster detail

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/cluster/clusters/{cluster_id}`**

    Returns `ClusterDetailResponse`:
    `{cluster, plan, planHash, planVersion, draftHfTokenSaved, executionOperations, executionCompletedAt, executionCompletedPlanHash}`.

    - `draftHfTokenSaved`: `boolean` indicating whether the caller has an
      encrypted draft Hugging Face token saved for this draft cluster (always
      `false` for active clusters or when saved by a different user; the token
      itself is never returned).
    - `executionOperations`: operation id → `user_done` / `admin_done` /
      `lens_done` / `failed`.
    - `executionCompletedAt`: timestamp of the most recent completed run, or
      `null`.
    - `executionCompletedPlanHash`: plan hash recorded by that run, or `null`.

    A non-null `executionCompletedAt` is not enough to treat an older draft as
    complete. If `executionCompletedPlanHash` is `null` or differs from the
    current `planHash`, re-check permissions and re-run the operation list.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster import execution, guard, registry

    cluster = registry.require_cluster("cluster-a")
    state = guard.load_plan(cluster.id)
    ledger = execution.operations(cluster.id)
    completed_at = execution.completed_at(cluster.id)
    completed_hash = execution.completed_plan_hash(cluster.id)
    current_hash = state.plan_hash if state else None
    print(ledger, completed_at, completed_hash, current_hash)
    ```
  </TabItem>
</Tabs>

### Register a cluster

Register a cluster from an uploaded kubeconfig file. The route accepts multipart form data, stores the cluster record, and returns the new cluster plus any created Lens session id.

llm-d component versions are fixed by the Lens stack profile (see [Get supported llm-d versions](#get-supported-llm-d-versions)); `llmDRef`, `llmDBenchmarkRef`, `routerVersion`, `gieVersion` and `ippVersion` are accepted for compatibility but ignored.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/clusters`**

    Request: multipart form-data, not JSON.

    - `name` (`string`, form): cluster display name.
    - `description` (`string`, form, optional): free-form description.
    - `file` (`file`, form): UTF-8 kubeconfig upload.
    - `proxy` (`string`, form, optional): JSON string matching `ProxyConfigDTO`.
    - `llmDRef` (`string`, form, optional): ignored — the `llm-d` version comes from the stack profile.
    - `llmDBenchmarkRef` (`string`, form, optional): ignored — the `llm-d-benchmark` version comes from the stack profile.
    - `gatewayProvider` (`string`, form, optional): shared Gateway provider (`envoy-ai-gateway` | `istio` | `agentgateway` | `gke`).
    - `gatewayPublicUrl` (`string`, form, optional): externally reachable host/IP clients use for the Gateway — Lens adds `http://` + the exposed port + `/v1`. Empty derives it from the exposed port and the cluster node.
    - `gatewayPort` (`integer`, form, optional): NodePort the shared Gateway is exposed on (30000–32767).
    - `gatewayAuthzHost` (`string`, form): the host/IP this cluster uses to reach Lens (required for providers with a Lens address hook: `envoy-ai-gateway`/`istio`/`agentgateway`). Pick from `GET /api/cluster/lens-hosts`; Lens adds its own serving port, and when empty Lens fills in this host's address.
    - `inotifyMaxUserInstances` (`integer`, form, default `8192`): per-uid inotify instance limit Lens applies to every node (`fs.inotify.max_user_instances`). Lift it above kind's 128 default on nodes running many pods.
    - `vllmImage` (`string`, form, optional): custom OCI container image reference (requiring `:tag` or `@sha256:` digest) for vLLM; when omitted, defaults to the selected hardware profile's `runtime_image`. Invalid references return `422 invalid_vllm_image`.
    - `draft` (`boolean`, form, optional): clusters are always created as drafts. Explicit `draft=false` returns `400 draft_creation_forbidden`.

    Example field values:

    ```json
    {
      "name": "Primary cluster",
      "description": "Shared production GPU cluster",
      "file": "<uploaded kubeconfig.yaml UTF-8 file>",
      "proxy": "{"mode":"custom","httpProxy":"http://proxy.example:3128","httpsProxy":"http://proxy.example:3128","noProxy":"127.0.0.1,localhost,.svc"}",
      "llmDRef": "v0.3.0",
      "llmDBenchmarkRef": "main",
      "draft": true
    }
    ```

    Response: `CreateClusterResponse`.

    ```json
    {
      "cluster": {
        "id": "cluster-a",
        "name": "Primary cluster",
        "description": "Shared production GPU cluster",
        "createdAt": "2026-09-23T09:00:00Z",
        "ready": false,
        "proxy": {
          "mode": "custom",
          "httpProxy": "http://proxy.example:3128",
          "httpsProxy": "http://proxy.example:3128",
          "noProxy": "127.0.0.1,localhost,.svc"
        },
        "llmDRef": "v0.3.0",
        "llmDBenchmarkRef": "main",
        "draft": true
      },
      "sessionId": "f4c15c0a-8c1f-4eb7-b4d7-ef83f22c2e9b"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster import service

    kubeconfig_text = """
    apiVersion: v1
    kind: Config
    clusters: []
    contexts: []
    current-context: ""
    users: []
    """.strip()

    cluster, session = service.create_cluster(
        "Primary cluster",
        "Shared production GPU cluster",
        kubeconfig_text,
        proxy_mode="custom",
        http_proxy="http://proxy.example:3128",
        https_proxy="http://proxy.example:3128",
        no_proxy="127.0.0.1,localhost,.svc",
        llm_d_ref="v0.3.0",
        llm_d_lensmark_ref="main",
        vllm_image="ghcr.io/example/vllm:v0.8.0",
        draft=True,
    )

    print(cluster.id, session.id)
    ```
  </TabItem>
</Tabs>

### Update a cluster

Patch a cluster's editable settings (name, description, proxy, gateway and inotify settings). The kubeconfig and draft state are not part of this patch contract; finalize with `POST /execution/complete`. Version fields (`llmDRef`, `llmDBenchmarkRef`, `routerVersion`, `gieVersion`, `ippVersion`) are server-managed from the stack profile and ignored on input.
Gateway namespace prefixes are scoped to the stable Lens cluster-registration
short ID. For registration `1234abcd`, the default becomes
`lens-gateway-1234abcd`; `gatewayNamespace: "custom"` resolves to
`custom-1234abcd`. Passing that suffixed value again does not append it twice.
Cluster responses report the effective namespace, including existing records
that previously used the shared `lens-gateway` default. This is also the behavior
of `service.update_cluster_settings(..., gateway_namespace="custom")`.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`PATCH /api/cluster/clusters/{cluster_id}`**

    Request body (`ClusterSettingsUpdateRequest`):

    - `name` (`string`, optional)
    - `description` (`string`, optional)
    - `proxy` (`ProxyConfigDTO`, optional)
    - `llmDRef` (`string`, optional)
    - `llmDBenchmarkRef` (`string`, optional)
    - `gatewayProvider` (`string`, optional): may be assigned once when the cluster has no provider yet; after that it is immutable and a different value returns `422 gateway_provider_immutable`.
    - `gatewayNamespace` (`string`, optional): namespace prefix, at most 63 characters; receives the registration's stable short-ID suffix.
    - `gatewayPort` (`integer`, optional)
    - `gatewayPublicUrl` (`string`, optional): externally reachable Gateway host/IP — Lens adds the exposed port; empty derives it.
    - `draft`: not accepted. Sending it returns `400 draft_update_forbidden`.
    - `gatewayAuthzHost` (`string`): the host/IP this cluster uses to reach Lens (required for providers with a Lens address hook; Lens adds its own serving port; empty fills in this host's address).
    - `inotifyMaxUserInstances` (`integer`, optional): per-uid inotify instance limit applied to every node (default `8192`).
    - `monitoringMode` (`string`, optional): `"managed"` or `"existing"`.
    - `monitoringNamespace` (`string`, optional): namespace for the monitoring stack (default `"llm-d-monitoring"`).
    - `prometheusUrl` (`string`, optional): explicit HTTP/HTTPS Prometheus URL; send `""` or `null` to clear.
    - `grafanaUrl` (`string`, optional): explicit HTTP/HTTPS Grafana URL; send `""` or `null` to clear.
    - `prometheusNodePort` (`integer`, optional): Prometheus NodePort (`30000`–`32767`); send `null` to clear.
    - `grafanaNodePort` (`integer`, optional): Grafana NodePort (`30000`–`32767`); send `null` to clear.
    - `monitoringHost` (`string`, optional): host/IP used to derive NodePort URLs when explicit URLs are unset; send `""` or `null` to clear.
    - `installAcceleratorExporters` (`boolean`, optional): whether to install accelerator metric exporters.
    - `vllmImage` (`string`, optional): custom OCI container image reference (requiring `:tag` or `@sha256:` digest) for vLLM; send `""` or `null` to reset to the selected hardware profile's `runtime_image` default. Invalid references return `422 invalid_vllm_image`; changing it during an active draft execution returns `409 execution_in_progress`.

    ```json
    {
      "name": "Primary cluster",
      "description": "Shared production GPU cluster",
      "proxy": {
        "mode": "custom",
        "httpProxy": "http://proxy.example:3128",
        "httpsProxy": "http://proxy.example:3128",
        "noProxy": "127.0.0.1,localhost,.svc"
      },
      "llmDRef": "v0.3.0",
      "llmDBenchmarkRef": "main"
    }
    ```

    Response: `CreateClusterResponse` with the updated record.

    ```json
    {
      "cluster": {
        "id": "cluster-a",
        "name": "Primary cluster",
        "description": "Shared production GPU cluster",
        "createdAt": "2026-09-23T09:00:00Z",
        "ready": true,
        "proxy": {
          "mode": "custom",
          "httpProxy": "http://proxy.example:3128",
          "httpsProxy": "http://proxy.example:3128",
          "noProxy": "127.0.0.1,localhost,.svc"
        },
        "llmDRef": "v0.3.0",
        "llmDBenchmarkRef": "main",
        "draft": false
      },
      "sessionId": null
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster import service

    cluster = service.update_cluster_settings(
        "cluster-a",
        name="Primary cluster",
        description="Shared production GPU cluster",
        proxy_mode="custom",

        no_proxy="127.0.0.1,localhost,.svc",
        llm_d_ref="v0.3.0",
        llm_d_lensmark_ref="main",
        gateway_authz_host="10.0.0.5",
        update_vllm_image=True,
        vllm_image="ghcr.io/example/vllm:v0.8.0",

    print(cluster.id, cluster.name)
    ```

### Rotate the cluster HF_TOKEN secret

Replace the Hugging Face token stored in the cluster's `HF_TOKEN` Secret, from the Edit cluster drawer. Unlike creation this applies the Secret, so an existing one is overwritten rather than rejected. `namespace` and `name` default to the coordinates already recorded on the cluster (`hfTokenSecret`), so rotating a token needs only the token; supplying different coordinates repoints the cluster at that Secret and creates it when absent.

Rotation rewrites only this cluster-level Secret. The namespace-local `llm-d-hf-token` copies that Deployments and Model Cache downloads derive at run time are re-derived on the next deployment or download, so workloads that are already running keep the previous token until they are recreated.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`PUT /api/cluster/clusters/{cluster_id}/hf-token-secret`**

    Request body (`HfTokenSecretUpdateRequest`):

    - `namespace` (`string`, optional): defaults to the cluster's recorded secret namespace.
    - `name` (`string`, optional): defaults to the cluster's recorded secret name.
    - `token` (`string`, required): new Hugging Face token; a blank value is rejected with `422 invalid_secret_token`.

    ```json
    {
      "token": "hf_rotatedTokenValue"
    }
    ```

    Response: `HfTokenSecretRef` with the coordinates that were written.

    ```json
    {
      "namespace": "llm-d-bench-storage-44395349",
      "name": "hf-token-c758ced0"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster import registry, service

    cluster = registry.get_cluster("cluster-a")
    # Rotate in place, reusing the coordinates recorded on the cluster.
    ref = asyncio.run(service.update_hf_token_secret(cluster, "hf_rotatedTokenValue"))
    print(ref["namespace"], ref["name"])

    # Or repoint the cluster at a different Secret.
    ref = asyncio.run(
        service.update_hf_token_secret(
            cluster,
            "hf_rotatedTokenValue",
            namespace="llm-d-bench-storage-44395349",
            name="hf-token-rotated",
        )
    )
    ```
  </TabItem>
</Tabs>

### Start cluster software downloads

Start downloading the `llm-d` and `llm-d-benchmark` revisions pinned by the Lens stack profile for a cluster. The handler schedules background downloads and immediately returns the current status snapshot; the request body is ignored.

Source checkouts are isolated by repository URL and resolved commit. Branch downloads refresh the remote ref; previously cached full commit SHAs can be reused offline. A per-source lock and atomic publication prevent concurrent requests from exposing incomplete checkouts or replacing an earlier snapshot.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/clusters/{cluster_id}/software-downloads`**

    Request body (`SoftwareDownloadRequest`): optional and ignored — the profile-pinned revisions are downloaded.

    ```json
    {}
    ```

    Response: `SoftwareDownloadStatusResponse`.

    ```json
    {
      "llmD": {
        "ref": "v0.2.0",
        "state": "downloading",
        "path": null,
        "error": null
      },
      "llmDBenchmark": {
        "ref": "main",
        "state": "downloading",
        "path": null,
        "error": null
      }
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster.router import _download_and_record
    from llm_d_lens.cluster import repo_downloads

    async def main() -> None:
        await _download_and_record("cluster-a", "llm-d", "v0.2.0")
        await _download_and_record("cluster-a", "llm-d-benchmark", "main")
        print(repo_downloads.get_status("cluster-a", "llm-d"))
        print(repo_downloads.get_status("cluster-a", "llm-d-benchmark"))

    asyncio.run(main())
    ```

### Read and save the provisioning plan

The plan is Lens state. Saving it never mutates the target cluster.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/cluster/clusters/{cluster_id}/plan`**

    Returns `{plan, planHash, planVersion}`.

    **`PUT /api/cluster/clusters/{cluster_id}/plan`**

    Accepts a `ProvisioningPlan` JSON body and optional `If-Match: <planHash>`.
    Draft-only; an active cluster returns `409 cluster_not_draft`. A stale
    `If-Match` returns `409 plan_conflict`. `plan.stack.vllmImage` (optional OCI container image reference requiring `:tag` or `@sha256:` digest) is preserved if omitted from `stack`, or cleared to `null` (the selected hardware profile's `runtime_image` default) when explicitly set to `null` or `""`. `plan.monitoring.autoDiscovered`
    tracks runtime-discovered endpoint fields (`prometheusUrl`, `grafanaUrl`,
    `prometheusNodePort`, `grafanaNodePort`, `host`) without changing `planHash`.
    When `tokenSource` is `create-secret`
    with an empty or default `llm-d-bench-storage*` namespace, the route
    automatically aligns `secretNamespace` onto the edit kubeconfig's
    SSAR-verified writable namespace (setting `secretNamespaceMode` to `existing`
    and aligning default `handoff.namespace`), while preserving explicit custom
    namespaces and `existing-secret:*` and falling back cleanly when Kubernetes
    is unreachable.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster import guard

    state = guard.load_plan("cluster-a")
    if state is not None:
        print(state.plan_hash, state.plan)
    ```

    `PUT /plan` is REST only: the route normalizes the plan, validates hardware
    profiles and namespace rules, stores it with optimistic concurrency, and
    mirrors derived columns on the cluster record. Call the endpoint instead of
    writing a plan directly.
  </TabItem>
</Tabs>

### Check operation permissions

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/clusters/{cluster_id}/permission-check`**

    Returns `OperationReport`:
    `{planHash, planVersion, plan, status, sufficient, userOperations, adminOperations, lensOperations, blockedOperations, missing, marker, remediation}`.
    `status` is `ready`, `admin_required`, or `blocked`. The check never mutates
    the target Kubernetes cluster; for an idle draft cluster with update
    permission, it may auto-align an eligible default `create-secret` /
    `handoff` namespace in Lens state onto the edit kubeconfig's writable
    namespace and return the updated `plan`, `planHash`, and `planVersion`.
    The check includes a cluster-wide wildcard SSAR probe (`*/*/*`) for remote
    overlay operations and applies reverse dependency closure promotion so any
    unfinished, promotable upstream dependencies of an Orchestration
    administrator operation are also promoted into `adminOperations`.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster import evaluator, guard, operations, registry

    cluster = registry.require_cluster("cluster-a")
    state = guard.require_plan(cluster.id, None)
    planned = operations.build_operations(state.plan, cluster_id=cluster.id)
    report = asyncio.run(
        evaluator.evaluate_operations(
            cluster.id,
            planned,
            plan_hash=state.plan_hash,
            handoff_namespace=state.plan.handoff.namespace,
        )
    )
    print(report.status, report.user_operations)
    ```
  </TabItem>
</Tabs>

### Generate the orchestration administrator operation script

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/clusters/{cluster_id}/permission-remediation`**

    Requires `cluster:cluster:update`. Returns
    `{filename, script, instructions, planHash, adminOperations, marker, warnings}`.
    Returns `409 admin_operations_not_required` for a ready plan and
    `503 admin_script_source_unavailable` when a pinned chart source cannot be
    resolved.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    `POST /permission-remediation` is REST only: it resolves pinned chart CRDs
    through the backend's filesystem cache, renders the script with the exact
    operation order, records an audit entry, and returns the downloadable file.
    Use the endpoint so the generated marker and plan hash match the cluster's
    stored plan.

### Delete a cluster

Delete a Lens-managed cluster record and clean up related state. This should only be used when the cluster should be removed from Lens entirely.

Deletion uses a two-phase cleanup flow so namespace-scoped `edit` kubeconfigs do not get stuck when cluster-scoped or cross-namespace cleanup requires orchestration administrator privileges:

- **Step A (best-effort with stored kubeconfig)**: Lens removes the resources it is permitted to delete in the cluster, including the registration's isolated Gateway namespace (normally `lens-gateway-<cluster-id>`) or, for shared/existing Gateway namespaces (`namespaceMode: "existing"` or a non-deletable namespace), only Lens-owned Gateway resources (`gateway.gateway.networking.k8s.io/<gateway_name>` and best-effort provider/authz/`lens-node-sysctl` companions). For `HF_TOKEN` secrets, `existing-secret:*` and `existing`-mode secret namespaces are never deleted; `create-secret` resources with a `create`-mode namespace are deleted as `hf-secret.namespace` when not protected or shared, post-creation rotated HF Secrets are deleted at the Secret level only, and legacy plan-less external secret namespaces are deleted only when Lens-owned or empty of non-injected objects. Protected namespaces (`default`, `kube-system`, `kube-public`, `kube-node-lease`, `istio-system`, `envoy-gateway-system`, `envoy-ai-gateway-system`, `agentgateway-system`), `lens-gateway`, `llm-d-bench-storage`, and the kubeconfig/handoff namespace are never deleted. For a draft cluster, attached Storage volumes are also removed together with their `PersistentVolumeClaim` and `PersistentVolume` objects (underlying NFS or host-path files are kept because `Retain` is used).
- **Step B (orchestration administrator handoff)**: If any required cleanup operations fail with `403` / RBAC errors, Lens checks for a completion marker `ConfigMap` (`lens-admin-cleanup-<cluster_id>`) in `marker.namespace` matching the expected `clusterId`, `status: "completed"`, `cleanupDigest`, and all unverified operations. If not yet completed, Lens returns `409` with code `cluster_admin_cleanup_required` (RFC-7807) containing the idempotent `script`, `cleanupDigest`, `operations`, `completedOperations`, `marker`, `canVerifyMarker`, and `confirmRequired` so an orchestration administrator can run the script and the user can retry deletion.
- **Offline / unreachable fallback**: If the cluster is unreachable during deletion, Lens returns `502` with code `cluster_gateway_cleanup_failed` and includes the idempotent `script` and `cleanupDigest` in the error payload. Passing `confirmAdminCleanup=true` acknowledges manual cleanup and removes the Lens registration record.

A non-draft cluster that still has available deployments or Storage volumes is always rejected with `409` (`cluster_has_available_deployments` or `cluster_has_storage_volumes`), even when `confirmAdminCleanup=true`.

For clusters where a temporary orchestration administrator kubeconfig can be supplied directly, `POST /api/cluster/clusters/{cluster_id}/cleanup` remains available as an alternative.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`DELETE /api/cluster/clusters/{cluster_id}`**

    Request: no request body.

    - `cluster_id` (`string`, path): target cluster id.
    - `confirmAdminCleanup` (`boolean`, query, default `false`): when `true`, confirms that an orchestration administrator has already run the cleanup script when marker verification is unavailable (`canVerifyMarker: false`) or the cluster is unreachable (`502`).

    Response: `204 No Content`. This endpoint does not return a JSON body.

    Failure:
    - `409 cluster_has_available_deployments` or `409 cluster_has_storage_volumes` if a finalized cluster still has those resources.
    - `409 cluster_admin_cleanup_required` if required remote cleanup needs orchestration administrator privileges (includes `script`, `cleanupDigest`, `operations`, `completedOperations`, `marker`, `canVerifyMarker`, and `confirmRequired`).
    - `502 cluster_gateway_cleanup_failed` if the cluster is unreachable or required cleanup failed without `confirmAdminCleanup=true` (includes `script` and `cleanupDigest` when available).
  </TabItem>
  <TabItem value="python-api" label="Python API">
    `service.delete_cluster()` raises `ClusterOverviewError` with the same status and code when required cleanup fails.


    ```json
      "nodes": [{ "host": "10.0.0.10-12", "port": 22 }]
    ```

    Each response item contains `host`, `port`, `algorithm`, and `fingerprint`; unreachable hosts contain an `error` instead.

    ```json
    {
      "items": [
        { "host": "10.0.0.10", "port": 22, "algorithm": "ssh-ed25519", "fingerprint": "SHA256:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA" },
        { "host": "10.0.0.11", "port": 22, "algorithm": "ssh-ed25519", "fingerprint": "SHA256:BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB" },
        { "host": "10.0.0.12", "port": 22, "error": "Connection timed out" }
      ]
    }
    ```

### Start a bootstrap job

Start a long-running Kubespray-based cluster bootstrap job after preflight succeeds. The response returns the bootstrap job id immediately while the real provisioning continues in the background.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/bootstrap`**

    Request body (`BootstrapCreateRequest`):

    - `nodes` (`BootstrapNodeInput[]`): the nodes to provision.
    - `hostKeys` (`BootstrapHostKeyPin[]`): the exact confirmed fingerprint for every expanded `host:port`.
    - `proxy` (`BootstrapProxyConfig`, optional): target-node proxy configuration.

    ```json
    {
      "nodes": [
        {
          "host": "10.0.0.1",
          "port": 22,
          "roles": [
            "control-plane"
          ],
          "username": "root"
        },
        {
          "host": "10.0.0.2",
          "port": 22,
          "roles": [
            "worker"
          ],
          "username": "root"
        }
      ],
      "hostKeys": [
        { "host": "10.0.0.1", "port": 22, "fingerprint": "SHA256:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA" },
        { "host": "10.0.0.2", "port": 22, "fingerprint": "SHA256:BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB" }
      ],
      "proxy": {
        "mode": "custom",
        "httpProxy": "http://proxy.example:3128",
        "httpsProxy": "http://proxy.example:3128",
        "noProxy": "127.0.0.1,localhost,.svc"
      }
    }
    ```

    Response: `BootstrapCreateResponse`.

    ```json
    {
      "bootstrapId": "bootstrap-5b7fd3a81290"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster.bootstrap.dto import BootstrapHostKeyPin, BootstrapNodeInput, BootstrapProxyConfig
    from llm_d_lens.cluster.bootstrap import service

    async def main() -> None:
      pins = [
        BootstrapHostKeyPin(host="10.0.0.1", port=22, fingerprint="SHA256:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA"),
        BootstrapHostKeyPin(host="10.0.0.2", port=22, fingerprint="SHA256:BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB"),
      ]
        job = service.create_job(
            [
                BootstrapNodeInput(host="10.0.0.1", roles=["control-plane"]),
                BootstrapNodeInput(host="10.0.0.2", roles=["worker"]),
            ],
            pins,
            proxy=BootstrapProxyConfig(
                mode="custom",
                httpProxy="http://proxy.example:3128",
                httpsProxy="http://proxy.example:3128",
                noProxy="127.0.0.1,localhost,.svc",
            ),
        )
        await service.run_bootstrap_job(job.id)
        print(job.id)

    asyncio.run(main())
    ```
  </TabItem>
</Tabs>

### Get bootstrap status

    ```json
kind: Config
clusters: []
contexts: []
users: []
"
    ```

### Cancel a bootstrap job

Cancel a running bootstrap job so it stops provisioning and does not continue. This endpoint returns immediately once cancellation has been requested.

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/bootstrap/{bootstrap_id}/cancel`**

    Request: no request body.

    - `bootstrap_id` (`string`, path): bootstrap job id.

    Response: `204 No Content`. This endpoint does not return a JSON body.
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster.bootstrap import service

    service.cancel_job("bootstrap-5b7fd3a81290")
    ```
  </TabItem>
</Tabs>
