## 在线安装

在 Ubuntu 22.04 LTS 或更新版本（x86_64）上，下载并执行在线安装脚本，
无需克隆仓库。以运行服务的用户执行，不要使用 `sudo bash`；
只有安装缺失的系统软件包时才会请求 sudo。
下载入口需要 Bash、`curl` 或 `wget`、CA 证书和 `python3`，缺失时可运行
`sudo apt-get install curl ca-certificates python3`。

将 `VERSION` 设为 `main` 安装开发版，或替换为实际发布 tag（如 `vX.Y.Z`）。
仅支持包含在线安装脚本的 tag。

使用 **curl**：

```bash
VERSION=main && curl -fsSL "https://raw.githubusercontent.com/llm-d-incubation/llm-d-lens/${VERSION}/scripts/LensInstaller-Ubuntu-x86_64-online.sh" | bash
```

或使用 **wget**：

```bash
VERSION=main && wget -qO- "https://raw.githubusercontent.com/llm-d-incubation/llm-d-lens/${VERSION}/scripts/LensInstaller-Ubuntu-x86_64-online.sh" | bash
```

安装器从 `/dev/tty` 读取交互输入。源码包验证成功后，会将脚本保存为当前目录中的
`LensInstaller-Ubuntu-x86_64-online.<unique-id>.sh` 并打印路径，不覆盖已有文件。
请在可写目录中运行。脚本主体完整接收后才会执行。
自动化 Bash 环境建议启用 `set -o pipefail`，让下载器失败也能使整个管道返回非零状态。

交互模式会询问安装目录（默认 `$HOME/llm-d-lens`）和
统一应用/API 端口（默认 `3000`）；按回车即可接受每个默认值。
安装脚本下载固定到 commit 的源码包，然后配置 Node、Python 3.11+、
虚拟环境、PostgreSQL、应用构建和 TLS。缺少兼容 Python 时，使用固定版本的
uv 将独立的 Python 3.12 安装到安装目录的 `.tools/`，不替换系统 Python。
仅接受新目录或空目录，不覆盖已有安装。

### 版本选择

脚本内置源码版本，不需要也不接受版本参数。`main` 安装执行时的开发分支，
发布版本的脚本安装对应 tag。下载前会将版本解析成确定的 commit SHA；
安装目录内的 `.lens-version.json` 记录版本、SHA 和安装时间。
固定源码不代表所有间接 npm/Python 依赖都已锁定。

### 网络与失败处理

需允许访问 `raw.githubusercontent.com`、`api.github.com`、`codeload.github.com`、
Node.js 和软件包仓库，以及 Ubuntu 软件源；安装独立 Python 还需下载 GitHub release
资源。脚本继承 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`，不会关闭证书校验。
如果 sudo 过滤了代理变量，请单独配置 apt 代理。

日志以私有权限保存在 `$LENS_LOG_DIR`（默认 `~/.local/state/lens/logs/`）。
日志可能包含安装器生成的数据库凭据，请勿公开。临时下载放在
`$LENS_SCRATCH_DIR`，退出时清理。下载及源码包检查完成前不会修改安装目录；
后续安装失败可能留下部分文件，这些文件会保留用于诊断，不会自动升级、
回滚或删除安装目录。网络失败或 GitHub API 限流会明确报错，不会切换版本。

无终端的脚本化或 CI 安装，请将命令末尾的 `| bash` 替换为
`| bash -s -- --silent`。

其他安装选项可追加在 `--silent` 后面。已保存的脚本仍可通过
`bash <saved-script-path> [options]` 直接运行。

常用选项：

| 选项 | 作用 |
| --- | --- |
| `--install-dir DIR` | 安装位置（默认 `$HOME/llm-d-lens`）。 |
| `--app-port PORT` | Web 应用/API 端口（默认 `3000`）。 |
| `--backend-port PORT` | `--app-port` 的旧版别名；两者配置同一个监听端口。 |
| `--no-https` | 提供纯 HTTP 服务，而不是自动 HTTPS（自签名证书）。 |
| `--no-start` | 安装但不启动服务。 |
| `--db-mode embedded\|external` | 使用内置数据库或外部数据库。 |
| `-h, --help` | 显示全部选项。 |

启用自动 HTTPS 时，安装器生成的 `lensctl.sh` 与本地源码启动器还会为模型 Gateway 的内部 `lens-authz` 链路启用不校验证书的 TLS（`LENS_MODEL_GATEWAY_AUTHZ_TLS_INSECURE=1`），因为集群不信任自签名证书。这是开发便利选项，会关闭该链路的证书校验，网络攻击者可能冒充 authz 并伪造身份。只能用于可信网络。安全警告和关闭方法见[环境变量](/environment-variables)。

## 管理安装

安装脚本会在安装目录中写入 `lensctl.sh`：

```bash
"$HOME/llm-d-lens/lensctl.sh" start
"$HOME/llm-d-lens/lensctl.sh" status
"$HOME/llm-d-lens/lensctl.sh" stop
```

卸载请运行 `"$HOME/llm-d-lens/lensctl.sh" uninstall`，默认保留数据。
使用 `--purge` 可删除数据，或使用 `--keep-data` 跳过数据保留提示。
内嵌数据库通过 `--keep-db` / `--purge-db` 单独控制。
在线安装入口本身不接受卸载参数。

如果你要升级现有安装而不是全新安装，请参阅
[升级指南](/upgrade)。

## 从源码安装与运行

在仓库根目录使用本地源码启动器，而不是 Ubuntu 安装程序生成的打包部署：

```bash
hack/lens-local.sh start
hack/lens-local.sh status
```

启动器准备 Node.js、npm 依赖和 Python 环境，然后在端口 `5173` 运行源码前端、
在 `3000` 运行统一 Python API。这种方式通过 Vite 运行源码，并不替代下方的生产构建命令。
`npm run dev` 和 `npm run dev:web` 都会启动这两个开发进程。
执行 `npm run build` 后，`npm start` 通过一个 Python 进程、一个端口提供构建后的前端、
API 和 MCP。Node 用于前端构建，不参与生产请求处理。

`hack/lens-local.sh start` 和 `restart` 会在更改服务之前重新生成并验证复用地图。
无效的注册项会阻止启动，但不会停止已有服务；待处理的用户决策只会提示警告，
不会被自动解决。若需限定部署节点，传入 `--target-node NODE` 和可选的
`--kubeconfig FILE`，或者设置 `TARGET_NODE` 与 `KUBECONFIG`；
不需要目标节点专用配置文件。预检查要求和各个子命令参见 [CLI 参考](/cli-reference)。

## 可选的 BLIS 精确估算运行时

在线安装器和后端 Python 依赖默认不安装 BLIS，AISimulate 仍为默认工具。
BLIS 需要在兼容的 POSIX 主机上单独显式安装，使用与后端相同的服务用户及
`LENS_CACHE_DIR`。API 请求不会下载、构建或安装运行时。

请向管理员获取经过审计的二进制和完整输入树。此流程不提供公共二进制下载，
也不会构建任意源码版本。仅接受实验性的 `762f1605` 基线，其二进制 SHA-256 必须为
`c701b5577e06009157c268e19532c0d598576288c40d9f4a95ce515edc529d16`。
推荐输入树包含 `blis-catalog` 提交
`b5550f750cb51571498577fbdc1c68f78cda67db` 中的全部 42 个模型条目，catalog 摘要为
`ce4886a01c27882c2481aea2f3cac13758d2fc3e3661b71b7ca25ee4dd985923`，完整输入树摘要为
`98cf41670c054d2c98a666381dd57826862ea64a7e8e2dd611e34af9fbce2fd1`。
原来的 24 模型输入树仍兼容，其完整输入树摘要为
`28cc378251abb2bd6be3035bee5ac2c29c1cf42ee2e45afd57a297cfee88ee3a`。
两套配置保留相同的二进制和 registry 锁。安装仅识别这两套已知输入锁，
不会信任调用者自行提供的摘要。
即使源码提交相同，摘要不同的构建也不会自动获准。

在已安装的 Lens 目录中执行：

```bash
.venv/bin/python -m llm_d_lens.estimate_tools.blis.install install \
	--binary /absolute/path/to/audited/blis \
	--inputs /absolute/path/to/audited/inputs
.venv/bin/python -m llm_d_lens.estimate_tools.blis.install check
```

安装命令校验摘要，将产物复制到私有暂存目录，真实执行已确认的八请求基线，
验证结果后发布到 `$LENS_CACHE_DIR/estimate-tools/managed-blis-762f1605`
（默认缓存根目录为 `~/.cache/lens`）。验证失败会清理暂存目录，已有安装不会被覆盖。
复制的输入及安装记录属于可选缓存，不写入数据库。安装后重启后端：
源码用户执行 `hack/lens-local.sh restart backend`，打包安装用户通过 `lensctl.sh`
停止并启动应用。运行时发现在进程内缓存。

也可在后端服务环境中同时设置 `LENS_BLIS_BINARY` 和 `LENS_BLIS_INPUTS`，
指向管理员管理的绝对路径，然后重启服务。这两个路径优先于受管缓存，
仍须满足相同摘要锁。`PATH` 和 `LENS_TEST_BLIS_*` 都不会启用产品执行。
禁用时，停止后端，取消两个显式路径，将受管运行时目录移出上述发现位置，再启动后端。
移动文件不会自动改变正在运行的进程。

升级已有安装时，先获取并验证完整目录工件，再停止后端，将旧受管目录移到发现位置之外备份。
安装并检查新工件后启动后端，保留备份以便回滚；不要向已安装目录合并文件或修改安装记录。
已保存的显式运行时配置 ID 不会自动改写为新的完整目录配置 ID。

模型名称必须匹配 catalog ID 或声明的完整来源仓库名，忽略大小写。
完整目录指该固定版本的全部条目，不代表所有 Hugging Face 模型；其中仍没有
`Qwen/Qwen3-8B`。目录中存在条目不等于所有硬件、拓扑组合或预测准确性均已认证，
仍须通过原生构建和逐请求校验。

固定版本的完整硬件目录包含 `a100-80`、`a100-sxm`、`b200`、`b300`、`gb200-nvl72`、
`gb300`、`h100`、`h200` 和 `l40s`。`a100-80` 明确是 A100 SXM 的别名，
`h100` 描述 H100 SXM5，均不是 PCIe 条目。因此，此 BLIS 配置仍不支持识别到的
A100/H100 PCIe 设备；不要为了通过检查而选择 SXM 身份。设备名称必须匹配 catalog ID
或运行时明确批准的别名，忽略大小写并将空白和下划线视作连字符。固定配置将
`h100 sxm`、`h100_sxm` 和 `h100-sxm` 映射到 `h100`，但不会映射 H100 PCIe。
任意厂商产品标签不会自动等同于 catalog ID。

配置页的 **Exact estimates** 可选择 AISimulate、BLIS 或两者。
仅选 AISimulate 时展示原生平均 token 长度与可读的加速器选项，通过硬件 profile 在内部映射。
BLIS 增加显式工作负载、负载目标、前缀、运行参数和运行时声明。双选时区分公共输入与
BLIS 控件，并明确报告 AISimulate 无法表达的语义，不会丢弃设置或改写负载来强行对齐工具。
连接的集群信息会预填无歧义的加速器型号和已知的均匀节点容量。未知或异构容量保持为空。
保存的输入和用户手动修改优先于后续发现结果。这些仍是声明的仿真输入，不代表资源预留，
也不代表已匹配模拟器。引擎版本是仿真声明值，不是检测到的集群版本。选择 BLIS 且版本为空时，
面板会从引擎类型匹配、唯一可用的受管运行时已确认输入中预填版本，不覆盖已保存或手动编辑的
版本（包括手动清空）。
请针对显式拓扑和负载检查支持情况。
结果分别保留执行状态、约束判断、指标定义及来源。取消会中止请求，编辑输入会清除旧结果。
工具选择随配置保存；可选保存声明的仿真输入，但必须通过渲染后清单的一致性校验。

面板可查看运行时能力和已确认的参考配置。
已确认基线使用固定 128 个输入 token、32 个输出 token、每秒 2 个请求、
种子 42、8 个请求、60 秒仿真时间窗和 30 秒请求截止时间，无共享前缀。
这是安装参考用例，不是请求白名单。聚合估算可使用锁定目录中的其他模型和硬件，
但必须具有匹配的精度/量化、互连、拓扑、vLLM `0.32.0` 设置、固定长度负载和显式运行控制。
模型来源仓库别名必须由目录声明。多节点估算必须显式提供目录互连；
`h100_pcie` 等缺失硬件变体仍不受支持，不会用 `h100` SXM 近似替代。
原生均值负载不会被静默转换。映射与能力规则见
[估算 API](/api-reference/modules/deployments)。

运行时可用不代表请求受支持，编译支持也不代表精确输入执行证据或预测准确度验证。
安装仍只验证参考用例，而不是每个目录组合。
P/D、搜索、容量估算、回放和合并排名均未启用。不支持的输入按工具分别报告，
不会回退到 AISimulate。现有 AISimulate 推荐接口及 Agentic 推荐行为保持不变。

## 文档站点

本站点使用 [Docusaurus](https://docusaurus.io/) 构建。可在本地预览，
并支持热重载：

```bash
npm run docs:dev
```

校验配置和页面路径：

```bash
npm run docs:check
```

Python MCP 目录根据当前 API schema 和随包提供的特殊工具定义生成。
本地及安装后的启动器会在启动服务前校验目录；非预期跳过的操作会阻止启动。
运行时不依赖生成的 Node 文件。
