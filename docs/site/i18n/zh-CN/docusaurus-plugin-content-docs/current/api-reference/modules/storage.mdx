## 概述

存储模块注册 Lens 挂载到模型缓存下载和部署中的本地磁盘、NFS 导出或动态 PVC。在下载缓存模型或部署需要共享存储的模型之前，先在这里创建卷。卷可以标记 `model-cache` 用途，从而可在模型缓存中选择；该用途要求使用 `local-disk` 或 `nfs`，而不是 `dynamic-pvc`。

## 快速开始

列出你可以使用的存储卷，可选地限定到一个集群。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes?cluster_id=<cluster-id>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        result = await lens.storage.list_storage_volumes(cluster_id="<cluster-id>")
        for volume in result.items:
            print(volume.id, volume.name, volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

供应在后台进行，`status` 会从 `pending` 变为 `ready`（或 `failed`）。

## 常见任务

### 创建本地磁盘模型缓存卷

当每个节点上准备相同的 host path 时，使用 `local-disk`。卷必须可写才能存放模型下载。创建返回 `202`，并在配置 Kubernetes 对象期间返回 `pending` 状态的记录。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "name": "<volume-name>",
    "kind": "local-disk",
    "capacity": "500Gi",
    "readOnly": false,
    "purposes": ["model-cache"],
    "localDisk": {"hostPath": "/srv/model-cache"}
  }' \
  "$LENS_URL/api/v1/storage/volumes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal
from llm_d_lens.storage.contracts import (
    LocalDiskSpec,
    StorageVolumeCreateRequest,
    StorageVolumeKind,
    StorageVolumePurpose,
)


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.create_storage_volume(
            StorageVolumeCreateRequest(
                cluster_id="<cluster-id>",
                name="<volume-name>",
                kind=StorageVolumeKind.LOCAL_DISK,
                capacity="500Gi",
                read_only=False,
                purposes=[StorageVolumePurpose.MODEL_CACHE],
                local_disk=LocalDiskSpec(host_path="/srv/model-cache"),
            )
        )
        print(volume.id, volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

host path 必须是绝对路径，且不能包含 `..` 段。名称是可选的；留空时 Lens 会自动生成一个名称。

### 创建 NFS 模型缓存卷

当所有节点应共享同一个网络导出时，使用 NFS。发送 `nfs.server` 和 `nfs.path`，而不是 `localDisk`。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "name": "<volume-name>",
    "kind": "nfs",
    "capacity": "1Ti",
    "readOnly": false,
    "purposes": ["model-cache"],
    "nfs": {"server": "<nfs-server>", "path": "/exports/models"}
  }' \
  "$LENS_URL/api/v1/storage/volumes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal
from llm_d_lens.storage.contracts import (
    NfsSpec,
    StorageVolumeCreateRequest,
    StorageVolumeKind,
    StorageVolumePurpose,
)


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.create_storage_volume(
            StorageVolumeCreateRequest(
                cluster_id="<cluster-id>",
                name="<volume-name>",
                kind=StorageVolumeKind.NFS,
                capacity="1Ti",
                read_only=False,
                purposes=[StorageVolumePurpose.MODEL_CACHE],
                nfs=NfsSpec(server="<nfs-server>", path="/exports/models"),
            )
        )
        print(volume.id, volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

对于 `dynamic-pvc`，请改用 `dynamicPvc.storageClass`、`namespace` 和 `accessMode`，并且不要添加 `model-cache` 用途。

### 检查供应状态和实时声明状态

只有 `status` 为 `ready` 时卷才可用。读取记录以查看漂移和使用情况元数据，然后检查实时 PVC 和 PV 对象。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>"

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volume-resource-status?volume_id=<volume-id>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.get_storage_volume("<volume-id>")
        resources = await lens.storage.get_storage_volume_resource_status(
            volume_ids=["<volume-id>"]
        )
        print(volume.status, volume.nodes_added)
        print(resources.items)


asyncio.run(main())
```

  </TabItem>
</Tabs>

`volume_id` 中未知的 id 会被忽略，重复的 id 会被去重。失败的卷不能通过此 API 修复；请删除它并新建一个。

### 处理本地磁盘卷的新节点

当本地磁盘卷在 `nodesAdded` 中报告新节点时，先将卷内容复制到这些节点，然后确认更改以重置基线并清除警告。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>/acknowledge-nodes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.acknowledge_storage_volume_nodes("<volume-id>")
        print(volume.nodes_added)


asyncio.run(main())
```

  </TabItem>
</Tabs>

只有在每个新节点上都有内容后再确认。否则调度到这些节点的部署可能找不到模型文件。

### 导入卷上已有的模型文件

如果你在 Lens 之外将模型文件复制到了卷上，请扫描该卷。Lens 会在后台将发现的模型导入为模型缓存条目。卷必须处于 `ready` 状态。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>/scan-models"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        result = await lens.storage.scan_storage_volume_models("<volume-id>")
        print(result.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

调用返回 `202` 和 `{"status": "scanning"}`。扫描完成后，在模型缓存中查看导入的条目。

### 删除存储卷

删除会立即将卷标记为 `deleting`，返回 `202`，并在后台完成清理。传入 `keep_model_files=true` 可只删除记录，并将模型文件保留在底层磁盘或 NFS 导出上。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X DELETE -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/storage/volumes/<volume-id>?keep_model_files=true"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        volume = await lens.storage.delete_storage_volume(
            "<volume-id>",
            keep_model_files=True,
        )
        print(volume.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

被部署执行引用的卷会被 `409 storage_volume_in_use` 阻止删除。模型缓存条目不阻止删除；除非设置 `keep_model_files`，否则它们会随卷一起删除。

## 端点

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/storage/volumes` | `storage:volume:read` | 列出卷并支持可选过滤。 |
| GET | `/api/v1/storage/volumes/{volume_id}` | `storage:volume:read` | 读取单个卷及其漂移元数据。 |
| GET | `/api/v1/storage/volume-resource-status` | `storage:volume:read` | 读取实时 PVC 和 PV 状态。 |
| POST | `/api/v1/storage/volumes` | `storage:volume:create` | 创建并供应卷。 |
| POST | `/api/v1/storage/volumes/{volume_id}/acknowledge-nodes` | `storage:volume:acknowledge` | 清除本地磁盘节点漂移。 |
| POST | `/api/v1/storage/volumes/{volume_id}/scan-models` | `storage:volume:scan` | 导入卷上已有的模型文件。 |
| DELETE | `/api/v1/storage/volumes/{volume_id}` | `storage:volume:delete` | 删除卷，并可选择删除其模型文件。 |
| GET | `/api/v1/storage/storage-classes` | `storage:volume:read` | 列出集群的 StorageClass。 |
| GET | `/api/v1/storage/nodes` | `storage:volume:read` | 列出集群节点和可调度状态。 |

读取返回 `200`；创建、扫描和删除返回 `202`。

## 错误与限制

- **`401` / `403`** — 未认证或无权访问该集群。维护者只能管理分配给自己的集群上的卷。
- **`404`** — 卷或集群不存在，或者为列出 StorageClass 或节点而访问集群 API 时失败。
- **`409 storage_volume_name_conflict`** — 该名称已在该集群上使用。名称在集群内唯一，比较时不区分大小写。
- **`409 storage_volume_in_use`** — 仍有部署执行引用该卷。请先从这些部署中移除它。
- **`409 storage_volume_not_ready`** — 等待 `status: ready` 后再扫描。
- **`422`** — 请求无效。容量必须是带 `Gi`、`Mi` 或 `Ti` 的整数（例如 `500Gi`），路径必须是绝对路径，并且 spec 必须与所选类型匹配。
- `model-cache` 用途不能与 `kind: dynamic-pvc` 组合使用。请使用 `local-disk` 或 `nfs`，并以可写方式挂载卷。
- 模型缓存卷必须可写。将 `readOnly` 设为 `false`。
- 删除卷会移除其 Lens 记录以及 Kubernetes PVC/PV 对象。只有 `keep_model_files=true` 时底层文件才会保留。
- 删除是异步的。请轮询卷或列表，直到它消失。
