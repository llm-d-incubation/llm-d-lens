## Backend API

集群管理路由来自 `llm_d_lens/cluster/router.py`、`llm_d_lens/cluster/bootstrap/router.py` 和 `llm_d_lens/cluster/sdk_discovery.py`。

### 列出集群

列出由 Lens 管理的集群，并可选择包含尚未完成的草稿记录。该路由还会通过探测每个集群的 Kubernetes API 可达性来计算 `ready` 标志。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/cluster/clusters`**

    请求：无请求体。

    - `includeDrafts`（`boolean`，查询参数，默认 `false`）：是否包含草稿集群记录。

    响应：`ClustersResponse`，每个可见集群对应一个 `ClusterRecord`。`ready` 会校验集群连通性，包括命名空间作用域（`edit`）的 kubeconfig。

`hfTokenSecret` 返回该集群 HF_TOKEN Secret 的命名空间和名称；集群没有该 Secret 时为 `null`。接口只返回位置信息，令牌值保存在目标集群上，不会由 API 返回。

`ClusterRecord` 还包含 `vllmImage`（`string | null`，自定义 OCI 镜像引用；使用所选硬件配置文件的 `runtime_image` 默认值时为 `null`）以及监控配置字段：`monitoringMode`（`"managed"` 或 `"existing"`）、`monitoringNamespace`（默认 `"llm-d-monitoring"`）、`prometheusUrl`、`grafanaUrl`、`prometheusNodePort` 和 `grafanaNodePort`。

    ```json
    {
      "items": [
        {
          "id": "cluster-a",
          "name": "Primary cluster",
          "description": "Shared production GPU cluster",
          "createdAt": "2026-09-20T10:15:00Z",
          "ready": true,
          "proxy": {
            "mode": "custom",
            "httpProxy": "http://proxy.example:3128",
            "httpsProxy": "http://proxy.example:3128",
            "noProxy": "127.0.0.1,localhost,.svc"
          },
          "llmDRef": "v0.3.0",
          "llmDBenchmarkRef": "main",
          "llmDRepoPath": "/cache/llm-d/v0.3.0",
          "llmDBenchmarkRepoPath": "/cache/llm-d-benchmark/main",
          "hfTokenSecret": {
            "namespace": "llm-d-bench-storage-44395349",
            "name": "hf-token-c758ced0"
          },
          "draft": false
        }
      ]
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster import service

    async def main() -> None:
        clusters = service.list_clusters(include_drafts=True)
        ready_flags = await asyncio.gather(*(service.cluster_is_ready(cluster) for cluster in clusters))
        for cluster, ready in zip(clusters, ready_flags):
            print(cluster.id, cluster.name, ready)

    asyncio.run(main())
    ```
  </TabItem>
</Tabs>

### 获取集群详情

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/cluster/clusters/{cluster_id}`**

    返回 `ClusterDetailResponse`：
    `{cluster, plan, planHash, planVersion, draftHfTokenSaved, executionOperations, executionCompletedAt, executionCompletedPlanHash}`。

    - `draftHfTokenSaved`：`boolean`，表示当前调用方是否已为该 draft 集群保存加密的
      draft Hugging Face token（active 集群或由其他用户保存时始终为 `false`；token
      本身永远不会通过 GET 返回）。
    - `executionOperations`：operation id → `user_done` / `admin_done` /
      `lens_done` / `failed`。
    - `executionCompletedAt`：最近一次完成 run 的时间，未完成时为 `null`。
    - `executionCompletedPlanHash`：该 run 记录的 plan hash，没有时为 `null`。

    仅有非空 `executionCompletedAt` 不足以把旧 draft 视为已完成。如果
    `executionCompletedPlanHash` 为 `null` 或与当前 `planHash` 不一致，必须重新
    检查权限并重新执行 operation 列表。
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster import execution, guard, registry

    cluster = registry.require_cluster("cluster-a")
    state = guard.load_plan(cluster.id)
    ledger = execution.operations(cluster.id)
    completed_at = execution.completed_at(cluster.id)
    completed_hash = execution.completed_plan_hash(cluster.id)
    current_hash = state.plan_hash if state else None
    print(ledger, completed_at, completed_hash, current_hash)
    ```
  </TabItem>
</Tabs>

### 注册集群

通过上传的 kubeconfig 文件注册集群。该路由接受 multipart 表单数据，存储集群记录，并返回新集群以及（如有）创建的 Lens 会话 id。

llm-d 组件版本由 Lens 技术栈配置文件固定（参见[获取支持的 llm-d 版本](#获取支持的-llm-d-版本)）；`llmDRef`、`llmDBenchmarkRef`、`routerVersion`、`gieVersion` 和 `ippVersion` 为兼容性保留字段，但会被忽略。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/clusters`**

    请求：multipart 表单数据，不是 JSON。

    - `name`（`string`，表单字段）：集群显示名称。
    - `description`（`string`，表单字段，可选）：自由格式描述。
    - `file`（`file`，表单字段）：UTF-8 编码的 kubeconfig 上传文件。
    - `proxy`（`string`，表单字段，可选）：与 `ProxyConfigDTO` 匹配的 JSON 字符串。
    - `llmDRef`（`string`，表单字段，可选）：已忽略 —— `llm-d` 版本来自技术栈配置文件。
    - `llmDBenchmarkRef`（`string`，表单字段，可选）：已忽略 —— `llm-d-benchmark` 版本来自技术栈配置文件。
    - `gatewayProvider`（`string`，表单字段，可选）：共享网关供应商（`envoy-ai-gateway` | `istio` | `agentgateway` | `gke`）。
    - `gatewayPublicUrl`（`string`，表单字段，可选）：客户端用来访问网关的外部可达主机/IP —— Lens 会自动添加 `http://` 加暴露端口加 `/v1`。为空时将根据暴露端口和集群节点推导。
    - `gatewayPort`（`integer`，表单字段，可选）：共享网关暴露所使用的 NodePort（30000–32767）。
    - `gatewayAuthzHost`（`string`，表单字段）：该集群用来访问 Lens 的主机/IP（对于带有 Lens 地址钩子的供应商为必填：`envoy-ai-gateway`/`istio`/`agentgateway`）。可从 `GET /api/cluster/lens-hosts` 中选取；Lens 会自动添加自身的服务端口，为空时 Lens 会自动填入该主机地址。
    - `inotifyMaxUserInstances`（`integer`，表单字段，默认 `8192`）：Lens 应用于每个节点的每用户 inotify 实例数上限（`fs.inotify.max_user_instances`）。在运行大量 Pod 的节点上，应将其调高到 kind 默认值 128 之上。
    - `vllmImage`（`string`，表单字段，可选）：用于 vLLM 的自定义 OCI 容器镜像引用（需包含 `:tag` 或 `@sha256:` 摘要）；省略时默认使用所选硬件配置文件的 `runtime_image`。无效引用返回 `422 invalid_vllm_image`。
    - `draft`（`boolean`，表单字段，可选）：集群永远以 draft 创建；显式 `draft=false` 返回 `400 draft_creation_forbidden`。

    示例字段取值：

    ```json
    {
      "name": "Primary cluster",
      "description": "Shared production GPU cluster",
      "file": "<uploaded kubeconfig.yaml UTF-8 file>",
      "proxy": "{"mode":"custom","httpProxy":"http://proxy.example:3128","httpsProxy":"http://proxy.example:3128","noProxy":"127.0.0.1,localhost,.svc"}",
      "llmDRef": "v0.3.0",
      "llmDBenchmarkRef": "main",
      "draft": true
    }
    ```

    响应：`CreateClusterResponse`。

    ```json
    {
      "cluster": {
        "id": "cluster-a",
        "name": "Primary cluster",
        "description": "Shared production GPU cluster",
        "createdAt": "2026-09-23T09:00:00Z",
        "ready": false,
        "proxy": {
          "mode": "custom",
          "httpProxy": "http://proxy.example:3128",
          "httpsProxy": "http://proxy.example:3128",
          "noProxy": "127.0.0.1,localhost,.svc"
        },
        "llmDRef": "v0.3.0",
        "llmDBenchmarkRef": "main",
        "draft": true
      },
      "sessionId": "f4c15c0a-8c1f-4eb7-b4d7-ef83f22c2e9b"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    from llm_d_lens.cluster import service

    kubeconfig_text = """
    apiVersion: v1
    kind: Config
    clusters: []
    contexts: []
    current-context: ""
    users: []
    """.strip()

    cluster, session = service.create_cluster(
        "Primary cluster",
        "Shared production GPU cluster",
        kubeconfig_text,
        proxy_mode="custom",
        http_proxy="http://proxy.example:3128",
        https_proxy="http://proxy.example:3128",
        no_proxy="127.0.0.1,localhost,.svc",
        llm_d_ref="v0.3.0",
        llm_d_lensmark_ref="main",
        vllm_image="ghcr.io/example/vllm:v0.8.0",
        draft=True,
    )

    print(cluster.id, session.id)
    ```
  </TabItem>

### 更新集群

修改集群的可编辑设置（名称、描述、代理、Gateway 和 inotify 设置）。kubeconfig 和 draft 状态不在此补丁契约范围内；使用 `POST /execution/complete` finalize。版本字段（`llmDRef`、`llmDBenchmarkRef`、`routerVersion`、`gieVersion`、`ippVersion`）由服务端根据技术栈配置文件管理，输入时会被忽略。

Gateway 命名空间前缀会附加该 Lens 集群注册的稳定短 ID。注册 ID 为 `1234abcd` 时，
默认命名空间为 `lens-gateway-1234abcd`；`gatewayNamespace: "custom"` 会解析为
`custom-1234abcd`。再次传入带后缀的值不会重复添加。集群响应返回实际命名空间，
以前使用共享 `lens-gateway` 默认值的记录也遵循此规则。
`service.update_cluster_settings(..., gateway_namespace="custom")` 的行为相同。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`PATCH /api/cluster/clusters/{cluster_id}`**

    请求体（`ClusterSettingsUpdateRequest`）：

    - `name`（`string`，可选）
    - `description`（`string`，可选）
    - `proxy`（`ProxyConfigDTO`，可选）
    - `llmDRef`（`string`，可选）
    - `llmDBenchmarkRef`（`string`，可选）
    - `gatewayProvider`（`string`，可选）：当集群尚未设置供应商时可赋值一次；设置后不可更改，传入不同值会返回 `422 gateway_provider_immutable`。
    - `gatewayNamespace`（`string`，可选）：最多 63 个字符的命名空间前缀，会附加注册的稳定短 ID。
    - `gatewayPort`（`integer`，可选）
    - `gatewayPublicUrl`（`string`，可选）：外部可达的网关主机/IP —— Lens 会自动添加暴露端口；为空时将自动推导。
    - `gatewayAuthzHost`（`string`）：该集群用来访问 Lens 的主机/IP（对于带有 Lens 地址钩子的供应商为必填；Lens 会自动添加自身服务端口；为空时会自动填入该主机地址）。
    - `inotifyMaxUserInstances`（`integer`，可选）：应用于每个节点的每用户 inotify 实例数上限（默认 `8192`）。
    - `monitoringMode`（`string`，可选）：`"managed"` 或 `"existing"`。
    - `monitoringNamespace`（`string`，可选）：监控栈命名空间（默认 `"llm-d-monitoring"`）。
    - `prometheusUrl`（`string`，可选）：显式 HTTP/HTTPS Prometheus URL；传入 `""` 或 `null` 可清除。
    - `grafanaUrl`（`string`，可选）：显式 HTTP/HTTPS Grafana URL；传入 `""` 或 `null` 可清除。
    - `prometheusNodePort`（`integer`，可选）：Prometheus NodePort（`30000`–`32767`）；传入 `null` 可清除。
    - `grafanaNodePort`（`integer`，可选）：Grafana NodePort（`30000`–`32767`）；传入 `null` 可清除。
    - `monitoringHost`（`string`，可选）：未设置显式 URL 时用于推导 NodePort URL 的主机/IP；传入 `""` 或 `null` 可清除。
    - `installAcceleratorExporters`（`boolean`，可选）：是否安装加速器指标导出器。
    - `vllmImage`（`string`，可选）：用于 vLLM 的自定义 OCI 容器镜像引用（需包含 `:tag` 或 `@sha256:` 摘要）；传入 `""` 或 `null` 可重置为所选硬件配置文件的 `runtime_image` 默认值。无效引用返回 `422 invalid_vllm_image`；在活跃 draft 执行期间修改返回 `409 execution_in_progress`。
    - `draft`：不接受。发送它返回 `400 draft_update_forbidden`。

    ```json
    {
      "name": "Primary cluster",
      "description": "Shared production GPU cluster",
      "proxy": {
        "mode": "custom",
        "httpProxy": "http://proxy.example:3128",
        "httpsProxy": "http://proxy.example:3128",
        "noProxy": "127.0.0.1,localhost,.svc"
      },
      "llmDRef": "v0.3.0",
      "llmDBenchmarkRef": "main"
    }
    ```

    响应：`CreateClusterResponse`，包含更新后的记录。

    ```json
    {
      "cluster": {
        "id": "cluster-a",
        "name": "Primary cluster",
        "description": "Shared production GPU cluster",
        "createdAt": "2026-09-23T09:00:00Z",
        "ready": true,
        "proxy": {
          "mode": "custom",
          "httpProxy": "http://proxy.example:3128",

          "noProxy": "127.0.0.1,localhost,.svc"
        },
        "llmDRef": "v0.3.0",
        "llmDBenchmarkRef": "main",
        "draft": false
      },
      "sessionId": null
    }
    ```

### 轮换集群 HF_TOKEN secret

在编辑集群面板中替换集群 `HF_TOKEN` Secret 中保存的 Hugging Face 令牌。与创建接口不同，这里使用 apply，因此已存在的 Secret 会被覆盖而不是报错。`namespace` 和 `name` 默认使用集群上已记录的坐标（`hfTokenSecret`），所以轮换令牌只需提供令牌；提供不同坐标会把集群指向该 Secret，并在其不存在时创建它。

轮换只重写这个集群级 Secret。部署和模型缓存下载在运行时派生的命名空间内 `llm-d-hf-token` 副本会在下一次部署或下载时重新派生，因此已在运行的工作负载在重建之前仍使用旧令牌。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`PUT /api/cluster/clusters/{cluster_id}/hf-token-secret`**

    请求体（`HfTokenSecretUpdateRequest`）：

    - `namespace`（`string`，可选）：默认使用集群已记录的 Secret 命名空间。
    - `name`（`string`，可选）：默认使用集群已记录的 Secret 名称。
    - `token`（`string`，必填）：新的 Hugging Face 令牌；空值返回 `422 invalid_secret_token`。

    ```json
    {
      "token": "hf_rotatedTokenValue"
    }
    ```

    响应：`HfTokenSecretRef`，返回实际写入的坐标。

    ```json
    {
      "namespace": "llm-d-bench-storage-44395349",
      "name": "hf-token-c758ced0"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster import registry, service

    cluster = registry.get_cluster("cluster-a")
    # 使用集群上已记录的坐标原地轮换。
    ref = asyncio.run(service.update_hf_token_secret(cluster, "hf_rotatedTokenValue"))
    print(ref["namespace"], ref["name"])

    # 也可以把集群指向另一个 Secret。
    ref = asyncio.run(
        service.update_hf_token_secret(
            cluster,
            "hf_rotatedTokenValue",
            namespace="llm-d-bench-storage-44395349",
            name="hf-token-rotated",
        )
    )
    ```
  </TabItem>
</Tabs>

### 启动集群软件下载

为集群下载由 Lens 技术栈配置文件固定的 `llm-d` 和 `llm-d-benchmark` 版本。处理函数会调度后台下载任务并立即返回当前状态快照；请求体会被忽略。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/clusters/{cluster_id}/software-downloads`**

    请求体（`SoftwareDownloadRequest`）：可选且会被忽略 —— 系统会下载配置文件中固定的版本。

    ```json
    {}
    ```

    响应：`SoftwareDownloadStatusResponse`。

    ```json
    {
      "llmD": {
        "ref": "v0.2.0",
        "state": "downloading",
        "path": null,
        "error": null
      },
      "llmDBenchmark": {
        "ref": "main",
        "state": "downloading",
        "path": null,
        "error": null
      }
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster.router import _download_and_record
    from llm_d_lens.cluster import repo_downloads

    async def main() -> None:
        await _download_and_record("cluster-a", "llm-d", "v0.2.0")
        await _download_and_record("cluster-a", "llm-d-benchmark", "main")
        print(repo_downloads.get_status("cluster-a", "llm-d"))
        print(repo_downloads.get_status("cluster-a", "llm-d-benchmark"))

    asyncio.run(main())
    ```
  </TabItem>

### 获取集群软件下载状态

返回集群固定的 `llm-d` 和 `llm-d-benchmark` 引用的当前内存态下载状态。使用此端点来轮询下载进度。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/cluster/clusters/{cluster_id}/software-downloads`**

    请求：无请求体。

    - `cluster_id`（`string`，路径参数）：目标集群 id。

    响应：`SoftwareDownloadStatusResponse`。

    ```json
    {
      "llmD": {
        "ref": "v0.2.0",
        "state": "ready",
        "path": "/cache/llm-d/v0.2.0",
        "error": null
      },
      "llmDBenchmark": {
        "ref": "main",
        "state": "ready",
        "path": "/cache/llm-d-benchmark/main",
        "error": null
      }
    }
    ```
  </TabItem>

### 删除集群

删除由 Lens 管理的集群记录，并清理相关状态。仅当需要将集群从 Lens 中彻底移除时才应使用此操作。

删除采用两阶段清理流程，使仅拥有命名空间级 `edit` kubeconfig 的用户在遇到需要编排平台管理员权限的集群级或跨命名空间清理时不会被阻塞：

- **阶段 A（使用已保存的 kubeconfig 尽力清理）**：Lens 删除其有权限清理的资源，包括注册独立的 Gateway 命名空间（通常为 `lens-gateway-<cluster-id>`）；若使用共享/已有 Gateway 命名空间（`namespaceMode: "existing"` 或不可删除命名空间），则仅删除 Lens 自有的 Gateway 资源（`gateway.gateway.networking.k8s.io/<gateway_name>` 及尽力清理的 provider/authz/`lens-node-sysctl` 配套资源）。对于 `HF_TOKEN` Secret，永远不会删除 `existing-secret:*` 及其 `existing` 模式命名空间；`create-secret` 且为 `create` 模式的命名空间在非受保护/非共享时直接作为 `hf-secret.namespace` 删除，创建后轮换的 HF Secret 仅删除 Secret 本身（不删除命名空间），无计划的旧版外部 Secret 命名空间仅在 Lens 自有或移除后仅剩系统注入对象时删除。受保护命名空间（`default`、`kube-system`、`kube-public`、`kube-node-lease`、`istio-system`、`envoy-gateway-system`、`envoy-ai-gateway-system`、`agentgateway-system`）、`lens-gateway`、`llm-d-bench-storage` 以及 kubeconfig/handoff 命名空间永远不会被删除。对于草稿集群，仍挂在其上的存储卷也会连同其 `PersistentVolumeClaim` 和 `PersistentVolume` 对象一起删除（底层 NFS 或主机路径文件因 `Retain` 回收策略而保留）。
- **阶段 B（编排平台管理员交接）**：如果任何必需的清理操作因 `403`/RBAC 权限不足而失败，Lens 会在 `marker.namespace` 中检查完成标记 `ConfigMap`（`lens-admin-cleanup-<cluster_id>`），验证其 `clusterId`、`status: "completed"`、`cleanupDigest` 及所有未验证操作。若尚未完成，Lens 返回 `409 cluster_admin_cleanup_required`（RFC-7807），并在响应中包含幂等清理脚本 `script`、`cleanupDigest`、`operations`、`completedOperations`、`marker`、`canVerifyMarker` 和 `confirmRequired`，供编排平台管理员执行脚本后重试删除。
- **离线/不可达回退**：如果删除时集群不可达，Lens 返回 `502 cluster_gateway_cleanup_failed`，并在错误载荷中附带幂等 `script` 和 `cleanupDigest`。传入 `confirmAdminCleanup=true` 可确认已完成手动清理并移除 Lens 注册记录。

非草稿集群如果仍有可用部署或存储卷，即使传入 `confirmAdminCleanup=true` 也始终会返回 `409`（`cluster_has_available_deployments` 或 `cluster_has_storage_volumes`）。

如果可以直接提供临时编排平台管理员 kubeconfig，仍可使用 `POST /api/cluster/clusters/{cluster_id}/cleanup` 作为替代方案。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`DELETE /api/cluster/clusters/{cluster_id}`**

    请求：无请求体。

    - `cluster_id`（`string`，路径参数）：目标集群 id。
    - `confirmAdminCleanup`（`boolean`，查询参数，默认 `false`）：当标记不可验证（`canVerifyMarker: false`）或集群不可达（`502`）时，设为 `true` 表示确认编排平台管理员已执行清理脚本。

    响应：`204 No Content`。此端点不返回 JSON 响应体。

    失败：
    - `409 cluster_has_available_deployments` 或 `409 cluster_has_storage_volumes`：已完成注册的集群仍有对应资源。
    - `409 cluster_admin_cleanup_required`：必需的远端清理需要编排平台管理员权限（包含 `script`、`cleanupDigest`、`operations`、`completedOperations`、`marker`、`canVerifyMarker` 和 `confirmRequired`）。
    - `502 cluster_gateway_cleanup_failed`：集群不可达或必需清理失败且未传 `confirmAdminCleanup=true`（可用时包含 `script` 和 `cleanupDigest`）。
  </TabItem>
  <TabItem value="python-api" label="Python API">
    必要清理失败时，`service.delete_cluster()` 抛出包含相同状态和错误码的 `ClusterOverviewError`。

    ```python
    import asyncio

    from llm_d_lens.cluster import service

    async def main() -> None:
        await service.delete_cluster("cluster-a", confirm_admin_cleanup=False)

    asyncio.run(main())
    ```
  </TabItem>
</Tabs>

### 获取集群概览

返回一个集群的实时 Kubernetes 概览信息，包括节点、GPU、命名空间、缓存镜像以及组件健康状况摘要。该路由还会在返回实时快照的同时报告当前的集群记录。

显存容量优先使用 Prometheus 遥测，其次使用 DRA ResourceSlice 容量。
两者均未提供容量时，已注册的硬件 profile 可以读取工作节点上的每卡显存和设备数量标签。
NVIDIA profile 使用 GFD 的 `nvidia.com/gpu.memory`（MiB）和 `nvidia.com/gpu.count`；
标签数量必须与识别的设备容量一致，避免将共享副本数计入物理显存。
该补充来源仅提供静态总容量，不提供当前显存占用或剩余显存。
缺少占用遥测时，设备的 `vramUsedBytes` 和 `vramUsagePercent` 保持 `null`，界面显示未知而非零占用。
标签缺失或无效时，容量仍保持未知，不会根据型号猜测显存。
标签名称和单位由 profile 的 `planning.node_memory` 声明；未声明的 profile 不启用该补充来源。

### 读取规划发现资源

为一个活动的集群会话读取某个受许可列表限制的规划发现资源。此端点有意限制为固定的 `kubectl` 读取操作，当读取失败或返回不可用的 JSON 时会返回 `{"result": null}`。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`GET /api/cluster/sessions/{session_id}/planning-discovery/{resource}`**

    请求：无请求体。

    - `session_id`（`string`，路径参数）：活动集群会话 id。
    - `resource`（`string`，路径参数）：`version`、`nodes`、`deviceclasses`、`resourceslices` 或 `runtimeclasses` 之一。

    响应：包含 `result` 键的包装对象。

    ```json
    {
      "result": {
        "items": []
      }
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio
    import json

    from llm_d_lens.cluster import sessions
    from llm_d_lens.utils.kubernetes import run_kubectl

    async def main() -> None:
        session = sessions.require_active_session("f4c15c0a-8c1f-4eb7-b4d7-ef83f22c2e9b")
        result = await run_kubectl(["get", "nodes", "-o", "json"], timeout=10, cluster_id=session.id)
        payload = json.loads(result.stdout) if result.ok else None
        print({"result": payload if isinstance(payload, dict) else None})

    asyncio.run(main())
    ```
  </TabItem>
</Tabs>

### 发现引导阶段的 SSH 主机密钥

        { "host": "10.0.0.1", "port": 22, "fingerprint": "SHA256:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA" },

### 启动引导作业

在预检成功后启动一个基于 Kubespray 的长时间运行集群引导作业。响应会立即返回引导作业 id，而实际的配置过程会在后台继续进行。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/cluster/bootstrap`**

    请求体（`BootstrapCreateRequest`）：

    - `nodes`（`BootstrapNodeInput[]`）：要配置的节点。
    - `hostKeys`（`BootstrapHostKeyPin[]`）：每个展开后的 `host:port` 对应的确切已确认指纹。
    - `proxy`（`BootstrapProxyConfig`，可选）：目标节点的代理配置。

    ```json
    {
      "nodes": [
        {
          "host": "10.0.0.1",
          "port": 22,
          "roles": [
            "control-plane"
          ],
          "username": "root"
        },
        {
          "host": "10.0.0.2",
          "port": 22,
          "roles": [
            "worker"
          ],
          "username": "root"
        }
      ],
      "hostKeys": [
        { "host": "10.0.0.1", "port": 22, "fingerprint": "SHA256:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA" },
        { "host": "10.0.0.2", "port": 22, "fingerprint": "SHA256:BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB" }
      ],
      "proxy": {
        "mode": "custom",
        "httpProxy": "http://proxy.example:3128",
        "httpsProxy": "http://proxy.example:3128",
        "noProxy": "127.0.0.1,localhost,.svc"
      }
    }
    ```

    响应：`BootstrapCreateResponse`。

    ```json
    {
      "bootstrapId": "bootstrap-5b7fd3a81290"
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">
    ```python
    import asyncio

    from llm_d_lens.cluster.bootstrap.dto import BootstrapHostKeyPin, BootstrapNodeInput, BootstrapProxyConfig
    from llm_d_lens.cluster.bootstrap import service

    async def main() -> None:
      pins = [
        BootstrapHostKeyPin(host="10.0.0.1", port=22, fingerprint="SHA256:AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA"),
        BootstrapHostKeyPin(host="10.0.0.2", port=22, fingerprint="SHA256:BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB"),
      ]
        job = service.create_job(
            [
                BootstrapNodeInput(host="10.0.0.1", roles=["control-plane"]),
                BootstrapNodeInput(host="10.0.0.2", roles=["worker"]),
            ],
            pins,
            proxy=BootstrapProxyConfig(
                mode="custom",
                httpProxy="http://proxy.example:3128",
                httpsProxy="http://proxy.example:3128",
                noProxy="127.0.0.1,localhost,.svc",
            ),
        )
        await service.run_bootstrap_job(job.id)
        print(job.id)

    asyncio.run(main())
    ```
  </TabItem>
</Tabs>
