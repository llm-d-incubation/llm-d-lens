## 概述

模型缓存将模型权重存储在已注册的存储卷上，使部署和基准测试无需在启动时下载。使用本模块填充共享缓存、查看下载进度和日志、重试失败、同步新节点并删除缓存模型。目标卷必须为 `ready` 且标记 `model-cache` 用途。下载始终使用集群上保存的 Hugging Face 令牌；API 不接受按请求传入的令牌。

## 快速开始

列出已缓存的模型，可选地限定到一个集群或存储卷。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries?cluster_id=<cluster-id>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        result = await lens.model_cache.list_model_cache_entries(
            cluster_id="<cluster-id>"
        )
        for entry in result.items:
            print(entry.id, entry.source.display_name(), entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

`pendingSyncNodes` 列出仍需要本地磁盘缓存条目的节点。

## 常见任务

### 从 Hugging Face 下载模型

请求将模型下载到就绪的模型缓存卷。调用返回 `202` 和一个 `pending` 条目，同时下载 Job 在后台启动。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "storageVolumeId": "<volume-id>",
    "source": {
      "kind": "huggingface",
      "huggingface": {
        "repoId": "<org>/<model>",
        "revision": "main"
      }
    }
  }' \
  "$LENS_URL/api/v1/model-cache/entries"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.model_cache.contracts import (
    HuggingFaceSource,
    ModelCacheCreateRequest,
    ModelSource,
    ModelSourceKind,
)
from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.create_model_cache_entry(
            ModelCacheCreateRequest(
                cluster_id="<cluster-id>",
                storage_volume_id="<volume-id>",
                source=ModelSource(
                    kind=ModelSourceKind.HUGGINGFACE,
                    huggingface=HuggingFaceSource(
                        repo_id="<org>/<model>",
                        revision="main",
                    ),
                ),
            )
        )
        print(entry.id, entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

对于私有或门控模型，请让管理员在集群设置中保存一个有权访问该模型的 Hugging Face 令牌。公开模型无需令牌即可下载。`tokenSource` 仅为兼容性而接受，但会被忽略。

### 重新下载卷上已有的模型

对相同模型和修订版再次请求会返回 `409 model_cache_entry_exists`，并带有现有 `entryId` 和 `entryStatus`。重新发送并设置 `force: true` 可再次下载。Lens 永远不会创建重复条目。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "clusterId": "<cluster-id>",
    "storageVolumeId": "<volume-id>",
    "source": {
      "kind": "huggingface",
      "huggingface": {"repoId": "<org>/<model>", "revision": "main"}
    },
    "force": true
  }' \
  "$LENS_URL/api/v1/model-cache/entries"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.model_cache.contracts import (
    HuggingFaceSource,
    ModelCacheCreateRequest,
    ModelSource,
    ModelSourceKind,
)
from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.create_model_cache_entry(
            ModelCacheCreateRequest(
                cluster_id="<cluster-id>",
                storage_volume_id="<volume-id>",
                source=ModelSource(
                    kind=ModelSourceKind.HUGGINGFACE,
                    huggingface=HuggingFaceSource(
                        repo_id="<org>/<model>",
                        revision="main",
                    ),
                ),
                force=True,
            )
        )
        print(entry.id, entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

`ready` 或 `failed` 条目会被重置并原地重新下载。`pending` 或 `downloading` 条目会原样返回，因此确认操作会加入正在进行的下载，而不是再启动一个。

### 查看下载进度和日志

读取条目以查看每节点状态，然后获取失败节点的日志。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>"

curl -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>/logs?node=<node-name>"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.get_model_cache_entry("<entry-id>")
        logs = await lens.model_cache.get_model_cache_entry_logs(
            "<entry-id>",
            node="<node-name>",
        )
        print(entry.status, entry.node_progress)
        print(logs.logs)


asyncio.run(main())
```

  </TabItem>
</Tabs>

`nodeProgress[].status` 为 `pending`、`downloading`、`ready` 或 `failed`。节点失败时，`failureDetail` 包含面向用户的错误。

### 重试失败的下载

只有处于 `failed` 状态的条目可以重试。调用返回 `202`，并将条目移回 `pending`。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>/retry"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        entry = await lens.model_cache.retry_model_cache_entry("<entry-id>")
        print(entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

重试 `ready`、`pending`、`downloading` 或 `deleting` 条目会返回 `409 model_cache_invalid_state`。请先修复根本原因再重试。

### 将缓存模型同步到新节点

新节点或替换节点没有本地磁盘缓存内容。同步单个条目或集群上的所有条目；Lens 只为缺少该模型的节点排队下载。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
# Sync every local-disk entry missing on new nodes.
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/sync-nodes?cluster_id=<cluster-id>"

# Or sync one entry.
curl -X POST -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>/sync-nodes"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        changed = await lens.model_cache.sync_model_cache_nodes(
            cluster_id="<cluster-id>"
        )
        entry = await lens.model_cache.sync_model_cache_entry_nodes("<entry-id>")
        print(len(changed.items), entry.status)


asyncio.run(main())
```

  </TabItem>
</Tabs>

两个调用都返回 `202`。当新节点需要供应时，条目会移回 `downloading`。NFS 卷不需要节点同步，因为所有节点共享它。

### 删除缓存模型

删除会移除条目；除非保留文件，否则会安排清理缓存文件。调用返回 `202`。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -X DELETE -H "Authorization: Bearer $LENS_TOKEN" \
  "$LENS_URL/api/v1/model-cache/entries/<entry-id>?keep_files=true"
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
import asyncio

from llm_d_lens.sdk import LensLocal


async def main() -> None:
    with LensLocal("<username>") as lens:
        result = await lens.model_cache.delete_model_cache_entry(
            "<entry-id>",
            keep_files=True,
        )
        print(result)


asyncio.run(main())
```

  </TabItem>
</Tabs>

设置 `keep_files=false` 可从共享卷中移除文件。从未达到 `ready` 的条目可能返回最小的 `{"id": "<entry-id>", "status": "deleted"}` 响应，因为没有需要清理的内容。

## 端点

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/model-cache/entries` | `model-cache:entry:read` | 列出条目，可按集群或卷过滤。 |
| GET | `/api/v1/model-cache/entries/{entry_id}` | `model-cache:entry:read` | 读取单个条目、节点进度和待同步节点。 |
| POST | `/api/v1/model-cache/entries` | `model-cache:entry:create` | 请求下载模型。 |
| POST | `/api/v1/model-cache/entries/{entry_id}/retry` | `model-cache:entry:retry` | 重试失败的下载。 |
| POST | `/api/v1/model-cache/entries/sync-nodes` | `model-cache:entry:sync` | 将所有缺少模型的条目同步到新节点。 |
| POST | `/api/v1/model-cache/entries/{entry_id}/sync-nodes` | `model-cache:entry:sync` | 将单个条目同步到新节点。 |
| DELETE | `/api/v1/model-cache/entries/{entry_id}` | `model-cache:entry:delete` | 删除条目，并可选择删除其文件。 |
| GET | `/api/v1/model-cache/entries/{entry_id}/logs` | `model-cache:entry:read` | 读取下载或清理日志。 |
| GET | `/api/v1/model-cache/huggingface/search` | `model-cache:entry:read` | 搜索 Hugging Face 仓库。 |
| GET | `/api/v1/model-cache/huggingface/models/{repo_id}` | `model-cache:entry:read` | 读取单个仓库的元数据和 README。 |

读取返回 `200`；创建、重试、同步和删除返回 `202`。

## 错误与限制

- **`401` / `403`** — 未认证或无权访问该集群。
- **`404`** — 条目不存在，或在 Hugging Face 上找不到该仓库。
- **`409 model_cache_entry_exists`** — 卷上已有此模型和修订版。确认后重新发送并设置 `force: true`。
- **`409 storage_volume_not_model_cache`** — 该卷未标记 `model-cache` 用途。
- **`409 storage_volume_not_ready`** — 等待存储卷变为 `ready`。
- **`409 model_cache_invalid_state`** — 只有 `failed` 条目可以重试。
- **`501 model_catalog_not_supported`** — 尚未实现模型目录来源。请改为发送 Hugging Face 的 `repoId` 和 `revision`。
- **`502 huggingface_hub_unavailable`** — 无法访问 Hugging Face。请检查网络访问以及集群或主机代理。
- 下载需要就绪的 `local-disk` 或 `nfs` 卷。`dynamic-pvc` 卷不能带有 `model-cache` 用途。
- Hugging Face 环境变量由管理员管理。请通过集群保存的令牌设置凭据，而不是部署自定义参数。
- 同步适用于本地磁盘条目。NFS 卷是共享的，不需要逐节点复制。
- 删除是异步的。清理完成前，条目会保持在 `deleting` 状态。
