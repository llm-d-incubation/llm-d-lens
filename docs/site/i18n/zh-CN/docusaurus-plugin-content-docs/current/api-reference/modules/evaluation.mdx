import Tabs from '@theme/Tabs';

Lens Evaluate 可以对就绪的部署执行或已发布的 Model Service 进行基准测试，也可以在同一个工作流中部署配置并运行测试。使用本模块可以运行吞吐量和延迟测试、比较配置、查看已保存结果并清理运行。基准测试需要就绪的执行（包含端点）和活动集群会话。

## 快速开始

对现有的就绪部署运行基准测试。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -sX POST http://127.0.0.1:3000/api/v1/evaluate/runs \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "deployment_execution_id": "<execution-id>",
    "cluster_session_id": "<cluster-session-id>",
    "workload": "sanity_random.yaml"
  }'
```

```json
{
  "kind": "benchmark",
  "id": "<run-id>",
  "status": "queued"
}
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.evaluation.models import EvaluateRunRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        run = await lens.evaluation.create_run(
            EvaluateRunRequest(
                deployment_execution_id="<execution-id>",
                cluster_session_id="<cluster-session-id>",
                workload="sanity_random.yaml",
            )
        )
        print(run.id, run.status)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

## 常见任务

### 估算基准测试时间

预览工作负载的运行时长和自动超时。此操作不会读取或启动集群资源。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/evaluate/timing-estimate`**

```json
{
  "parallelism": 1,
  "matrix": [{"isl": 1024, "osl": 128}],
  "concurrency_stages": [{"concurrency": 8, "num_requests": 96}]
}
```

响应字段：`lower_seconds`、`upper_seconds`、`timeout_seconds`、`timeout_mode`、`assumptions`。

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.evaluation.models import BenchmarkSpec
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        timing = await lens.evaluation.estimate_timing(
            BenchmarkSpec(
                parallelism=1,
                matrix=[{"isl": 1024, "osl": 128}],
                concurrency_stages=[{"concurrency": 8, "num_requests": 96}],
            )
        )
        print(timing.lower_seconds, timing.upper_seconds, timing.timeout_seconds)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 使用矩阵和 SLA 目标进行基准测试

扫描不同的输入/输出长度组合，并附加可选目标。运行入队后返回 `202`；请轮询其进度。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/evaluate/runs`**

```json
{
  "deployment_execution_id": "<execution-id>",
  "cluster_session_id": "<cluster-session-id>",
  "harness": "inference-perf",
  "workload": "sanity_random.yaml",
  "parallelism": 2,
  "matrix": [{"isl": 1024, "osl": 128}],
  "concurrency_stages": [{"concurrency": 8, "num_requests": 96}],
  "sla_targets": {
    "ttft_ms": 500,
    "tpot_ms": 50,
    "throughput_min_tps": 1000
  }
}
```

响应字段：`id`、`status`、`deployment_execution_id`、`matrix`、`sla_targets`。

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.evaluation.models import BenchmarkSlaTargets, EvaluateRunRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        run = await lens.evaluation.create_run(
            EvaluateRunRequest(
                deployment_execution_id="<execution-id>",
                cluster_session_id="<cluster-session-id>",
                harness="inference-perf",
                workload="sanity_random.yaml",
                parallelism=2,
                matrix=[{"isl": 1024, "osl": 128}],
                concurrency_stages=[{"concurrency": 8, "num_requests": 96}],
                sla_targets=BenchmarkSlaTargets(
                    ttft_ms=500,
                    tpot_ms=50,
                    throughput_min_tps=1000,
                ),
            )
        )
        print(run.id, run.status)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 对已发布的 Model Service 进行基准测试

使用 `model_service_group_id` 代替 `deployment_execution_id`。测试框架会解析该组的活动成员，并通过共享网关调用。必须提供以 `lens-mk-` 开头的模型访问令牌作为 `api_key`；该令牌不会被持久化。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/evaluate/runs`**

```json
{
  "model_service_group_id": "<model-service-group-id>",
  "api_key": "<token>",
  "harness": "inference-perf",
  "workload": "sanity_random.yaml"
}
```

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.evaluation.models import EvaluateRunRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        run = await lens.evaluation.create_run(
            EvaluateRunRequest(
                model_service_group_id="<model-service-group-id>",
                api_key="<token>",
                workload="sanity_random.yaml",
            )
        )
        print(run.id, run.status)

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 比较已保存的配置

部署一个或多个已保存的配置产物，运行基准测试，并与可选基线比较结果。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/evaluate/evaluations`**

```json
{
  "name": "Qwen comparison",
  "cluster_session_id": "<cluster-session-id>",
  "benchmark_plans": [
    {
      "id": "candidate",
      "configuration_artifact_id": "<configuration-artifact-id>",
      "include_baseline": true,
      "baseline_type": "direct-vllm",
      "benchmark": {
        "workload": "sanity_random.yaml",
        "matrix": [{"isl": 1024, "osl": 128}]
      }
    }
  ],
  "compare_configurations": true
}
```

响应字段：`kind`、`id`、`status`、`cases[]`。

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.evaluation.models import EvaluationCreateRequest
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        workflow = await lens.evaluation.create_evaluation(
            EvaluationCreateRequest(
                name="Qwen comparison",
                cluster_session_id="<cluster-session-id>",
                benchmark_plans=[
                    {
                        "id": "candidate",
                        "configuration_artifact_id": "<configuration-artifact-id>",
                        "include_baseline": True,
                        "baseline_type": "direct-vllm",
                        "benchmark": {
                            "workload": "sanity_random.yaml",
                            "matrix": [{"isl": 1024, "osl": 128}],
                        },
                    }
                ],
            )
        )
        print(workflow.id, workflow.status, len(workflow.cases or []))

    asyncio.run(main())
```

  </TabItem>
</Tabs>

### 查看结果并管理运行

读取基准测试结果或展开的工作流详情，然后在满足条件时取消、重试或删除。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`GET /api/v1/evaluate/runs/<run-id>`**

**`GET /api/v1/evaluate/workflow-runs/<workflow-id>/details`**

```json
{
  "workflow": {"id": "<workflow-id>", "status": "succeeded"},
  "report": {
    "comparison_version": 2,
    "comparisons": []
  }
}
```

对于失败或已取消的工作流，使用 `POST /api/v1/evaluate/workflow-runs/<workflow-id>/retry`；使用 `POST /api/v1/evaluate/workflow-runs/<workflow-id>/cancel` 停止；进入终态后使用 `DELETE /api/v1/evaluate/workflow-runs/<workflow-id>` 删除。

  </TabItem>
  <TabItem value="python-api" label="In-process Python SDK">

```python
from llm_d_lens.sdk import LensLocal

with LensLocal("<username>") as lens:
    import asyncio

    async def main() -> None:
        detail = await lens.evaluation.get_workflow_run_details("<workflow-id>")
        print(detail["workflow"]["id"], detail["report"]["comparison_version"])

        await lens.evaluation.cancel_workflow_run("<workflow-id>")
        await lens.evaluation.delete_workflow_run("<workflow-id>")

    asyncio.run(main())
```

  </TabItem>
</Tabs>

## 端点

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/evaluate/benchmark-defaults` | `evaluate:run:read` | 显示默认基准测试来源和运行时 |
| `POST` | `/api/v1/evaluate/timing-estimate` | `evaluate:run:read` | 估算时长和超时 |
| `POST` | `/api/v1/evaluate/runs` | `evaluate:run:create` | 对就绪执行或 Model Service 运行基准测试 |
| `GET` | `/api/v1/evaluate/runs` | `evaluate:run:read` | 列出基准测试运行 |
| `GET` | `/api/v1/evaluate/runs/{run_id}` | `evaluate:run:read` | 获取基准测试结果和证据 |
| `POST` | `/api/v1/evaluate/runs/{run_id}/cancel` | `evaluate:run:cancel` | 取消活动基准测试 |
| `DELETE` | `/api/v1/evaluate/runs/{run_id}` | `evaluate:run:delete` | 删除终态基准测试 |
| `POST` | `/api/v1/evaluate/workflow-runs` | `evaluate:workflow:create` | 在一个工作流中部署并运行基准测试 |
| `POST` | `/api/v1/evaluate/evaluations` | `evaluate:workflow:create` | 运行多配置评估 |
| `GET` | `/api/v1/evaluate/workflow-runs` | `evaluate:run:read` | 列出评估工作流 |
| `GET` | `/api/v1/evaluate/workflow-runs/{workflow_id}` | `evaluate:run:read` | 获取工作流记录 |
| `GET` | `/api/v1/evaluate/workflow-runs/{workflow_id}/details` | `evaluate:run:read` | 获取用例、结果和报告 |
| `POST` | `/api/v1/evaluate/workflow-runs/{workflow_id}/retry` | `evaluate:run:retry` | 重试失败或已取消的工作流 |
| `POST` | `/api/v1/evaluate/workflow-runs/{workflow_id}/cancel` | `evaluate:run:cancel` | 取消工作流 |
| `POST` | `/api/v1/evaluate/workflow-runs/{workflow_id}/cases/{case_id}/cancel` | `evaluate:run:cancel` | 取消单个评估用例 |
| `DELETE` | `/api/v1/evaluate/workflow-runs/{workflow_id}` | `evaluate:run:delete` | 删除终态工作流 |

## 错误与限制

| 状态码 | 含义 | 处理方式 |
| --- | --- | --- |
| `401` / `403` | 未认证或缺少权限 | 检查令牌和上表的权限列 |
| `404` | 执行、运行、工作流或 Model Service 不存在 | 重新列出资源并确认 id |
| `409` | 未就绪、生命周期冲突、没有健康成员或由其他后端持有 | 检查状态并将请求发送到持有该工作的后端 |
| `422` | 请求无效或标识符格式错误 | 修正请求字段 |
| `503` | 评估无法入队 | 检查集群访问权限后重试 |

- 基准测试目标必须是包含端点且具有活动集群会话的 `ready` 执行。否则创建返回 `409`；执行不存在返回 `404`。
- `deployment_execution_id` 和 `model_service_group_id` 只能设置一个。Model Service 基准测试还需要以 `lens-mk-` 开头的 `api_key`。
- HTTP `202` 表示运行已入队。开始流量前必须通过监控准备；准备失败会在基准测试开始前停止运行。
- `wait_timeout_seconds: null` 使用 900 到 14400 秒之间的自动预算。显式值必须为 1-14400。`parallelism` 为 1-32，`harness_memory_gib` 为 1-512。
- `matrix`、`shared_prefix` 和 `workload_yaml` 中最多只能使用一个作为工作负载生成器。
- 只有 `succeeded`、`failed` 和 `cancelled` 是终态。仅在基准测试或工作流进入终态后删除；活动运行以及由工作流持有的基准测试返回 `409`。
- 只能重试失败或已取消的工作流。对由其他后端持有的工作执行取消、重试或删除会返回 `409`；请将请求发送到该后端。
- 对于 PD 配置，自动基线副本数必须为 1 到 32 的精确整数。否则创建会在入队前返回 `409`；可设置显式基线副本数以覆盖。
- 缺失的历史遥测、KV 采集或资源快照不会根据当前实时数据重建。请重新运行以采集新启用的证据。
