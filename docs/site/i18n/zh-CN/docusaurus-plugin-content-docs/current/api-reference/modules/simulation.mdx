## 后端 API

本地执行与 Pod 执行通过 `llm_d_lens.simulation.progress.report_request_progress` 共享请求进度报告。Pod 报告仍会等待就绪；本地报告则保留其原始开始时间。后端适配器通过 `backends.analytics.artifact_error_message` 共享产物错误格式化逻辑，同时各自保留自身的错误/超时字段优先级、状态映射和指标单位。任务 API 与后端环境准备逻辑保持不变。

Trace Replayer（轨迹回放）的后端路由位于 `llm_d_lens/simulation/router.py`，路由前缀为 `/api/simulation`。

### 测试时证据与历史入库

任务的创建、查询、列表及重跑响应包含可选 `benchmark_evidence`：
保存的任务和部署配置、通过 API 补全的 `benchmark_context`、可选的 Model Service
`routing`、采集或校验失败时的 `benchmark_context_error`，以及终态 `ingestion` 诊断。
请求不需要新增元数据参数。事实在流量开始前采集，完成后校验；重跑重新获取自己的快照。

`benchmark_context.model_identity` 记录权威模型标识及来源（`deployment-configuration`
或 `model-service-routing`），包括部署执行 ID；Model Service 路径还包含组和成员 ID。
Simulation 直接复用已验证身份，不解析容器启动命令。硬件和运行时事实仍独立探测，
并保留容器及路由稳定性检查。未观测到的 `serving_configuration` 字段及辅助元数据
保持 null，并记录 `warnings`，不以配置值代替。硬兼容字段缺失的记录仍可归档，
但不参与预测匹配。

入库报告包含 `schema_version`、`status`、`record_ids`、`existing_ids`、
`inserted_ids` 和 `issues`。状态为 `stored`、`partial`、`skipped` 或 `error`；
只读预览对待入库的有效记录返回 `eligible` 和 `eligible_ids`。
每条证据使用 `simulation:<task-id>` 及原始测试时间。先保存源测试结果，再写入证据，
已有证据不覆盖。必需上下文缺失或工件不完整时返回明确原因，不使用当前环境替代。

标准化将 AIPerf 的报告时长与成功请求窗口比较，将 Trace Replayer 的报告时长与全部
请求窗口比较，均保留一秒容差；另行检查完整请求窗口不超过任务的实测执行时长。
平均并发度使用全部请求存续时间之和除以完整请求窗口，不修改原始汇总时长和吞吐指标。
证据记录的 provenance 包含 `measurement_windows`，字段为
`reported_duration_seconds`、`reported_duration_scope`（`successful-requests` 或
`all-requests`）、`all_requests_duration_seconds` 和
`successful_requests_duration_seconds`。

### 发现端点模型

探测某个模型端点，发现它报告了哪些模型。可选的 `api_key` 以 Bearer 令牌发送，不包含在响应中。连接失败、认证失败或无效模型列表返回 HTTP 400。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/simulation/models/discover`**

    请求体：`ModelDiscoveryRequest`
    - `endpoint_url` (`string`，必填)
    - `api_key`（`string`，可选，最多 4096 个字符；仅用于本次请求；与 `model_access_token_id` 互斥——同时提供将返回 HTTP 422；为 CLI 与直接 API 调用保持向后兼容）
    - `model_access_token_id`（`string`，可选；调用方名下有效且未过期的模型访问令牌 ID——需要已认证调用方，会为本次探测签发短期委托令牌，且与 `api_key` 互斥）

    ```json
    {
      "endpoint_url": "http://127.0.0.1:38000/v1"
    }
    ```

    响应：

    ```json
    {
      "endpoint": "http://127.0.0.1:38000/v1",
      "models": [
        "Qwen/Qwen3-8B",
        "Qwen/Qwen3-8B-Instruct"
      ]
    }
    ```
  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
import asyncio

from llm_d_lens.simulation.endpoints import discover_models


async def main() -> None:
    models = await discover_models("http://127.0.0.1:38000/v1", api_key="your-model-access-token")
    print(models["endpoint"], models["models"])


asyncio.run(main())
```

### 创建模拟任务

对于 Endpoint URL 目标（`endpoint_mode != "deployment"`），服务在保存或调度任务之前，
会使用提供的 `api_key` 检查 `/v1/models`。校验失败返回 HTTP 400；直接调用 Python
接口时抛出 `SimulationConfigurationError`。手动填写模型名称不能绕过此检查。
绑定部署的 Model Service 任务仍使用集群执行路径。

创建一个模拟（Simulation）任务，对目标模型端点回放某个跟踪数据集。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/simulation/tasks`**

    请求体：`SimulationTaskCreateRequest`
    - `name`, `description`, `scenario`, `backend`, `endpoint_mode`
    - `cluster_session_id`, `endpoint_namespace`, `endpoint_service`, `endpoint_deployment_execution_id`, `endpoint_cluster_id`, `endpoint_cluster_name`, `endpoint_deployment_name`
    - `model_service_group_id` (`string`，可选) — 用于指定一个已发布、持续进行健康探测的
      模型服务（Model Service），而非原始的部署执行实例。设置该字段后，后端会将其解析为该
      分组当前活跃成员及其已发布名称，并强制将 `endpoint_mode` 设为 `"deployment"`，
      覆盖任何传入的 `endpoint_deployment_execution_id`/`model_name`。需要提供 `model_access_token_id` 或 `api_key`。
    - `model_access_token_id` (`string`，可选) — 调用方名下有效且未过期的模型访问令牌 ID。需要已认证调用方，会在任务执行时签发新的短期委托令牌（原始密钥绝不持久化），且与 `api_key` 互斥（同时提供将返回 HTTP 422）。
    - `api_key` (`string`，可选) — 原始模型访问令牌；与 `model_access_token_id` 互斥，为 CLI 与直接 API 调用保持向后兼容。当设置了 `model_service_group_id` 时，必须提供 `model_access_token_id` 或 `api_key` 之一。
    - `endpoint_url`, `model_name`, `trace_dataset`, `trace_path`
    - `duration_seconds`、`scale_factor`、`trace_start_seconds`、`trace_end_seconds`、`trace_timeout_seconds`、`stream`（AIPerf 要求 `stream: true`）
    - `fixed_schedule`（`boolean`，可选，默认 `true`）：对于 AIPerf 后端，`true` 表示按轨迹时间戳回放（Fixed Schedule），`false` 表示通过 `--concurrency` 切换为并发槽位模式（Concurrency Slots）。文件轨迹格式（`mooncake_trace`、`bailian_trace`、`baseten_trace`、`burst_gpt_trace`）同时支持两种模式（`supports_fixed_schedule: true`、`supports_concurrency: true`）；`weka_public_dataset` 始终使用并发模式（`supports_fixed_schedule: false`、`supports_concurrency: true`）。
    - `backend`（`string`，可选，默认 `"aiperf"`）：唯一支持的执行后端。创建时传入 `"trace-replayer"` 将返回 HTTP 422，历史 `"trace-replayer"` 任务记录仍可正常读取和删除。
    - `backend_options`（`object`，可选）：支持 `random_seed`（`>= 0` 的整数，默认 `666`，通过 `--random-seed` 传递给 AIPerf）、`concurrency`（正整数 `>= 1`，当 `fixed_schedule: false` 且未指定时默认为 `1`，在所有 AIPerf 轨迹格式中均通过 `--concurrency` 传递）、`trajectory_start_min_ratio` 和 `trajectory_start_max_ratio`（`[0.0, 1.0]` 范围内的可选浮点数，需满足 `min <= max`，仅对兼容 `inferencex-agentx-mvp` 的负载生效，未设置或清空时会被省略），以及可选的 `warmup_seconds >= 0`、`e2e_slo >= 0` 与布尔值 `collect_server_telemetry`。
    - `grace_period_seconds`（`number`，可选，默认 `30.0`，范围 `0.0`–`3600.0` 秒）— 发送窗口 `duration_seconds` 结束后，等待在途请求完成排空的宽限期。

    AIPerf 始终传递 `--use-server-token-count`、`--slice-duration 1.0` 和 `--streaming`。在兼容 `inferencex-agentx-mvp` 的负载（兼容的 Weka subagent 公开数据集以及 Concurrency Slots 模式下的 `mooncake_trace`）上，还会传递 `--scenario inferencex-agentx-mvp`，并在 `duration_seconds < 900` 或使用本地 `mooncake_trace` 时附加 `--unsafe-override`。

    ```json
    {
      "name": "Trace simulation",
      "description": "Replay a chat trace against a ready deployment",
      "scenario": "chat",
    ```

### 重新运行模拟任务

对于 Endpoint URL 目标（`endpoint_mode != "deployment"`），服务在保存或调度任务之前，
会使用提供的 `api_key` 检查 `/v1/models`。校验失败返回 HTTP 400；直接调用 Python
接口时抛出 `SimulationConfigurationError`。手动填写模型名称不能绕过此检查。
绑定部署的 Model Service 任务仍使用集群执行路径。

### 使用 AI 分析模拟任务

使用已配置的外部 AI 提供商（`ai_providers`），基于脱敏后的测试后遥测、客户端 KPI、自动化诊断（forensics）以及服务端/系统指标，对模拟任务运行 AI 驱动的瓶颈诊断与调优建议。支持单轮初始诊断与多轮追问。

- **认证 / 权限**：需要 `simulation:task:read` 权限以及任务所属集群的访问权限。由于 Lens Assistant 已具备 AI 推理能力，该接口已从 MCP 工具目录中排除（`intentionalSkips`）。
- **安全 / 脱敏**：在构造提示词之前会自动脱敏任务密钥（`api_key`、URL 凭据），且提供商 API 密钥绝不会在响应或错误信息中返回或暴露。

<Tabs>
  <TabItem value="rest-api" label="REST API">
    **`POST /api/simulation/tasks/{task_id}/ai-analysis`**

    - 路径参数：`task_id`（`string`，必填）

    请求体（`application/json`，所有字段均可选）：

    | 字段 | 类型 | 说明 |
    | --- | --- | --- |
    | `provider_id` | `string \| null` | 外部 AI 提供商 ID；默认使用第一个已配置的提供商。 |
    | `model` | `string \| null` | 可选模型覆盖；默认使用该提供商配置的模型。 |
    | `question` | `string \| null` | 可选聚焦提示词或追问问题（最多 4000 个字符）。 |
    | `messages` | `array<{ role: "user" \| "assistant", content: string }>` | 用于多轮追问的历史对话轮次（最多 20 条）。 |

    响应（`200 OK`）：

    | 字段 | 类型 | 说明 |
    | --- | --- | --- |
    | `task_id` | `string` | 模拟任务 ID。 |
    | `provider_id` | `string` | 所使用的外部 AI 提供商 ID。 |
    | `provider_name` | `string` | 外部 AI 提供商显示名称。 |
    | `model` | `string` | 本次分析使用的模型名称。 |
    | `analysis` | `string` | Markdown 格式的诊断结论与调优建议。 |
    | `generated_at` | `string` | 生成分析的 ISO 8601 UTC 时间戳。 |
    | `telemetry_scope` | `string` | 纳入提示词的遥测范围（`"full_telemetry"`、`"server_and_client"`、`"client_only"`、`"server_only"` 或 `"task_summary_only"`）。 |

    错误码：
    - `400`：模拟配置无效。
    - `422`：请求体校验错误（例如 `question` 超过 4000 个字符、`messages` 超过 20 条或包含未预期的额外字段）。
    - `403`：缺少 `simulation:task:read` 权限或集群访问权限。
    - `404`：未找到模拟任务或外部 AI 提供商。
    - `409`：未配置外部 AI 提供商。
    - `502`：上游外部 AI 提供商返回错误（返回脱敏后的 `application/problem+json` 详情，`code: "ai_analysis_upstream_error"`）。
    - `504`：外部 AI 提供商请求超时。
  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
import asyncio

from llm_d_lens.simulation.models import SimulationAIAnalysisRequest
from llm_d_lens.simulation.service import analyze_task_with_ai


async def main() -> None:
    result = await analyze_task_with_ai(
        "1a2b3c4d",
        request=SimulationAIAnalysisRequest(
            question="分析 TTFT 瓶颈并给出 vLLM 与 llm-d 调优参数建议。",
        ),
    )
    print(result.model, result.analysis)


asyncio.run(main())
```
