## 后端 API

Lens Assistant 由 `server/mcp/` 下的 Node MCP 服务器支撑，而不是由一个专门的 FastAPI 路由器支撑。`server/server.js` 通过 `app.use(mcpRouter)` 直接挂载 `mcpRouter`，而 `server/mcp/router.ts` 在 `/api/mcp` 上暴露无状态的 Streamable HTTP 端点。

### 发送一次无状态的 MCP 请求

通过创建一个全新的 `McpServer`、建立连接并处理请求体，来处理一次无状态的 Streamable HTTP MCP 请求。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/mcp`**

请求：

- Content type：`application/json`
- Body：一个 MCP JSON-RPC 请求对象。在无状态模式下，Lens 会为每个请求创建一个全新的服务器，因此不需要会话 ID。
- 常见的请求形态包括 `initialize`、`tools/list` 和 `tools/call`。

`tools/call` 请求示例：

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "method": "tools/call",
  "params": {
    "name": "list_simulation_backends",
    "arguments": {}
  }
}
```

响应：

成功的响应使用 MCP JSON-RPC 结果信封格式。对于工具调用，Lens 的 MCP 服务器会返回 `content` 块，其 `text` 字段包含经过 JSON 字符串化的 Lens REST 结果。

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\n  \"items\": []\n}"
      }
    ]
  }
}
```

如果在 SDK 发送响应之前发生了未处理的服务器错误，Lens 会返回：

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32603,
    "message": "Internal server error"
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

该端点是一个 Node.js MCP 处理程序，而不是一个 Python 函数——对于 `/api/mcp` 传输本身没有直接对应的 Python 调用。请改为直接调用其背后的 Python 领域逻辑；例如，一个与部署相关的 MCP 工具可以复用[部署](/api-reference/modules/deployments)页面上展示的同一个部署辅助函数：

```python
from llm_d_lens.deploy.standard_kubernetes_service import (
    StandardKubernetesServiceRequest,
    build_standard_kubernetes_service_configuration,
)

request = StandardKubernetesServiceRequest(
    model="meta-llama/Llama-3.1-8B-Instruct",
    deployment_name="assistant-backed-deploy",
    cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
    replicas=1,
    tensor_parallel_size=1,
)
configuration = build_standard_kubernetes_service_configuration(request)
print(configuration.checksum)
```

  </TabItem>
</Tabs>

### 无状态模式下不支持 GET

返回 `405 Method not allowed.`，因为无状态模式不支持 Streamable HTTP 的 GET 流。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`GET /api/mcp`**

请求：

该端点没有请求体。在 Lens 的无状态 MCP 模式下，Streamable HTTP 的 GET 流被特意禁用。

响应：

返回一个 HTTP 状态码为 `405` 的 JSON-RPC 错误负载。

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

该端点是一个 Node.js MCP 传输防护逻辑，而不是一个 Python 函数——没有直接对应的 Python 调用。对于你实际想调用的工具，请使用其背后的 Python 模块，具体可参见下方的[MCP 工具调用的内容](#what-the-mcp-tools-call)。

  </TabItem>
</Tabs>

### 无状态模式下不支持 DELETE

返回 `405 Method not allowed.`，因为无状态模式不支持终止会话。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`DELETE /api/mcp`**

请求：

该端点没有请求体。Lens 不会在请求之间保留 MCP 会话，因此也就没有服务器端会话可以终止。

响应：

返回一个 HTTP 状态码为 `405` 的 JSON-RPC 错误负载。

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

该端点是一个 Node.js MCP 传输防护逻辑，而不是一个 Python 函数——没有直接对应的 Python 调用。如果需要 Python 自动化，请跳过 MCP，直接调用其背后的 Lens 领域模块。

  </TabItem>
</Tabs>

工具目录由两部分组成：`server/mcp/tools.ts` 包含 138 个自动生成的工具，`server/mcp/specialTools.ts` 包含 25 个手写工具。自动生成的那一半由 `node scripts/generate-mcp-tools.mjs` 根据 `llm_d_lens` FastAPI 的 OpenAPI schema 生成，而手写的那一半涵盖了组合型或 Node 支撑的路由。这些处理程序都是对 Lens 自身 REST API 的瘦封装：`server/mcp/internal.ts` 通过 `internalRequest(...)` 将请求转发到环回地址的 `/api/...` 路径上。

### 查询公开基准证据 {/* #query-public-benchmark-evidence */}

自动生成的 `query_public_benchmark_rag` 工具虽然使用 POST，但属于只读工具。
它原样传递 REST 请求体，并在 MCP 文本块中返回相同的 `QueryResponse` JSON。
它不是部署规划器工具，也不是语料导入接口。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/benchmark-rag/query`**

要求真实已认证调用者在 GLOBAL 作用域拥有 `benchmark-rag:query:read`。
默认仅 GLOBAL 管理员拥有此权限，其他角色需要显式 GLOBAL 授权；
集群授权、匿名身份及禁用认证模式的 `system` 身份均不符合要求。
浏览器 Cookie 调用还必须满足标准 CSRF 策略。MCP 调用者还需要
`mcp:tool:invoke` 或 `playground:chat:use`。
Node 使用内部 HMAC 签名转发真实调用者，不使用服务身份或参数中指定的身份。

```json
{
  "question": "What published throughput measurements match this workload?",
  "intent": "numeric",
  "filters": {
    "origins": ["prism:public-snapshot"],
    "metric": "throughput",
    "statistic": "mean",
    "unit": "tokens/s",
    "workload": {"batch_size": 8},
    "value_min": "100.000000001",
    "normalized": false
  },
  "limit": 10
}
```

`question` 为必填字段（1–2048 字符）。`intent` 支持默认的 `auto` 以及
`numeric`、`comparison`、`definition`、`figure`；`limit` 默认为 10（范围 1–50）。
请求和筛选器中的额外字段会被拒绝；不支持任意 SQL。
筛选字段包括 `origins`、`source_revision`、`source_path`、`record_id`、
`experiment_id`、`model`、`hardware`、`runtime`、`metric`、`statistic`、`unit`、
结构化 JSON `workload` 和 `series`、`value_min`、`value_max` 以及 `normalized`。
数值范围必须显式指定 `unit`，下限不得超过上限。使用 Decimal 字符串保留精度。
归一化检索必须显式启用；响应保留原始单位，另行提供归一化数值、单位和规则，
不会隐式混合不可比较的测量值。
问题规划使用有界、确定性的关键词规则，而非通用自然语言处理或 LLM 推理。
显式结构化筛选条件具有权威性；不要假设自由文本问题会隐含额外的模型、硬件、
指标或单位筛选条件。
自动关键词规则仅支持英语。其他语言的问题通过显式 `intent` 和结构化
`filters` 获得支持，而非依赖自动语言理解。

响应包含 `contract: "benchmark-rag.query.v1"`、解析后的 `intent`、
`question`、`filters`、`status`（`answered`、`partial`、`abstained`）、`answer`、
`evidence`、`matched_items`、`truncated`、`abstentions` 和 `warnings`。
响应固定报告 `generation_mode: "deterministic"` 和 `internal_branch_enabled: false`。
证据包含 Decimal 字符串数值、单位和统计量、实验上下文、可选归一化数值，
以及图表覆盖情况和缺失序列信息。图表证据还可以包含 `related_experiments`
（默认为空），仅展示显式关联的已发布场景及其实验上下文，不猜测身份。
每个引用标明来源、版本、路径、SHA-256、
归档制品 URI、来源指针、标题路径和已发布清单。
拒答是明确的领域结果；上游授权、传输或响应损坏则返回 MCP `isError: true`，
不包含证据，也不会伪装为成功的空响应。

仅允许已批准并发布的公开来源：`prism:public-snapshot`、
`https://github.com/VincyZhang/llm-d` 和
`https://github.com/llm-d/llm-d-benchmark.git`。必须同时恢复已发布语料及其不可变
来源归档，仅有数据库记录并不足够。不会查询内部或私有记录，也没有 Agentic 生成路径。
尚未完成真实部署验证。

  </TabItem>

from llm_d_lens.benchmark_rag.query_contracts import QueryRequest, QueryResponse

request = QueryRequest.model_validate({

    "intent": "numeric",
    "filters": {"metric": "throughput", "unit": "tokens/s", "value_min": "100.1"},
    "limit": 10,
})
body = request.model_dump(mode="json")
# Send body to the authenticated REST endpoint; validate its successful JSON:
# result = QueryResponse.model_validate(response_json)

DTO 验证不是授权：请使用已认证 REST 会话，或通过真实调用者解析后的 principal
访问共享服务。不要伪造 `system` 或管理员身份，也不要绕过 GLOBAL 权限检查。

具有代表性的自动生成 MCP 工具会直接转发到已有的 Python 支撑的 REST 模块：

| MCP 工具 | 转发的 HTTP 端点 | 底层模块 |
| --- | --- | --- |
| `create_standard_vllm_deployment_run` | `POST /api/v1/deployments/standard-vllm-runs` | [部署](/api-reference/modules/deployments)，经由 `llm_d_lens/deploy/router.py` |
| `list_deployment_executions` | `GET /api/v1/deployments/executions` | [部署](/api-reference/modules/deployments)，经由 `llm_d_lens/deploy/router.py` |
| `create_evaluate_run` | `POST /api/v1/evaluate/runs` | [评估](/api-reference/modules/evaluation)，经由 `llm_d_lens/evaluation/router.py` |
| `get_cluster_stack_status` | `GET /api/v1/monitoring/cluster-stack/status` | [可观测性](/api-reference/modules/observability)，经由 `llm_d_lens/monitoring/cluster_stack/router.py` |
| `list_simulation_tasks` | `GET /api/simulation/tasks` | [模拟](/api-reference/modules/simulation)，经由 `llm_d_lens/simulation/router.py` |

如果你需要的是 Python 而不是 MCP 传输，请直接调用其背后的 Python 领域逻辑，而不是通过 `/api/mcp`。例如，MCP 工具 `create_standard_vllm_deployment_run` 最终调用的是与 `POST /api/v1/deployments/standard-vllm-runs` 相同的部署辅助函数：

```python
from llm_d_lens.deploy.standard_kubernetes_service import (
    StandardKubernetesServiceRequest,
    build_standard_kubernetes_service_configuration,
)

request = StandardKubernetesServiceRequest(
    model="meta-llama/Llama-3.1-8B-Instruct",
    deployment_name="assistant-backed-deploy",
    cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
    replicas=1,
    tensor_parallel_size=1,
)
configuration = build_standard_kubernetes_service_configuration(request)

print(configuration.checksum)
```

完整的请求/响应 schema 请参见 FastAPI 的 OpenAPI schema（使用 `npm run docs:api` 重新生成）。
