## 后端 API

Lens Assistant 使用统一 Python 服务中的 `llm_d_lens.mcp.router`。其 FastAPI 路由通过官方 MCP Python SDK 在 `/api/mcp` 提供无状态 Streamable HTTP 端点。

候选工具声明并转发 `workload.concurrency` 或 `workload.request_rate`
（正数且互斥的负载目标）。兼容 API 的输入／输出 token 长度缺省为
4000／1000，与 Agentic 规划一致。预期的校验提示和无可行候选时的重试行为
保持不变。其他 AIC 服务错误返回状态码 `400` 及通用响应
`{ "error": "AIC candidate search failed" }`，内部异常详情仅记录在服务端日志中。

### 发送一次无状态的 MCP 请求

使用新的 SDK 服务器和传输管理器处理一次无状态 Streamable HTTP MCP 请求。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/mcp`**

请求：

- Content type：`application/json`
- Body：一个 MCP JSON-RPC 请求对象。在无状态模式下，Lens 会为每个请求创建一个全新的服务器，因此不需要会话 ID。
- 常见的请求形态包括 `initialize`、`tools/list` 和 `tools/call`。

`tools/call` 请求示例：

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "method": "tools/call",
  "params": {
    "name": "list_simulation_backends",
    "arguments": {}
  }
}
```

响应：

成功的响应使用 MCP JSON-RPC 结果信封格式。对于工具调用，Lens 的 MCP 服务器会返回 `content` 块，其 `text` 字段包含经过 JSON 字符串化的 Lens REST 结果。

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\n  \"items\": []\n}"
      }
    ]
  }
}
```

如果在 SDK 发送响应之前发生了未处理的服务器错误，Lens 会返回：

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32603,
    "message": "Internal server error"
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

使用官方 MCP Python 客户端进行传输调用。查询元数据时，`llm_d_lens.mcp.catalog.catalog(app)` 返回与端点相同的工具定义。进程内领域集成可复用[部署](/api-reference/modules/deployments)页面上的辅助函数：

```python

    StandardKubernetesServiceRequest,
    build_standard_kubernetes_service_configuration,
)

request = StandardKubernetesServiceRequest(
    model="meta-llama/Llama-3.1-8B-Instruct",
    deployment_name="assistant-backed-deploy",
    cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
    replicas=1,
    tensor_parallel_size=1,
)
configuration = build_standard_kubernetes_service_configuration(request)
print(configuration.checksum)
```

</Tabs>

返回 `405 Method not allowed.`，因为无状态模式不支持 Streamable HTTP 的 GET 流。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`GET /api/mcp`**

请求：

该端点没有请求体。在 Lens 的无状态 MCP 模式下，Streamable HTTP 的 GET 流被特意禁用。

响应：

返回一个 HTTP 状态码为 `405` 的 JSON-RPC 错误负载。

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

Python 路由在无状态模式下拒绝 GET 流。请使用 MCP 客户端的 POST 传输，或直接调用底层 Python 领域逻辑，参见[MCP 工具调用的内容](#what-the-mcp-tools-call)。

  </TabItem>
</Tabs>

### 无状态模式下不支持 DELETE

返回 `405 Method not allowed.`，因为无状态模式不支持终止会话。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`DELETE /api/mcp`**

请求：

该端点没有请求体。Lens 不会在请求之间保留 MCP 会话，因此也就没有服务器端会话可以终止。

响应：

返回一个 HTTP 状态码为 `405` 的 JSON-RPC 错误负载。

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32000,
    "message": "Method not allowed."
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

Python 路由不保留传输会话，因此拒绝终止会话的请求。使用 Python MCP 客户端时请设置 `terminate_on_close=False`。

  </TabItem>
</Tabs>

`llm_d_lens.mcp.catalog` 根据 FastAPI OpenAPI schema 生成工具，并与 `llm_d_lens/mcp/definitions.json` 中的 25 个特殊工具定义合并。`node scripts/generate-mcp-tools.mjs --check` 校验该目录，不再生成 Node 文件。`llm_d_lens.mcp.tools` 通过进程内 ASGI 客户端调用规范 REST 路由，保留认证、CSRF 和资源范围检查。

### 搜索公开 RAG 文档 {/* #search-public-rag-documents */}

只读工具 `search_public_rag_documents` 检索已发布的公开文档段落，不读取内部实验或诊断日志。
当前提供默认全文检索、显式选择的独立向量检索，以及带持久构建协调的可选混合检索。
后端提供灰度控制及脱敏资源/构建状态；连接凭据及固定本地模型仍由运维配置。
工程能力可用不等于混合相关性或上线门槛已经通过。
既有数值查询 `/benchmark-rag/query` 合同不变。

RAG 优先交付后端，最终通过 Agentic Deploy 集成。已有独立 Document Search 前端保留，
但不再更新维护，也不作为验收入口；不再安排独立 RAG 前端交付。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/benchmark-rag/search`**

要求真实已认证调用者在 GLOBAL 作用域拥有 `benchmark-rag:query:read`，
浏览器请求遵循标准 CSRF 策略。

```json
{
  "question": "prefix cache",
  "origins": ["https://github.com/llm-d/llm-d"],
  "limit": 10
}
```

`question` 非空且不超过 2,048 个字符；`limit` 为 1–50。
`mode` 默认为 `"lexical"`；传入 `"vector"` 可选择独立影子向量索引，
传入 `"hybrid"` 则在同一个固定物理向量构建上并行执行全文和向量检索。
混合模式最多返回 10 个父段落、同一来源文档最多 3 个，即使 `limit` 更大也不突破此上限。
混合模式默认启用 `query_enhancement: true`。固定的 `controlled-v1` 策略保留原始问题及技术标识符，
追加最多八条命中词表的英文术语，并对明确提及的来源给予融合后父证据分数 1.25 倍软权重。
其他来源仍可竞争，不是来源过滤或 LLM 改写。传入 `"query_enhancement": false` 可恢复原先未增强的混合行为。
显式全文/向量模式及默认全文模式保持不变，不启用精排或意图路由。
向量查询还必须满足包含 `query: ` 前缀和特殊 tokens 的 512-token 预算，超限明确失败，不截断。
省略 `origins` 时采用已批准来源白名单，而不是任意 URL。
客户端不能指定索引名、查询 DSL 或内部数据范围。

响应合同为 `benchmark-rag.search.v1`，包含 `retrieval_mode:
"opensearch_lexical"`、`"opensearch_vector"` 或 `"hybrid"`、`retrieval_build_id`、`index_stale`、`affected_origins`、
`candidate_count`、`excluded_count`、`truncated` 和 `results`。
每项结果包括原始段落、标题、章节、证据/块 ID、对应分支排名（`lexical_rank` 或 `vector_rank`）、
分数和既有 `Citation` 结构。向量响应包含 `embedding_contract` 及相对父段落的
`chunk_start` / `chunk_end` 字符偏移。重复表头和代码围栏只用于编码，不伪造进引用正文；
多个子块按父证据去重。
混合结果还包含 `matched_branches`、各路可用排名及 `fusion_score`（RRF 常数 60，
不直接相加 BM25 和向量得分）。同一父证据在每路最多贡献一次，以稳定证据/块 ID 打破平局。
混合请求另返回 `query_enhancement`，包含 `policy`、`enabled`、`effective_question`、
`added_terms` 和 `source_hints`，即使降级为全文也保留此信息；显式全文/向量请求该字段为 `null`。
软权重在 RRF 后、既有文件上限及 Top-10 选择前应用；关闭增强时不追加术语、不施加来源权重。
`branch_status` 记录各路状态及候选数，只有显式降级时 `degraded_reason` 才非空。
`refill_count` 最多为 2：每路首取 50 条，再最多补取 75 和 75 条，累计最多 200 个候选。
先过滤、按父证据去重并应用单篇上限，再判断是否补取。
`candidate_count` 是两路候选数之和（同一块被两路召回时计两次）；
`excluded_count` 统计不同的被排除或去重块，不把同一跨路身份重复计数。
服务在返回前通过 OpenSearch 文档仓库校验发布成员，并核验保留的原始正文及偏移。
检索 alias 是唯一活动权威，不查询 SQL 文档成员。分数表示文本相关性，不证明硬件兼容或性能达标。

过期来源被排除并列入 `affected_origins`，明确返回 `rebuild_required`，需重建索引才能检索该来源新内容。
缺少配置、OpenSearch 不可用、分片结果不完整或索引响应损坏时返回 503，不伪装成正常空结果。
原文归档损坏同样返回 503；成功检索但无匹配则正常返回空结果。不自动切换 PostgreSQL。
向量模式下，模型缺失、模型与索引合同不一致、向量非法或缓存损坏同样返回 503，
不静默退回全文检索。混合模式在 embedding/向量失败时返回经过权威验证的全文结果，
`retrieval_mode` 为 `"opensearch_lexical"`，`degraded_reason` 为 `"vector_unavailable"`，
合同不匹配时为 `"embedding_contract_mismatch"`。Hybrid 模型就绪阶段使用独立、有界的
8 秒预算，复用共享缓存编码器；查询 embedding 加每页向量检索仍有 5 秒截止时间，
冷模型初始化不再占用查询预算。上层调用仍可施加更紧的总截止时间。
降级日志仅记录脱敏的失败阶段/类别，不包含原始异常或来源正文。
来源成员完整性校验在单次请求内使用 `_mget` 批量读取，每批最多 256 条；
保留完整 envelope/hash/identity 校验，并在返回前重新检查来源 head，
不引入跨请求持久权威缓存。Hybrid 遵守调用方结果数量上限（最多 50），
包括 Agentic 的二十个候选重排池，不再静默限制为十条。
活动构建损坏、全文失败、权威存储不可用或源字节损坏仍明确失败，绝不以未经验证的向量结果替代。
近邻不证明问题有可支持答案：混合/向量检索仍可能为无依据问题返回相关文本，不声称已经实现校准拒答。
增强后的问题仍受同一 embedding token 预算约束，不截断；预算失败遵循上述显式混合降级合同。
开发集收益不等于留出集、性能或上线验收通过。

  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
from llm_d_lens.benchmark_rag.indexing import PublicRagIndexBuilder
from llm_d_lens.benchmark_rag.embedding import configured_encoder
from llm_d_lens.benchmark_rag.opensearch_evidence_search import (
    OpenSearchEvidenceSearchRepository,
)
from llm_d_lens.benchmark_rag.search import PublicRagSearchService
from llm_d_lens.benchmark_rag.search_contracts import PublicSearchRequest

repository = OpenSearchEvidenceSearchRepository("http://127.0.0.1:9200")
# Administrative operation on already approved and published source evidence:
build = await PublicRagIndexBuilder(repository).build(
    ("https://github.com/llm-d/llm-d",)
)
response = await PublicRagSearchService(repository).search(
    PublicSearchRequest(question="prefix cache"), principal
)
# Separate administrative S2 build; never switches the lexical alias:
vector_build = await PublicRagIndexBuilder(repository).build(
    ("https://github.com/llm-d/llm-d",), encoder=configured_encoder()
)
vector_response = await PublicRagSearchService(repository).search(
    PublicSearchRequest(question="prefix cache", mode="vector"), principal
)
hybrid_response = await PublicRagSearchService(repository).search(
    PublicSearchRequest(question="prefix cache", mode="hybrid"), principal
)
unenhanced_response = await PublicRagSearchService(repository).search(
    PublicSearchRequest(question="prefix cache", mode="hybrid", query_enhancement=False),
    principal,
)
```

显式构建文档检索索引时，可复用上面的投影 `repository`，
并注入同步元数据仓库：

```python
from llm_d_lens.benchmark_rag.document_lifecycle import DocumentLifecycle
from llm_d_lens.benchmark_rag.document_repository import DocumentRepository
from llm_d_lens.benchmark_rag.sources import SourceArchive

metadata = DocumentRepository.from_environment()
build = await PublicRagIndexBuilder(
    repository,
    dao=metadata,
    archive=SourceArchive(),
    lifecycle=DocumentLifecycle(metadata),
).build(("https://github.com/llm-d/llm-d",))
```

构建器默认使用 OpenSearch 文档生命周期。
来源暂存及发布是独立前置步骤，不由这次检索重建执行。
既有混合发布通过已验证的外部成员描述符迁移，不复制实验事实正文。
既有 `admin.py rebuild` 仍是 Prism SQL 导入操作；
OpenSearch 检索重建使用下述独立 `search-rebuild` 命令。

`principal` 必须来自实际授权调用者，不能来自请求文本。
`build()` 校验完整来源段落，写入新物理索引，检查逐条 bulk 结果、数量及来源代次，
再切换 `public-rag-active`，不会先清空活动索引。
全文模式保留完整章节正文。S2 生成保留精确字符偏移的 token-aware 子块，在向量索引中保留全文字段，
完整验证后只更新独立的 `public-rag-vector-shadow` alias。编码采用固定
`intfloat/multilingual-e5-small` revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`，
384 维、attention-mask mean pooling、L2 归一化及 cosine 相似度。
前缀与重复结构上下文均计入 512-token 预算，不启用截断。默认每批 8 个输入、2 个 CPU 线程，
每个编码器串行推理。

可选依赖 `apps/backend[rag-embedding]` 提供 Transformers、safetensors 和 PyTorch；
本地 CPU 部署应先安装 CPU 版 PyTorch wheel。经批准的固定版本模型及 tokenizer 文件需单独下载到配置路径。
运行时离线加载、仅使用 safetensors、不执行远程代码，并核验固定内容哈希。
官方模型卡声明 MIT，但该模型仓库没有独立 LICENSE 文件。

向量缓存位于 Lens cache 根目录的 `benchmark-rag/embeddings/`，键包含输入、模型 revision 和编码/分块合同。
缓存损坏明确失败；管理员可用 `encoder.encode(inputs, rebuild_cache=True)` 重建已知输入。
缓存可丢弃，不是权威证据备份。`DocumentLifecycle` 在 `public-rag-management-v1`
保留构建历史及重建请求。查询为整次请求固定物理索引和模型，对无法解释的 alias/mapping 偏差 fail closed。
不再使用 SQL 构建记录、SQL 活动指针或已移除的 SQL 协调器。
检索重建是管理操作，不是请求期间触发的昂贵副作用。

#### 受控运行与管理 {/* #controlled-runtime-and-operations */}

本轮目标是支持 Agentic 受控接入的后端，不是独立 RAG 产品发布，也不新增独立前端。
为兼容已有调用，直接文档搜索默认保持启用；Agentic 文档消费独立控制，默认**关闭**。
这些运行控制不代表质量或性能验收通过。连接凭据及固定本地模型仍由运维配置。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`GET /api/v1/benchmark-rag/runtime`**（MCP：`get_public_rag_runtime`）要求 GLOBAL
范围的 `benchmark-rag:runtime:read`，返回：

- 持久运行策略及 `generation`。
- OpenSearch/API key 是否配置、固定 embedding 合同、`model_files_present` 及 writer 模式。
  模型文件存在不等于已校验哈希或已就绪；不会回显 URL、密钥或本地路径。
- 每种模式的活动/最新构建、最新任务状态、预期/实际数量、来源滞后和重建请求。
  `missing`、`unavailable`、`recovery_required` 明确区分；
  未配置服务返回 `opensearch_configured: false` 和空 `builds`，不代表搜索成功。
- 按模式/结果统计的进程内搜索次数、滞后次数、总/最大耗时（毫秒）。
  重启后重置，不跨 worker 汇总；可采集 `rag_public_search` 结构化日志进行外部监控。
  问题、段落及调用者身份不作为指标标签。

**`PUT /api/v1/benchmark-rag/runtime`** 要求 GLOBAL 范围的
`benchmark-rag:runtime:configure` 及标准浏览器 CSRF。
两个专用权限默认仅赋给内置全局管理员；自定义角色需要显式授权，查询权限不能管理灰度。
此管理写操作有意不暴露为 MCP 工具。请求替换完整设置；省略的字段取默认值：

```json
{
  "expected_generation": 0,
  "search_enabled": true,
  "advanced_search_enabled": true,
  "agentic_mode": "shadow",
  "agentic_user_ids": ["approved-user-id"],
  "agentic_search_mode": "lexical",
  "agentic_query_enhancement": true
}
```

`agentic_mode` 支持 `disabled`、`shadow`、`enabled`。
影子和启用模式必须配置非空、稳定用户 ID 白名单，管理员不自动绕过。
白名单不授予查询权限。Agentic 默认 lexical；hybrid 必须显式选择，不启用精排。
影子检索不得影响模型提示词、排序或最终方案。
更新必须传入上次读取的 `expected_generation`；过期写入返回 409。
关闭后续 Agentic 文档消费时，替换为
`{"expected_generation": CURRENT_GENERATION, "agentic_mode": "disabled"}`。

`search_enabled: false` 关闭文档搜索（包括旧 definition 适配器），不关闭数值/实验 SQL 检索。
`advanced_search_enabled: false` 关闭 vector/hybrid，保留 lexical。
被关闭的搜索明确返回 503，不伪装为空结果，也不切回 SQL。
开关对后续请求生效；紧急恢复前必须排空在途工作。
策略更新不下载模型、不注册来源、不发布索引、不修改权限，也不代表质量验收。

  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
from llm_d_lens.benchmark_rag.runtime import (
    RuntimeUpdate, load_runtime_policy, update_runtime_policy,
)

current = load_runtime_policy()
updated = update_runtime_policy(RuntimeUpdate(
    expected_generation=current.generation,
    agentic_mode="shadow",
    agentic_user_ids=("approved-user-id",),
))
```

这些是可信管理代码使用的 Python 函数，不能代替 API 的授权检查。
策略位于 `LENS_DATA_DIR/public-rag/runtime.json`，权限 0600；

存储记录和响应 `evidence[].statistic` 保留原始 null；数值回答标注
`mean (default; source statistic unreported)`。generator/planner 测量使用
`statistic: "mean"`、`statistic_original: null` 和 `statistic_basis: "default_mean"`

数值问题会提取明确的统计量，例如 `p99`、`99th percentile`、
`mean`/`average`/`avg` 和 `median`（`p50`），以及 `Llama-3.1-70B`、

公共与已授权内部 SQL 模型筛选对入库和请求两端生成别名：去除首尾空白并转为小写，
保留完整名称、取最后一个 `/` 后的名称、将完整名称中所有 `/` 替换为 `-`，去重后按集合交集匹配。
例如 `Publisher/Falcon-7B` 可匹配 `falcon-7b` 或 `publisher-falcon-7b`，不维护注册表。
不同组织但尾名相同的名称可能命中，这只是名称检索，不证明唯一身份。

**Agentic 规划实验排序（2026-10-28）。**
此内部服务合同不改变上述通用查询端点。规划在已授权、已发布且模型/硬件精确匹配的
实验全集中，按实验/配置与 series 聚合并排序，再应用内部 `experiment_limit=50`，
不是先取 50 条 measurement 再排序。只有同一实验/配置及同一 series 的测量可以组合。
显式负载相似度及覆盖率优先，较低的有效实测延迟其次；默认零值不算显式负载。
不按距 SLO 的距离、最小违约量或 SLO 状态排序。

| 显式负载 | 显式延迟目标 | 排序 |
| --- | --- | --- |
| 有 | 有 | 先负载匹配，再按目标指定的精确 metric/statistic 比较较低实测延迟 |
| 无 | 有 | 按目标指定的精确 metric/statistic 比较较低实测延迟，不施加负载惩罚 |
| 有 | 无 | 先负载匹配，再按精确 metric/statistic 分组使用可用延迟 |
| 无 | 无 | 按精确 metric/statistic 分组使用可用延迟，不施加负载惩罚 |

目标限定可比指标/统计口径，不形成距阈值的分数。null statistic 按上述策略默认 mean，
显式百分位保持独立。多指标只在可用 metric/statistic 集合相同的案例间
使用 Pareto 支配：所有可比指标不更差且至少一项更好。保留互有优劣及不同覆盖集合，
不把 TTFT、TPOT、端到端延迟相加，不混合 mean/p99；覆盖率和未知状态必须显式保留。
无观测不等于零延迟。有效延迟须为正、有限且单位与具体指标兼容，
只允许有依据的兼容换算；零错误计数仍是有效上下文，不是延迟。
历史低延迟不能证明当前部署满足 SLO。

排序元数据包含 `queue="ranked"|"fallback"` 和 `fallback_reason`。
当且仅当没有可比较的实测负载字段（`workload_similarity=null`，包括未请求负载）
且请求/可比指标轴上没有有效延迟时，才进入 fallback，原因为
`no_comparable_workload_or_valid_latency`；ranked 案例的原因为 null。
实测相似度为零仍是有效比较，不会仅因缺少延迟而进入 fallback。
SQL 与 Python 对未知负载分数均保留 null。案例模型上下文、审计和 UI 必须明确标注
fallback 参考，不能称为低延迟；查询摘要使用中性的实验参考描述。
实验参考检索与确定性候选评分和服务端 SLO 评估保持分离。

候选 bundle 和后续预算选择保留负载/延迟排序，质量及新鲜度只作其后的细化，
不重新引入 SLO 状态优先。规划证据保留选中实验的完整相关测量，
受显式安全上限约束并报告省略项，因此可超过 50 个 measurement 封装；
模型上下文另限最多 10 个完整案例、20 个段落和 16,000 字节序列化证据。
公开 `QueryRequest.limit` 仍按 measurement/证据封装计数，范围 1–50；
`experiment_limit` 不是公开请求字段。拟议规划响应可选诊断为
`matched_experiments`、`returned_experiments`、`experiment_limit`，不改变通用端点计数或行为。
有限范围回归及已认证真实服务创建/细化验收通过，详见
[验证范围](/architecture/agentic-planning-evidence#scoped-ranking-validation-2026-10-28)。
明确标注的 H100 覆盖 A100 模拟不是物理硬件/SLO 认证；未批准或部署，S3/S4 门槛仍未完成。

Agentic 配置案例保留可空的 `workload_similarity` 与 `evidence_coverage`；
`workload_match_status` 区分 `not_requested`、`unknown`、`compared`，未指定负载不是零匹配或拒绝依据。
测量 `quality` 区分有限正值性能、非正性能、缺失/非有限数值、缺失单位及计数/负载上下文；
原值、统计口径和单位不变，零错误计数仍是有效上下文。质量排序不等于当前 SLO 确定性。
案例预算先保留负载/延迟排序，再优先保留有信息量的完整实验，与完整文档动态共享容量；
最终请求窗口裁剪保留该排序，并优先保留已排序案例而非定性文字。
generator/planner 投影只包含测量、单位、统计口径、序列、实验条件、适用性、排序队列/回退标记和稳定短引用
（`c:`、`m:`、`d:`）。原始值/单位为主，仅在换算不同时附加 `normalized`；
文档只包含标题、完整段落和短引用。完整哈希、归档定位、导入/索引/embedding 元数据和检索诊断仅留后端，
通过审计 `model_reference_map` 关联。模型返回引用先还原原始 ID，再做授权及分类型校验；
配置中的 `run_id`、`source_path` 和 `source_info.file_identifier` 保留为不可信来源线索，
包括 scorer/prefix-cache 技术名，而不是已核验的 serving 参数；冗长元数据和原始 URL 仍省略。
未知、已裁剪、类型错误或碰撞的引用明确失败。裁剪同步刷新映射，不重新编号剩余引用。
预算只计算模型投影；原始实验条件、测量和审计引用不截断。

拒答是明确的领域结果；上游授权、传输或响应损坏则返回 MCP `isError: true`，
不包含证据，也不会伪装为成功的空响应。

固定版本证据缺失或损坏（包括格式错误的归档清单）时，REST 返回 HTTP 503，
错误码为 `rag_evidence_unavailable`，而不是拒答或部分回答。
恢复未经改动的有效清单与来源字节后，后续查询即可恢复，无需重新索引。

仅允许已批准并发布的公开来源：`prism:public-snapshot`、
`https://github.com/llm-d/llm-d` 和
`https://github.com/llm-d/llm-d-benchmark.git`。必须同时恢复已发布语料及其不可变
来源归档，仅有数据库记录并不足够。这些来源属于公开分支；显式启用的内部分支
仅检索已授权的存储评估测量值，而不是任意私有数据。两个分支都没有 Agentic 生成路径。
本机单实例验收不代表生产、多 Pod 或跨集群部署通过；须另行验证目标运行环境及共享证据存储。

解析器版本使用 `guide-evidence-v1`。快照 `revision` 为

即完整受审文件/哈希映射的 64 字符 SHA-256，**不是**分支、日期或拼接文件的哈希。
`files` 必须按路径排序。尽量将 `SourceApproval.allowed_paths` 缩小到具体受审
文章路径，并保留明确的审核人、审批引用和许可引用。

审核快照后，可按以下方式准备首次手动刷新：

```python
import json
from pathlib import Path

from llm_d_lens.benchmark_rag.publication_contracts import (
    InventoryFile, PinnedInventory, SourceApproval, content_digest,
)
from llm_d_lens.benchmark_rag.refresh import RagRefreshService, RefreshPlan

# publication is RagPublicationService backed by the OpenSearch document repository.
# Load these operator-reviewed files; do not discover or approve URLs here.
approval = SourceApproval.model_validate_json(Path("/secure/rag/web-approval.json").read_bytes())
files = tuple(
    InventoryFile.model_validate(value)
    for value in json.loads(Path("/secure/rag/web-files.json").read_text())
)
origin = "https://llm-d.ai"
publication.register_source(origin, approval)
head = publication.dao.head(origin)
inventory = PinnedInventory(
    origin_id=origin,
    revision=content_digest({file.path: file.sha256 for file in files}),
    complete=True,
    files=files,
)
plan = RefreshPlan(
    review_reference="operator review of article relevance, rights, bytes and passage counts",
    approval=approval,
    inventory=inventory,
    expected_counts={"source": 1, "passage": 3},  # Replace with reviewed exact counts.
    base_generation=head.state.generation,
    base_manifest_id=head.registry.published_manifest_id,
)
report = RagRefreshService(publication).run(plan, Path("/secure/rag/web-snapshot"))
```

也可将同一计划保存为 JSON，交给 `admin refresh --plan ...`，并指定
`--source /secure/rag/web-snapshot --trigger manual`。首次刷新前必须登记来源。
不会发起 HTTP 请求、采集 RSS、跟随链接或启用定时任务。缺失/额外受审范围文件、
符号链接、哈希变化、Markdown 无效或计数错误均不能替换当前发布。
重复执行、回滚、撤回和备份/恢复沿用现有生命周期。

网页快照**仅发布 source 和 passage**。原文 URL 保留在 `source_url` 和引用的
`source_pointer.source_url` 中；偏移针对保留的 Markdown 快照，不是实时 HTML。
正文、表格和外部图片链接只作上下文，不是已验证数值测量，也不会重建图中数据点。

固定数值基线保持不变，也不对新增文章作背书。
