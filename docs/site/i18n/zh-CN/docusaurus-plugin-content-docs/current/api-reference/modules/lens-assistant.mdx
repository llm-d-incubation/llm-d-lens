## 模块用途

Lens Assistant 是使用 Lens MCP 工具目录的内置聊天界面。当你希望自己的 MCP
客户端、IDE 智能体或脚本查看和操作 Lens 时，也使用同一个端点。它是基于
Streamable HTTP 的无状态 JSON-RPC 2.0 端点：每个请求相互独立，工具调用读取
Lens REST 的当前状态。

## 快速开始

`POST /api/v1/mcp` 需要已登录会话，并拥有 `mcp:tool:invoke` 或
`playground:chat:use` 权限。凭据可通过 Bearer token 或 `prism_session` cookie 发送。

MCP 传输没有 Python SDK 封装。SDK 标签页展示同一 Lens 操作的类型化进程内调用。

<Tabs>
  <TabItem value="rest-api" label="REST API">

```bash
curl -s "http://127.0.0.1:3000/api/v1/mcp" \
  -H "Authorization: Bearer $LENS_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {"name": "list_clusters", "arguments": {}}
  }'
```

成功的工具调用返回 JSON-RPC `result`，其中包含 `content` 块。`text` 字段包含
经过 JSON 字符串化的 REST 结果。

</Tabs>

## 常见任务

### 查看可用工具

工具名称会随 Lens 模块演进。向服务端查询当前工具目录：

```bash
curl -s "http://127.0.0.1:3000/api/v1/mcp" \
  -H "Authorization: Bearer $LENS_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc": "2.0", "id": 2, "method": "tools/list"}'
```

每个工具会报告输入字段和风险等级（`read`、`write` 或 `approve`）。

## 端点

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/mcp` | 一次无状态 MCP JSON-RPC 请求（`initialize`、`tools/list` 或 `tools/call`）。 |
| `GET` | `/api/v1/mcp` | 返回 `405`；无状态模式没有服务端到客户端的流。 |
| `DELETE` | `/api/v1/mcp` | 返回 `405`；没有可终止的服务端会话。 |

## 错误与限制

- 缺少或无效的认证返回 `401`。会话缺少 `mcp:tool:invoke` 或
  `playground:chat:use` 时返回 `403`。
- 未知工具名或无效参数会返回工具错误结果。使用 `tools/list` 确认当前名称和字段。
- `GET` 和 `DELETE` 返回 `405` 及 JSON-RPC 错误负载。
- 请求之间不共享会话。每个请求都必须携带凭据。
- 在 Lens Assistant 中，破坏性的 `approve` 工具需要明确的人工确认；智能体不应自动批准。
