## 后端 API

Lens Assistant 由 `server/mcp/` 下的 Node MCP 服务器支撑，而不是由一个专门的 FastAPI 路由器支撑。`server/server.js` 通过 `app.use(mcpRouter)` 直接挂载 `mcpRouter`，而 `server/mcp/router.ts` 在 `/api/mcp` 上暴露无状态的 Streamable HTTP 端点。

### 发送一次无状态的 MCP 请求

通过创建一个全新的 `McpServer`、建立连接并处理请求体，来处理一次无状态的 Streamable HTTP MCP 请求。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/mcp`**

请求：

- Content type：`application/json`
- Body：一个 MCP JSON-RPC 请求对象。在无状态模式下，Lens 会为每个请求创建一个全新的服务器，因此不需要会话 ID。
- 常见的请求形态包括 `initialize`、`tools/list` 和 `tools/call`。

`tools/call` 请求示例：

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "method": "tools/call",
  "params": {
    "name": "list_simulation_backends",
    "arguments": {}
  }
}
```

响应：

成功的响应使用 MCP JSON-RPC 结果信封格式。对于工具调用，Lens 的 MCP 服务器会返回 `content` 块，其 `text` 字段包含经过 JSON 字符串化的 Lens REST 结果。

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\n  \"items\": []\n}"
      }
    ]
  }
}
```

如果在 SDK 发送响应之前发生了未处理的服务器错误，Lens 会返回：

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32603,
    "message": "Internal server error"
  },
  "id": null
}
```

  </TabItem>
  <TabItem value="python-api" label="Python API">

该端点是一个 Node.js MCP 处理程序，而不是一个 Python 函数——对于 `/api/mcp` 传输本身没有直接对应的 Python 调用。请改为直接调用其背后的 Python 领域逻辑；例如，一个与部署相关的 MCP 工具可以复用[部署](/api-reference/modules/deployments)页面上展示的同一个部署辅助函数：

    replicas=1,
    tensor_parallel_size=1,

工具目录由两部分组成：`server/mcp/tools.ts` 包含 138 个自动生成的工具，`server/mcp/specialTools.ts` 包含 25 个手写工具。自动生成的那一半由 `node scripts/generate-mcp-tools.mjs` 根据 `llm_d_lens` FastAPI 的 OpenAPI schema 生成，而手写的那一半涵盖了组合型或 Node 支撑的路由。这些处理程序都是对 Lens 自身 REST API 的瘦封装：`server/mcp/internal.ts` 通过 `internalRequest(...)` 将请求转发到环回地址的 `/api/...` 路径上。

### 查询公开基准证据 {/* #query-public-benchmark-evidence */}

自动生成的 `query_public_benchmark_rag` 工具虽然使用 POST，但属于只读工具。
为保持兼容，即使调用者选择启用已授权的内部分支，端点和 operation ID 也保留公开查询名称。
它原样传递 REST 请求体，并在 MCP 文本块中返回相同的 `QueryResponse` JSON。
它不是部署规划器工具，也不是语料导入接口。

<Tabs>
  <TabItem value="rest-api" label="REST API">

**`POST /api/v1/benchmark-rag/query`**

要求真实已认证调用者在 GLOBAL 作用域拥有 `benchmark-rag:query:read`。
默认仅 GLOBAL 管理员拥有此权限，其他角色需要显式 GLOBAL 授权；
集群授权、匿名身份及禁用认证模式的 `system` 身份均不符合要求。
浏览器 Cookie 调用还必须满足标准 CSRF 策略。MCP 调用者还需要
`mcp:tool:invoke` 或 `playground:chat:use`。
Node 使用内部 HMAC 签名转发真实调用者，不使用服务身份或参数中指定的身份。

```json
{
  "question": "What published throughput measurements match this workload?",
  "intent": "numeric",
  "filters": {
    "origins": ["prism:public-snapshot"],
    "metric": "throughput",
    "statistic": "mean",
    "unit": "tokens/s",
    "workload": {"batch_size": 8},
    "value_min": "100.000000001",
    "normalized": false
  },
  "limit": 10,
  "include_internal": false
}
```

`question` 为必填字段（1–2048 字符）。`intent` 支持默认的 `auto` 以及
`numeric`、`comparison`、`definition`、`figure`；`limit` 默认为 10（范围 1–50，
限制两个分支在验证合并后返回的证据封装总数）。
`include_internal` 是布尔值，默认为 `false`；未显式启用时，不访问内部数据、
计数或身份检查。设为 `true` 后仍须拥有原有 GLOBAL RAG 授权；内部记录还必须
通过所属评估上下文的现有 `evaluate:run:read` 策略。缺失、已删除或无法验证的
所属对象即使对管理员也会排除；显式启用不等于绕过授权。
请求和筛选器中的额外字段会被拒绝；不支持任意 SQL。
筛选字段包括 `origins`、`source_revision`、`source_path`、`record_id`、
`experiment_id`、`model`、`hardware`、`runtime`、`metric`、`statistic`、`unit`、
结构化 JSON `workload` 和 `series`、`value_min`、`value_max` 以及 `normalized`。
数值范围必须显式指定 `unit`，下限不得超过上限。使用 Decimal 字符串保留精度。
归一化检索必须显式启用；响应保留原始单位，另行提供归一化数值、单位和规则，
不会隐式混合不可比较的测量值。
问题规划使用有界、确定性的关键词规则，而非通用自然语言处理或 LLM 推理。
数值问题会提取明确的统计量，例如 `p99`、`99th percentile`、
`mean`/`average`/`avg` 和 `median`（`p50`），以及 `Llama-3.1-70B`、
`org/model` 等模型标识。单词名称可以使用 `for Falcon on H100`；
多词名称需要 `model "Custom Model"` 这样的标签。
引号中的名称按单个标识处理，包括其中的版本数字或类似仓库路径的片段。
模型标签为空或缺少名称时会在检索前拒答。
识别出的模型和统计量必须与显式筛选条件一致；冲突会返回验证错误，而不是覆盖。
多个统计量、多个模型或含糊的模型描述会在检索前以 `statistic_scope_required`
或 `model_scope_required` 拒答。此类比较应分别提交精确查询。
所要求的模型或统计量不存在时返回 `no_exact_match`，不会换成其他模型或用均值代替 p99。
其他条件仍需显式结构化筛选；这些有界规则不保证理解任意自由文本约束。
使用 `intent: "auto"` 且未指定测量范围时，`What is TTFT?`、
`Define request latency` 和指标定义比较会检索文档段落。
显式 `filters.metric` 属于测量范围：仅带此筛选条件的简短问题保持数值意图，
要求补充实验条件，而不是转去检索文档。
测量问题同时识别 `TTFT`/`time to first token` 和
`TPOT`/`time per output token`。显式 `intent` 不会被自动规则覆盖。
自动关键词规则仅支持英语。其他语言的问题通过显式 `intent` 和结构化
`filters` 获得支持，而非依赖自动语言理解。

响应包含 `contract: "benchmark-rag.query.v1"`、解析后的 `intent`、
`question`、`filters`、`status`（`answered`、`partial`、`abstained`）、`answer`、
`evidence`、`matched_items`、`returned_observations`、`truncated`、`abstentions` 和 `warnings`。
响应固定报告 `generation_mode: "deterministic"`。
`internal_branch_enabled` 默认为 `false`，表示请求是否显式启用内部分支，
不表示是否有内部记录获授权或返回。`matched_items` 统计候选公开索引项与已授权
内部基准记录的数量之和，不代表独立实验数量或精确的去重运行数量。
`returned_observations` 统计**验证合并后**实际返回的指标／证据封装；
`truncated` 明确报告因总 `limit` 而省略的结果。
证据包含 Decimal 字符串数值、单位和统计量、实验上下文、可选归一化数值，
以及图表覆盖情况和缺失序列信息。图表证据还可以包含 `related_experiments`
（默认为空），仅展示显式关联的已发布场景及其实验上下文，不猜测身份。
公开引用标明来源、版本、路径、SHA-256、
归档制品 URI、来源指针、标题路径和已发布清单。

证据 `origin` 为 `public`、`agentic` 或 `public_and_agentic`；内部测量的
`evidence_type` 为 `agentic_measurement`。`AgenticCitation` 包含
`origin_id: "agentic:evaluate"`、`evidence_type: "agentic_measurement"`、
`benchmark_id`、`evaluate_run_id`、`cluster_id`、`resource_uri`、`record_sha256`、
`metric_field`、`record_timestamp`、`access_scope: "owning_evaluation"` 和
`numeric_precision: "stored_float"`。内部归一化指标按 Float 存储，因此响应的
Decimal 字符串表示已存储浮点数，**不是**原始来源数值 token 的精确值；
公开原始字节的精度不受影响。

证据文本、来源指针字符串及实验上下文 JSON 保留原始空白，包括 JSON 键与表格单元格。
字符偏移和数值子串范围均指向未裁剪的原始字符串。请求侧的问题与过滤字符串仍独立裁剪。

只有固定版本的公开原始 JSON 中实际存在规范 `evaluate:<UUID>` 标识，且指标、
统计量、单位和数值一致，才能合并公开与内部证据。模型或工作负载相似不能证明身份。
验证成功后只返回一个封装，保留公开 `citation` 和内部 `corroborating_citations`，
并标注 `identity_verification: "canonical_evaluate_run_and_metric"`。
其他情况下 `corroborating_citations` 默认为空，`identity_verification` 可省略或为 null。
无法确定的重叠保持独立；未授权记录不能影响重叠身份，也不能通过计数或引用泄露。
历史写入器在 `evaluate:<id>` 中使用八字符模拟任务 ID，这些记录缺少可验证的
规范评估所属对象，因此有意省略；查询不会改写这些记录或更改规划器。

拒答是明确的领域结果；上游授权、传输或响应损坏则返回 MCP `isError: true`，
不包含证据，也不会伪装为成功的空响应。

固定版本证据缺失或损坏（包括格式错误的归档清单）时，REST 返回 HTTP 503，
错误码为 `rag_evidence_unavailable`，而不是拒答或部分回答。
恢复未经改动的有效清单与来源字节后，后续查询即可恢复，无需重新索引。

仅允许已批准并发布的公开来源：`prism:public-snapshot`、
`https://github.com/VincyZhang/llm-d` 和
`https://github.com/llm-d/llm-d-benchmark.git`。必须同时恢复已发布语料及其不可变
来源归档，仅有数据库记录并不足够。这些来源属于公开分支；显式启用的内部分支
仅检索已授权的存储评估测量值，而不是任意私有数据。两个分支都没有 Agentic 生成路径。
本机单实例验收不代表生产、多 Pod 或跨集群部署通过；须另行验证目标运行环境及共享证据存储。

  </TabItem>

### 管理已审核的基准刷新 {/* #administer-reviewed-benchmark-refreshes */}

刷新证据是目标机器本地管理操作，**不是** REST 端点或 MCP 工具。
查询工具保持只读，不能审批来源、刷新或回滚发布。

<Tabs>
  <TabItem value="rest-api" label="REST / MCP">

不开放写入端点。由可信管理员或管理任务执行：

```bash
export PYTHONPATH=apps/backend/src
python -m llm_d_lens.benchmark_rag.admin refresh \
  --schema public --data-dir /srv/lens-data \
  --plan /secure/rag/approved-plan.json --source /srv/sources/llm-d-benchmark \
  --trigger commit --event-revision "$REVIEWED_COMMIT"
```

cron/管理 Job 使用 `--trigger periodic`，不传 `--event-revision`。
两种触发共用同一固定 commit 的审批计划，不追踪分支 HEAD。
Prism 快照仅允许 `--trigger manual`。
通过安全环境配置 `LLM_D_BENCH_DATABASE_URL`，不要将凭据写入参数或计划。
代码不会自动安装定时任务或真实集群 Job。

  </TabItem>
  <TabItem value="python-api" label="Python API">

```python
import os
from pathlib import Path

from llm_d_lens.benchmark_rag.publication import RagPublicationService
from llm_d_lens.benchmark_rag.refresh import RagRefreshService, RefreshPlan
from llm_d_lens.db.dao.rag_transfer import transfer_database

# LENS_DATA_DIR must name the same persistent archive used by query instances.
plan = RefreshPlan.model_validate_json(Path("/secure/rag/approved-plan.json").read_bytes())
with transfer_database(os.environ["LLM_D_BENCH_DATABASE_URL"], schema="public") as dao:
    dao.prepare()
    report = RagRefreshService(RagPublicationService(dao=dao)).run(
        plan, Path("/srv/sources/llm-d-benchmark"), trigger="periodic"
    )
    print(report.model_dump_json())
```

`RefreshPlan.model_json_schema()` 提供严格计划契约。需审核来源审批、完整文件清单与
哈希、逐类型计数、基础 manifest/generation、允许的触发方式以及全部图覆盖。
新指南数值版本还需通过 `metadata_review_reference` 确认现有适配器的模型、
硬件和工作负载等假设在该版本仍成立；新增 schema/表布局仍需更新适配器。
空清单必须显式设置 `allow_empty: true`。计划不能扩大来源/路径白名单、
重新启用来源，或从 simulation ID 猜测归属。

  </TabItem>
</Tabs>

成功输出 `published` 或 `unchanged` JSON 报告，包含计划/清单哈希、审批引用、
版本、文件及逐类型计数、时间戳、发布 ID 和 generation。
失败返回退出码 1，并在 stderr 输出失败 JSON，不伪装为空导入成功。
请持久保留任务 stdout/stderr 记录尝试历史。
`admin status --origin ...` 读取当前来源 head/历史；
`admin rollback --origin ... --manifest-id ... --expected-generation ...`
显式恢复曾发布的 manifest，两者均需相同的 schema/data-dir 参数。
旧引用仍由保留字节支撑，新回答仅查询当前发布成员。
过期计划、并发修改、不完整清单或分页、解析/哈希/计数错误均不能替换当前发布。
直接重复审核任务为 no-op；旧周期任务不能撤销回滚或访问策略变更。

### 评估固定证据基线 {/* #evaluate-the-fixed-evidence-baseline */}

这是只读验收 API，不是 REST/MCP 工具或 LLM 评委。
`llm_d_lens.benchmark_rag.evaluation` 提供版本化的 `EvaluationSuite`、
`EvaluationCase`、`EvaluationReport` 及：

```python
report = run_evaluation(
    suite,
    execute=execute_authorized_case,
    verify_evidence=verify_retained_source_evidence,
)
```

执行必须使用真实调用者权限。必传的独立 verifier 对每个主引用和佐证引用核验
保留原始字节或已授权所属记录，返回问题码 tuple，仅有效证据返回空 tuple。
runner 检查精确 Decimal 观测、确定性回答的测量行、条件/拒答、来源/类型、
上限、计数及泄漏预期。非预期异常会抛出，预期拒绝必须实际产生相应领域错误。
全部用例必须通过，不能用跳过真实来源验收代替通过；不评价任意自由文本模型输出。

在仓库根目录回放固定公开及内部基线：

```bash
LENS_RAG_BASELINE_REPORT_DIR=/secure/acceptance/rag-v1 \
PYTHONPATH=apps/backend/src .venv/bin/python -m pytest \
  apps/backend/tests/unit/db/test_rag_public_baseline.py \
  apps/backend/tests/unit/db/test_rag_internal_baseline.py \
  apps/backend/tests/unit/benchmark_rag/test_evaluation.py -q
```

公开用例需要另行准备固定三来源输入；内部用例在隔离库创建真实 owner/Evaluate
fixture，不修复或放宽历史 simulation 入库。可选报告包含固定来源版本/清单哈希、用例集哈希、时间戳、用例结果和问题码，
不包含原始私有响应。`verified_citations` 包含双来源佐证引用，
`numeric_observations` 统计数值封装。

基线通过**不意味着**自动启用额外来源。新仓库/数据集、GCS/GIQ 来源或论文集合仍需独立
可见性/许可/权限审批、固定 origin/path/revision 清单、适配器及原始字节回归、
manifest 发布、回滚与撤回测试。论文默认仅作解释，除非测量得到独立验证。
证据中发现的 URL 不会自行获准；v1 白名单保持不变。
