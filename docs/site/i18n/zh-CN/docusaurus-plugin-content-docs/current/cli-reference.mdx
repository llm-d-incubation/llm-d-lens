## `hack/lens-local.sh`（本地源码安装与服务管理）

| 命令 | 用途 |
| --- | --- |
| `hack/lens-local.sh check` | 在不启动任何服务的情况下校验环境。 |
| `hack/lens-local.sh start` | 准备依赖并在后台启动 Vite 和统一 Python 后端。日志位于 `$LENS_LOG_DIR/dev/`，默认是 `~/.local/state/lens/logs/dev/`。会先校验复用地图和 MCP 目录。 |
| `hack/lens-local.sh stop` | 停止由本脚本启动的所有服务。 |
| `hack/lens-local.sh restart` | 启用目标节点模式时先检查节点，再准备依赖并校验复用地图，全部通过后才停止并重启服务。 |
| `hack/lens-local.sh status` | 显示哪些服务正在运行及其 PID。 |
| `hack/lens-local.sh clean [-y\|--yes] [--cache\|--hard\|--all]` | 停止服务并删除应用数据和日志。`--cache` 还会删除源码 checkout 和 benchmark venv；`--hard` 还会删除开发 venv、工具链、TLS 证书、node_modules 和构建产物；`--all` 同时删除两者。 |
| `hack/lens-local.sh install-node` | 将受支持的 Node.js 安装到 `.dev-tools/`（当系统的 Node 缺失或版本过旧时会自动使用）。 |

端口可以通过 `FRONTEND_PORT`（默认 `5173`）和 `BACKEND_PORT`（默认 `3000`）配置。
`SERVER_PORT` 仍作为 Python 端口的后备值。旧的 `restart server` 目标会选择 `backend`；
从旧版三进程结构切换时请使用 `restart all`。参见[环境变量](/environment-variables)。

### 目标节点与 kubeconfig

`check`、`start` 和 `restart` 支持 `--target-node NODE` 与
`--kubeconfig FILE`。命令行参数优先于 `TARGET_NODE` 和 `KUBECONFIG`。
kubeconfig 参数指定单个文件，相对路径以执行命令时所在目录为基准；
环境变量 `KUBECONFIG` 中的文件列表保持原样。

```bash
hack/lens-local.sh restart --target-node node-a --kubeconfig "$HOME/.kube/config"
TARGET_NODE=node-a KUBECONFIG="$HOME/.kube/config" hack/lens-local.sh check
```

不读取目标节点专用配置文件，也不保存上次的目标节点；每次启动时传参，
或在 shell 中导出 `TARGET_NODE`。未指定目标节点时，普通启动不访问 Kubernetes，
也不要求安装 kubectl/jq。指定目标节点后，需要 kubectl、jq，以及 `LLM_D_ROOT`
指向的、包含 `guides/` 的源码目录；在停止已有服务之前检查节点是否可访问、
处于 Ready 状态且未被 cordon。这不保证某个具体工作负载的资源请求、
亲和性或污点容忍条件一定能够满足。

节点名称会导出为后端已有的 `PRISM_K8S_TARGET_NODE`。
未设置 `TARGET_NODE` 时仍兼容该变量。未设置 `KUBECONFIG` 时使用 Kubernetes
正常的配置查找方式。`stop`、`status`、`clean` 和 `install-node` 不检查目标节点，
也不接受目标节点相关参数。

硬件发现由后端和硬件 profile 负责，启动器不再自动发现 Intel 专用的 PCI 白名单；
显式设置的 `PRISM_GPU_PCI_ALLOWLIST` 会保留。启动器也不再注入部署运行时默认值：
未覆盖时由后端使用命名空间前缀 `llmd-`、900 秒就绪超时、300 秒命令超时，
并保留失败的命名空间。显式设置的 `LLM_D_BENCH_*` 参数仍由原有消费者支持。

## `lensctl.sh`（已安装的部署）

由 Ubuntu 安装程序写入安装目录：

| 命令 | 用途 |
| --- | --- |
| `lensctl.sh start` | 启动已安装部署的服务。 |
| `lensctl.sh status` | 显示服务是否正在运行。 |
| `lensctl.sh stop` | 停止已安装部署的服务。 |
| `lensctl.sh uninstall` | 卸载；`--keep-data` / `--purge` 控制数据，`--keep-db` / `--purge-db` 控制内置数据库。 |

## `LensInstaller-Ubuntu-x86_64-online.sh`

从 main 或包含在线安装器的发布标签下载；脚本自行选择内嵌版本。
只能安装到新建或空目录，不支持覆盖版本或就地升级。

| 标志 | 用途 |
| --- | --- |
| `--install-dir DIR` | 安装位置（默认 `$HOME/llm-d-lens`）。 |
| `--app-port PORT` | Web 应用/API 端口（默认 `3000`）。 |
| `--backend-port PORT` | `--app-port` 的旧版别名；两者配置同一个监听端口。 |
| `--silent` | 仅使用默认值/标志进行非交互式安装。 |
| `--no-https` | 提供纯 HTTP 服务，而不是自动 HTTPS。 |
| `--no-start` | 安装但不启动服务。 |
| `--db-mode embedded\|external` | 使用内置数据库还是外部数据库。 |
| `--no-apt` | 缺少系统依赖时直接失败，不使用 apt 安装。 |
| `-h`、`--help` | 显示所有选项。 |

完整用法参见[安装](/installation)和[升级](/upgrade)。

## `node hack/generate-mcp-tools.mjs`

根据当前 REST schema 校验 Python MCP 目录，遇到非预期跳过的操作时失败。
`--check` 执行相同校验，`--json` 导出目录，不再生成 Node 服务端文件。
本地 `start`/`restart` 和安装后的启动器直接校验同一目录。
纯 Python 等价命令为 `.venv/bin/python -m llm_d_lens.mcp.catalog`。
