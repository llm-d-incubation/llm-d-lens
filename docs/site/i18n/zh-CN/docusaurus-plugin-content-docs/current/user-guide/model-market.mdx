打开 **Model Catalog（模型目录）**，选择模型并部署到集群。
首次使用建议选择 **Manual（手动）**模式。

使用分类标签旁的紧凑 **Search models（搜索模型）**输入框，按模型名称、发布者、仓库、模型类型、分类或精度筛选。
搜索不区分大小写，并与所选分类共同生效；输入多个词时，每个词都必须匹配。
模型数量会随输入更新。点击 **Clear filters（清空筛选）**可同时重置搜索和分类。

## 选择部署模式

在 **One-click deployment** 中，**Model Catalog** 返回按钮位于部署配置上方的内容区，
不再放在全局顶栏中。

| 模式 | 适用目标 |
| --- | --- |
| **Manual（手动）** | 选择 llm-d Guide 模板、配置资源或检查生成的 YAML |
| **Agentic（智能体，实验性）** | 让 Lens 根据负载和性能目标推荐配置 |

部署设置会使用模型卡片的 **Context（上下文）**元数据作为初始最大上下文长度，
Agentic 推荐也使用该值。例如，Qwen3-0.6B 使用 `40960`，而不是 `4096`。
仅当卡片未提供上下文时，才使用 `4096` 默认值。Standard 和 Agentic 请求接受
`256` 到 `1048576` 个 token，不会静默缩短卡片值；资源和模型兼容性检查仍然生效。
已有计划和部署不会被自动修改。

## 创建手动部署

1. 打开 **Model Catalog**，用 **Model categories（模型分类）**筛选，点击模型卡片。
2. 在 **One-click deployment（一键部署）**中填写 **Deployment name（部署名称）**，选择就绪的 **Cluster（集群）**。
3. 选择包含该模型的 **Model cache storage（模型缓存存储）**，等待显示 **This model is ready in the selected cache.（模型已在所选缓存中就绪）**。**Manual** 模式下模型缓存存储是可选的。
4. **Mode（模式）**保持 **Manual**，点击 **Configure deployment（配置部署）**。检查预填的模型和部署设置；需要修改时点击 **Edit setup（编辑设置）**。
5. 检查 **Runtime image（运行镜像）**、**Replicas（副本数）**和 **TP（每副本使用的加速器数量）**。
6. 在 **Guide template（方案模板）**中选择 **Guide** 和 **Accelerator（加速器）**。不确定如何选择时，参阅[选择评测方案](/evaluation/guides)。
7. 使用 P/D 或分层缓存方案时，从列表中选择变体。首次运行先保留提供的默认配置。
8. 点击 **Generate YAML（生成 YAML）**。如果当前可用卡不足但物理卡总量足够，查看 Pending 提示后点击 **Continue & generate（继续并生成）**；如果物理卡总量也不足，请减少副本数 / TP。
9. 检查 **Generated deployable configuration（生成的部署配置）**，修正标出的错误后点击 **Deploy（部署）**。
10. 在 **Deployments（部署）**页等待 **Ready（就绪）**。部署会保留，不会运行基准测试；不再使用时请手动停止或清理。

生成 YAML 同时支持设备插件和 DRA 集群。缺少 DRA 设备明细时，仍可根据已注册的
Kubernetes 加速器资源识别硬件变体；容量和配置校验保持生效。

点击 **Back to model card（返回模型卡片）**可返回所选模型。
如需测量性能，参阅[运行评估](/user-guide/evaluation)。

没有集群或缓存时，先[添加集群](/user-guide/clusters)、[创建缓存存储](/user-guide/storage)，
再[下载模型](/user-guide/model-cache)。所选缓存中没有该模型时，先下载到该卷，再回来部署。

选中模型后，点击 **Manage model cache（管理模型缓存）**，可直接在 **Model cache（模型缓存）**中打开 **Download a model（下载模型）**。
所选集群、Hugging Face 仓库 ID 和存储卷会自动填入，也可以修改。关闭弹窗后，点击 **Back to model（返回模型）**，
即可回到先前选中的模型，并保留部署设置。使用浏览器的返回按钮也会保留模型选择。返回时，存储选项和模型下载状态会刷新。

只有在准备了与所选硬件兼容的镜像时，才修改运行镜像。
更换集群或 Guide 源码后，重新检查变体选择。生成时出现资源或网络错误，先解决提示的问题再部署。

## 获取 AI 辅助推荐

1. 打开模型，填写部署名称，选择集群和缓存存储。
2. 将 **Mode** 改为 **Agentic**。
3. 选择 **Use case（使用场景）**和 **GPU capacity for planning（规划可用 GPU）**，检查负载及性能目标。**Mean input tokens per request（平均输入长度，ISL）**、**Mean output tokens per request（平均输出长度，OSL）**、**TTFT SLO (ms)** 和 **TPOT SLO (ms)** 初始为空。占位示例 `4000`、`1000`、`2000` 和 `30` 不会作为要求提交，也不会将平均输入长度复制成 P95；不提供端到端延迟输入框。在规划提示词中，TPOT 也支持每 token 单位：`TPOT <= 20 ms/token` 与 `TPOT <= 0.02 s/token` 均表示每 token 20 毫秒。
4. **AI provider** 可保持 **Default (no external AI provider)（不使用外部 AI）**，也可选择已配置的提供方辅助排序。
5. 可选：展开 **Preference（偏好）**，用英文填写，例如 `use fewer GPU resources`（少用 GPU）或 `prefer prefix cache`（优先前缀缓存）。
6. 点击 **Generate recommendation（生成推荐）**。
7. 在 **Validated alternatives（已验证的备选方案）**中展开 **Why this option（选择理由）**，比较资源用量和性能估算。
8. 点击所选方案的 **Deploy recommendation（部署推荐方案）**，到**部署**页查看启动状态。

Agentic 生成与重新计算推荐时跳过模型文件是否存在、下载是否就绪的检查，
但仍需选择合法的已注册模型缓存存储卷。可以先规划、后下载模型；
批准部署时才检查模型是否已在所选存储中就绪，并解析当前凭据策略。
模型缺失或下载未完成会阻止部署，不再阻止生成推荐。Manual 和 Standard 部署检查保持不变。

可选：生成推荐前展开 **Pod placement（Pod 放置）**，选择部署运行的位置。

Agentic 生成和选择使用 `optimized-baseline`，不再提供直接部署的 `baseline-vllm`，
包括内置回退和 AIC 推荐；历史 direct-vLLM 配置也不会重新进入候选集。
已有计划和手动 Standard vLLM 部署不受影响。

按负载估算容量时，填写 **Concurrent requests（并发请求数）**或 **Request rate (QPS)（每秒请求数）**之一，不能同时填写。
两项均为可选，不预填目标值。提供其中一项时调用 AIC 原生推荐模式；两项留空时保留固定 GPU 数搜索。
Lens 会按所选 GPU 容量和部署约束校验推荐的精确拓扑。联合输入、预测不可用、容量不足或延迟 SLO 无法满足时，
Agentic 页面会明确显示原因和处理建议，不会悄悄回退为没有负载目标的预测。

要调整推荐，在备选方案下方输入新的偏好，点击 **Recalculate selection（重新计算）**。
不配置外部 AI 提供方也可以使用此操作。

每次生成或重新计算推荐时，Lens 都会先按所选模型查询已发布的公开 SQL 实验，
再进行 AIC 规划。配置外部 AI 提供方时，适用的公共实测证据在候选生成和排序中优先于
AIC 估算；公共证据缺失或不适用时，AIC 作为补充。实时资源硬约束和明确的操作偏好仍然有效，
不同硬件、负载、运行时版本、拓扑或指标统计口径的结果不能直接互换。

公共检索还会按目标集群实时探测的加速卡型号过滤，而不是按集群名称判断。
厂商修饰及分隔符差异可以匹配，但显存大小和 PCIe/SXM 型号仍严格区分。
未知或混合硬件会明确提示；没有匹配结果时不会回退到其他硬件家族。

公开基准记录的运行时后端缺失、为空或为 `unknown` 时，检索和规划上下文默认按 `vllm` 处理。
明确标注的其他后端保持原值，不匹配 vLLM 计划。该资料库默认规则不会推断运行时版本，
也不会改写原始证据。

在 **Decision evidence（决策证据）** 中查看 **Public SQL measured observations**，
可检查检索状态、原始数值与单位、来源路径、版本和校验和。无匹配、查询失败或缺少已认证的全局
`benchmark-rag:query:read` 权限时，页面会明确提示，并继续使用原有证据规划。
包含公共 RAG 观测数据的计划仍要求相同的读取权限。
没有外部 AI 时，检索结果仅作为上下文保留，不会自动转换为确定性性能预测，也不会改写显示的 SLO 判断。

内部 SQL 实验单独列出。Agentic 规划使用 SQL 证据，
不要求安装文档搜索服务或独立搜索页。

使用外部 AI 提供方时，生成和选择阶段的提示词都会将完整偏好放在规划上下文之前。
在平台与硬件有效性约束内，单卡、不做 P/D 分离等明确要求优先于候选多样性和性能建议。
这是对 AI 的指引，不代表系统能通过通用自然语言解析器强制校验所有要求。

新的规划审计会保留完整偏好，以及每次实际 AI 请求与响应，包括工具上下文和重试。
不记录提供方认证头和 API Key。请将审计文件作为私有数据保护；
旧决策无法补回此前没有记录的交互。

**AI score（AI 评分）**只用于方案排序，不是性能实测结果，也不是成功概率。
显示 **SLO not met（未满足性能目标）**时，应调整目标或资源。
部署后通过[评估](/user-guide/evaluation)测量真实表现。

## 调整可选设置

| 目标 | 操作位置 |
| --- | --- |
| 修改上下文长度或批处理参数 | Manual 配置编辑器中的 **Advanced settings（高级设置）** |
| 启用工具调用 | 开启 **Enable automatic tool choice**，再选择 **Tool call parser** |
| 使用单独的代理 | **Deployment environment（部署环境）** |
| 修改副本或加速器数量 | **Replicas** 和 **Tensor parallelism** / **TP** |

启动时提示 KV 缓存容量不足，可在新配置中降低最大上下文长度或增加资源。

使用 NVIDIA 设备插件时，生成的模型服务 Pod 会选择硬件访问模式声明的 `nvidia` RuntimeClass，
但不会覆盖源码中已显式指定的 RuntimeClass。此规则适用于 baseline、optimized baseline、
P/D 分离、分层前缀缓存和精确前缀缓存路由。目标集群必须已注册该 RuntimeClass。当节点默认容器运行时为 `runc` 时，
仅申请 GPU 资源并不能完成设备注入。若 vLLM 报告 `Failed to infer device type`，
请检查 Pod 的 RuntimeClass 和设备访问；`VLLM_LOGGING_LEVEL=DEBUG` 只会增加诊断日志。
Lens 更新不会改写已有 Pod 或已保存清单；请重新生成并创建部署以应用修复。

出现 **Your role cannot create deployments.（当前角色无法创建部署）**时，请管理员授予目标集群的部署权限。
仍可点击 **Open Deployments** 查看有权访问的部署。
