在左侧导航中打开 **Custom Deployment**。此页面独立于部署列表；
读取配置需要 `configuration:artifact:read`，生成需要
`guide:plan:execute` 和 `configuration:artifact:render`，
保存及部署还需要对应的保存和运行权限。

## 查看推理流程

3D 视图将请求流程、服务组件和 Kubernetes 资源分层显示。
方块表示组件，菱形表示可选优化。点击菱形或 **Tiers** 中的对应行
可启用或关闭优化，并自动加入其依赖；点击方块只会查看和聚焦组件，
悬停不会更改选择。可以拖动旋转、右键拖动平移、滚轮缩放。
无法使用 WebGL 时，仍可通过键盘访问 **Tiers** 列表。
此视图展示的是计划中的资源，并非实时集群监控。

## 配置并生成

1. 选择目标集群和已就绪、已同步的 **Downloaded model**。
   模型及存储必须属于同一集群。
2. 点击要启用的优化，或通过可搜索的 **Guides** 选择指南。
   在信息卡片中打开 **Configure parameters** 调整该资源的参数。
   必需的依赖不能单独移除；互斥的部署变体需要明确选择。
3. 在 **Deployment settings** 中检查命名空间、目标集群、
   可选的运行时镜像覆盖和准入验证选项。
4. 点击 **Generate** 查看校验结果并下载生成的资源。
   准入验证采用服务端 dry-run，不会应用部署。

生成资源包含来源提交、部署 YAML 和 provenance 信息。模型缓存以
只读方式挂载；生成时会再次验证缓存和存储的就绪状态及集群归属。
生成成功不代表运行就绪，仍需检查目标集群的 CRD、存储、网络和模型访问。

点击 **Deploy** 可通过现有配置及部署运行 API 发布生成的 YAML。
部署会显示在[部署列表](/user-guide/deployments)中，provider 为
`source-composition`。清理部署仅移除该运行的命名空间，
不会删除原始模型缓存所在的命名空间。

如需查看来源目录、预览及生成接口的字段和验证规则，
参阅[源码组合 API](/api-reference/source-composition)。
