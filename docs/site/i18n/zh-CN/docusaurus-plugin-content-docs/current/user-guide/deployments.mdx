打开 **Deployments（部署）**，确认模型是否就绪、排查失败原因或管理已有部署。

## 打开部署创建流程

1. 在左侧导航中，打开**部署**。
2. 在页面标题栏，点击**创建**。
3. 按[创建部署](/user-guide/model-market)完成操作。提交后，新部署会出现在列表中。

在 **Agentic** 模式下，TTFT、TPOT SLO 和每请求输入/输出 token 数（ISL/OSL）
默认均未设置，留空提交时为 `null`。灰色示例占位文字仅供参考，不会作为默认值提交。
**SLO** 分组（**Optional target.**）默认展开，TTFT 与 TPOT 在同一行并排显示。
**Workload estimate（工作负载估计）**位于 **Preference（偏好）**正下方，默认展开；
**vLLM parameters（vLLM 参数）**位于工作负载下方，默认收起。

## Guide 入口选择

自动选择通用入口时，优先使用根目录（`.`），其次使用 `base`。如果两者都不存在，
部署会明确报告 Guide、硬件 profile 和可用变体，而不是自动选择某个平台的专用配置。
此时应选择兼容的 Guide 源码，或在支持显式选择的流程中指定已列出的变体。

Agentic 的分层前缀缓存表达 native CPU 缓存需求，不固定源码目录布局。
Lens 会根据所选源码解析 `native/cpu` 或 `native/cpu/base`，并兼容旧路径。
缺少对应入口时会报错，不会替换为其他缓存实现、存储层或平台专用配置。

## RuntimeClass 策略

RuntimeClass 发现与策略覆盖仅通过后端 API 提供，Manual 和 Agentic 表单不提供
RuntimeClass 输入项。发现接口、策略模式和请求示例请参阅
[部署 API 参考](../api-reference/modules/deployments.mdx)。

## 在列表中查找部署

1. 查看页面顶部的汇总卡片：**总计**、**就绪**、**进行中**、**失败**和**已清理**。
2. 在列表工具栏中，在**搜索部署**中输入内容，可按名称、描述、模型、命名空间、指南或 ID 匹配部署。
3. 打开**状态**以按部署状态进行筛选。
4. 打开集群选择器，选择**所有集群**或某一个集群。
5. 如有需要，更改**每页行数**，并使用分页器在列表中翻页。
6. 如果没有匹配的行，点击**清除筛选**。

## 查看部署详情

1. 在部署行中，点击提示为**查看详情**的操作。
2. 在抽屉中，查看**基本信息**、**模型与服务引擎**、**集群与环境**、**网络与端点**以及**审计与时间线**各个部分。
3. 当你需要在别处复用诸如**命名空间**、**集群会话 ID**、**容器镜像**、**内部端点**、**转发端点**或**执行 ID**等值时，使用这些值旁边的复制按钮。
4. 如果部署失败，请先阅读失败提示横幅，再做任何改动。

等待状态变为 **Ready（就绪）**后再调用。处于 **In progress（进行中）**时，
打开 Pod 日志查看启动进度；处于 **Failed（失败）**时，结合失败提示和对应 Pod 的日志排查。

**Failed（失败）**并非终态。发布超过进度期限会被记为失败，但工作负载往往会自行恢复——
例如某个 Pod 一直崩溃，直到其模型缓存补齐后才正常启动。Lens 会持续拿失败的部署与集群实况
比对，一旦其 Pod 重新提供服务就把状态改回 **Ready（就绪）**，因此不必急于重建部署。
如果命名空间已不存在，则该部署会被更正为 **Cleaned（已清理）**。

当 Pending Pod 正在等待加速器资源时，包括 DRA 调度器报告的
`cannot allocate all claims`，即使超过发布进度期限，部署也会保持**进行中**。
刷新先前被标为**失败**的部署时，如果当前诊断确认仍在等待资源，状态会恢复为**进行中**，
调度原因仍可在诊断中查看。这不会释放其他部署占用的设备；需要停止或删除不再使用的部署来
释放资源。容器崩溃和镜像拉取失败仍被视为失败；仅有 Pending 状态不足以判定为资源等待。

调度成功后，Running Pod 可能仍在加载模型，尚未 Ready。如果发布报告超出进度期限，
只要当前容器仍在 `startupProbe` 的启动预算内（没有启动探针时使用 `readinessProbe` 的预算），
Lens 就会保持**进行中**，不会自动清理。预算从各容器实际启动时刻计算，Pending 等待时间
不会占用该预算。当前崩溃、镜像拉取失败、容器重启或探针预算耗尽不适用此宽限。
仅有 Running 状态不代表就绪，仍需通过 provider 的就绪检查。

## 查看 Pod 并查看实时日志

对于新渲染的部署，所有 provider 都会将显式设置的最大模型长度、最大序列数、显存利用率、
块大小和最大批处理 token 数传给 vLLM。P/D 分别应用 Prefill 和 Decode 的配置。
角色配置覆盖 Guide 默认值；角色未指定最大长度时使用模型级最大长度。
定向自定义参数优先，未设置的字段保留上游默认值。这不会重写现有 Pod 或精确发布的清单；
需要创建新部署才能应用变更。排查 KV cache 容量错误时，应核对模型容器启动命令及日志。

Lens 会检查所有部署 provider 渲染的模型服务 Pod 的 `/dev/shm`。普通渲染中，
如果缺少挂载且未启用主机 IPC，会补充每个 Pod 独立的内存型 `emptyDir`，上限为
**4 GiB**；`baseline-vllm` 的默认值也为 4 GiB。这避免了容器运行时默认的
64 MiB 共享内存限制，不会启用主机 IPC，也不会修改上游 Guide 仓库。

已有挂载及其容量设置保持不变，包括未显式设置上限的内存卷和其他卷来源。
未设置上限、其他卷来源、只读或子路径挂载，以及已启用主机 IPC 的情况，会在服务日志和
部署诊断（`snapshot.shared_memory`）中记录警告。内存卷省略 `sizeLimit` 并不表示
上限为 64 MiB，也不表示内存无限可用。重复的 `/dev/shm` 挂载和无效卷绑定会被拒绝。

原样发布清单（`officialGuide`）只检查，不自动补充共享内存挂载；缺少挂载时记录警告。
检查报告也保存在部署产物的
`rendered_payload.value.deployment_contract.sharedMemory` 中。
卷按实际使用量消耗内存，而非提前占用整个上限；规划 Pod 内存时应将共享内存计入。
已有部署仍保留原始清单，需重新创建才能获得新默认值或缺失挂载的补充。

1. 要在行内查看 Pod 状态，点击提示为**显示 Pod** 的行展开开关。
2. 在展开的行中，查看 Pod 表格的列：**Pod**、**状态**、**重启次数**、**节点**和 **Pod IP**。
3. 要使用完整的日志查看器，点击提示为**查看 Pod 与日志**的操作。
4. 使用节点筛选或搜索框找到需要查看的 Pod。
5. 点击某个 Pod 卡片，打开该 Pod 的**Pod 日志：**。
6. 如果某个 Pod 包含多个容器，请选择所需的**容器：...**条目。
7. 选择**100 行**、**200 行**、**500 行**或**1000 行**以更改日志尾部的长度。
8. 如果需要查看上一个容器的日志，请打开**上一个**开关。
9. 保持**自动刷新 (5 秒)**开启，以让 Pod 列表和日志保持实时更新。
10. 使用**筛选日志行...**来缩小日志输出范围，或点击**复制**来复制当前的日志文本。

## 为就绪的部署创建本地端口转发

1. 找到一个已经处于**就绪**状态的部署。
2. 在该行中，点击提示为**创建本地端口转发**的操作。
3. 等待成功提示**本地端点已连接**出现。
4. 如果你想从工作站调用该服务，可从表格中复制更新后的本地端点。

## 打开部署监控与性能分析

1. 在部署行中，点击提示为**部署监控**的操作。
2. 如果监控尚未安装，点击**安装**。
3. 如果监控已存在但处于暂停状态，点击**启用**。

   在部署本身就绪之前，**安装**和**启用**均不可用——监控采集的是该部署的 Pod，
   在此之前没有任何数据可采集。等待期间菜单中会给出相应提示。
4. 当监控已启用时，使用**打开 Grafana** 或**打开 Prometheus** 在新标签页中打开相应的仪表盘。
5. 点击**性能分析**，跳转到该部署的性能分析视图。
6. 使用**禁用**可以在不卸载的情况下停止监控。
7. 使用**卸载**可以从该服务中移除部署监控。

## 编辑部署名称与描述

1. 在部署行中，点击提示为**编辑名称与描述**的操作。
2. 在**编辑部署**中，更新**显示名称**和**描述**。
3. 点击**保存更改**。
4. 如果你决定不保留这次编辑，点击**取消**。
要修改模型、镜像、资源数量或集群，请[创建新部署](/user-guide/model-market)；
此处只修改名称和描述。

## 模型推理访问

不再支持部署分享。admin 和 maintainer 在其集群 scope 内管理部署。
消费者不能访问部署页面或直接连接部署；请发布模型服务，再通过其
[Manage access 抽屉](/user-guide/model-services#管理模型访问权限)向用户或组授予推理权限。
旧部署授权不会自动转换成模型授权。

## 删除部署

1. 在部署行中，点击提示为**删除部署**的操作。
2. 在**删除部署**中，查看**执行 ID**、**集群**和**命名空间**。
3. 如果你希望 Lens 移除该命名空间及其中的所有内容，请保持**同时删除 Kubernetes 命名空间**选中；如果只想移除部署记录，请取消勾选。
4. 在**输入 `<短语>` 以确认**中，输入对话框中显示的确切确认短语。
5. 点击**删除部署**。
6. 如果你不想继续，点击**取消**。

## 找不到部署或操作按钮

先清除搜索、状态和集群筛选。仍然找不到时，请管理员检查角色的部署管理权限和集群 scope。

需要让应用调用已就绪的部署时，继续[发布模型服务](/tutorials/publish-a-model-service)。
