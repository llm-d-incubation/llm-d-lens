## 三种使用方式

<CardGroup cols={3}>
  <Card title="Web 控制台" icon="server" href="/quickstart">
    由统一 Python 后端（<code>llm_d_lens</code>）提供的浏览器控制台，覆盖多集群治理、可视化规划、Model Catalog、引导式评估、Trace Replayer、Model Services、可观测性与内置 Lens Assistant。
  </Card>
  <Card title="独立 llmd CLI" icon="rocket" href="/cli-reference">
    纯 Python 3.11+ 与 PyYAML 客户端（<code>apps/lens</code>），无需集群管理员权限、Lens 服务器、数据库或 Node，即可按命名空间直连 Kubernetes/OpenShift 执行 GitOps（<code>llmd</code> 为完整 CLI，<code>lens</code> 当前仅提供版本与帮助存根）。
  </Card>
  <Card title="Agent Tools（Lens MCP）" icon="bolt-lightning" href="/mcp">
    无状态 Streamable HTTP 端点（<code>POST /api/mcp</code>，<code>Bearer lens-pat-*</code>），面向 <code>opencode</code>、Claude Code、Cursor 与 Codex 提供 6 个 profile 共 46 个任务工具，与内部 <code>/api/assistant/mcp</code> 明确区分。
  </Card>
</CardGroup>

## 亮点功能

<CardGroup cols={2}>
  <Card title="最优性能" icon="bolt-lightning">
    部署运行在 llm-d 之上：预填充/解码分离、感知 KV 缓存的路由、
    KV 缓存向 CPU/SSD 分层卸载，以及基于延迟预测的路由，
    在同样的 GPU 上提升吞吐并降低尾延迟。
  </Card>
  <Card title="多集群部署" icon="server">
    通过单一界面、CLI 或 MCP 智能体工作流规划、审批并执行跨 Kubernetes 集群的推理部署，
    并支持按负载引导的智能体放置策略。
  </Card>
  <Card title="引导式评估" icon="chart-line">
    设计基准测试实验，针对线上部署运行测试，
    并分析和导出结果，无需手写脚本。
  </Card>
  <Card title="Trace Replayer（轨迹回放）" icon="flask">
    对推理端点重放已注册的请求轨迹，
    在真实流量到来前验证行为与容量。
  </Card>
  <Card title="模型服务网关" icon="route">
    将集群部署发布为兼容 OpenAI 与 Anthropic 的模型服务，
    运行在集群本地共享网关之后（HTTPRoute / IPP → EPP → InferencePool），
    配合 <code>lens-authz</code> 鉴权与按模型配置的选择策略。
  </Card>
  <Card title="内置治理能力" icon="shield-check">
    基于角色的访问控制、按集群的权限范围和审计日志，
    统一覆盖每一个 UI 页面、REST 路由与 <code>/api/mcp</code> 工具调用。
  </Card>
  <Card title="可观测性" icon="gauge-high">
    一键搭建并维护集群监控栈（Prometheus/Grafana），
    用于查看 GPU 利用率和部署健康状况。
  </Card>
</CardGroup>

## 架构

<img src={useBaseUrl('/img/home-3-7d83bcc33b.png')} alt="Lens system architecture" width="100%" />

单一的统一 Python FastAPI 后端（<code>apps/backend</code>，<code>llm_d_lens</code>）作为控制平面，
可以集中管理任意数量的本地或云端 Kubernetes 集群：它同时提供构建后的 Web UI（<code>apps/frontend</code>）、
REST API、RBAC 与审计校验、外部 Agent Task MCP 端点（<code>/api/mcp</code>）以及内部助手工具目录（<code>/api/assistant/mcp</code>），
并将状态持久化到 PostgreSQL，直接驱动集群、存储和集群本地共享网关。
对于无需服务器的命名空间级工作流，独立 <code>llmd</code> CLI（<code>apps/lens</code>）直接与 Kubernetes 交互；
模型客户端则使用 <code>Bearer lens-mk-*</code> 直接请求已发布的共享网关。
